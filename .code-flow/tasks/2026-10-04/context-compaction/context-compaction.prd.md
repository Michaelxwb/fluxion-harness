## 2. 背景与目标

### 2.1 问题陈述 [必填]

Agent 的长会话会上下文膨胀，而当前只有**一层最粗暴的处理**：`context_builder._trim` 保留尾部 `HISTORY_BUDGET_MESSAGES = 40` 条、从最近一条 USER 消息起切。由此有三个已经可指认的问题：

1. **开头被整体丢掉**：用户最初的诉求与最早的关键约束，在预算超限后第一批消失 ⇒ 模型"忘了自己在干什么"。（成对性已防住：`_drop_leading_tool` + 从 USER 边界切，不会产生孤儿 TOOL 消息。）
2. **旧工具结果长期占位**：工具结果外置阈值是 8 KiB（`TOOL_RESULT_ARTIFACT_BYTES`），超过就落共享产物 + 留预览；但**一轮里每条都不大、合计很大**时没有任何机制 ⇒ 会话被工具结果堆满。
3. **超预算只能硬丢、不能压缩**：没有任何摘要/降级机制 ⇒ 信息净损失，且丢掉了什么不留痕、不可解释。

### 2.2 目标与价值 [必填]

| 维度 | 内容 |
|---|---|
| **目标** | 把"硬丢"换成**分级压缩**：先便宜后昂贵（落盘 → snip → micro → 摘要），且压缩结果**可由库确定性重建、可审计** |
| **价值** | 长会话不再丢失原始诉求；上下文预算用得更有信息量；模型"为什么没记得"可解释 |

## 3. 用户与场景

### 3.1 目标用户 [必填]

- **IM 终端用户**：长会话/多工具回合（技能、附件、后台任务）中感知不到上下文被压缩，但回答质量不塌。
- **平台运维/审计人员**：能从审计面解释"这一轮模型看到的历史被压缩了什么"。
- **平台管理员**：能按需调整压缩策略（阈值/开关/摘要模型），且**不必重启服务**。

### 3.2 用户故事 [必填]

| 编号 | 用户故事 | 优先级 |
|---|---|---|
| US-01 | 作为 IM 用户，我希望长会话里系统仍记得我最初的要求，以便不用反复重申 | P0 |
| US-02 | 作为审计人员，我希望看到某轮压缩掉了什么、用了哪份摘要，以便解释模型行为 | P0 |
| US-03 | 作为管理员，我希望按租户调压缩阈值/开关/摘要模型，且改动对后续新 Run 生效而无需重启 | P1 |

## 4. 功能需求

### 4.1 功能清单 [必填]

| 功能ID | 功能名称 | 功能描述 | 优先级 | 来源 |
|---|---|---|---|---|
| FEAT-01 | 保留头部 + 省略标记（snip） | 历史裁剪从"只留尾部"改为"保留最前 N 组 + 最近 M 组，中间换省略标记"；标记按**消息组**报数（不报消息条数） | P0 | US-01 |
| FEAT-02 | 批次预算（落盘） | 落盘判定从"单条超阈值"扩为"**整轮**工具结果合计超预算 ⇒ 按字节从大到小落盘，够用就停"；预览同时保留头尾 | P0 | US-01 |
| FEAT-03 | 旧工具结果降级（micro） | 只保留最近 K 个工具交换组的原文，更早的**结果内容**换成占位符；`tool_calls` 与参数**原样保留**；占位符带 `artifact_id` 与工具名（模型可据此 `read_attachment` 回到原文） | P0 | US-01 |
| FEAT-04 | 摘要（第四层） | 前三层跑完后历史仍超阈值才调用模型摘要：五字段摘要 + **字段集合精确相等**校验；失败**保持原历史不变**、下一轮重试；摘要**落库**（权威历史），被压缩掉的逐字原文（transcript）落**共享产物 store** | P0 | US-01 |
| FEAT-05 | 压缩审计事件 | 每次压缩落一行 `canonical_event`（层级、省下的字节/组数、摘要引用），使"本轮历史被压缩了什么"可解释 | P0 | US-02 |
| FEAT-06 | 压缩指标 | 四级各自触发次数、省下字节、摘要调用与 token 数，进各自服务的 metric catalog | P1 | US-02 |
| FEAT-07 | 压缩配置 | 阈值/开关/摘要模型/预算进 execution snapshot 的 `policy_json`（既有冻结机制）；默认值随代码发布；改动**仅影响后续新 Run** | P1 | US-03 |
| FEAT-08 | 重建一致（回放） | 压缩后的历史必须能由库**确定性重建**，且与当时真正发给模型的那份**逐字节一致**（换 Pod / 重放 / resume 都成立） | P0 | US-04 |
| FEAT-09 | memory 预算 | memory 注入占用上下文预算的一部分，且压缩不会把注入内容压成不可解释状态 | P1 | US-01 |

### 4.2 边缘情况 [可选]

- 摘要输出多字段/少字段/非 JSON/带 tool_calls/finish_reason≠stop ⇒ 一律拒绝本次摘要，**不替换**历史。
- 落盘写失败（磁盘满、目录越界、同名冲突）⇒ 本批已写产物**回滚删除**，原历史不变。
- micro 占位符比原文还长（短结果）⇒ 必须跳过该条（否则历史反而变长）。
- 恰好等于阈值 ⇒ **不**触发（严格大于）。
- 中文内容按 **UTF-8 字节**判定（一个汉字 3 字节，不能用字符数）。

### 4.3 已对齐的决策记录（本会话结论）

| 议题 | 结论 |
|---|---|
| transcript 落哪 | 落**共享产物 store**（k8s 即 RWX PVC），但**不给 Console 任何读取/下载入口**（保持"Console 不暴露对话原文"的既有姿态） |
| 摘要落哪 | **落库**（权威历史）。理由：产物有 30 天保留期且 `cleanup-artifacts` **删文件+删行**，摘要若只当文件，过期后"被压缩掉的历史"彻底消失 |
| retention | **不豁免**（摘要进库已解决根本问题；transcript 随 30 天过期可接受） |
| 摘要成本/失败 | 摘要**默认关**、失败**保持原历史**、模型**可配**（引用已配置的 `model_definition`，页面上不填 key） |
| 配置分层 | 运行期可改、跟业务有关的 ⇒ 将来进 Console **系统设置页**；不能改的（DSN/端口/身份/租约时长/路径） ⇒ `.env` / k8s Secret+ConfigMap，**改后重启生效** |
| 设置失效 | **短 TTL 自动失效**（无广播），语义 = ≤TTL 后对**下一个新 Run** 生效；在跑的 Run 用快照冻结值 |
| 降级可回溯 | micro 占位符**带 `artifact_id` + 工具名**；snip 省略标记**列出被省掉的工具名/产物名** |
| 压缩可见性 | 落 **1 行审计事件**（见 FEAT-05） |
| 需求拆分 | **本需求只做压缩四层**；Console 系统设置页单列需求二（接口先按 FEAT-07 的 `policy_json` 口径写，避免返工） |

### 4.4 字节口径（实现前必须钉住）

| 机制 | 现状 | 本需求 |
|---|---|---|
| 工具结果落盘阈值 | `TOOL_RESULT_ARTIFACT_BYTES = 8 KiB`（单项） | 保留单项，**新增整轮批次预算** |
| 交付类工具内联上限 | `MAX_INLINE_RESULT_BYTES = 256 KiB` | 不动 |
| 历史预算 | `HISTORY_BUDGET_MESSAGES = 40`（常量） | 改为配置项（FEAT-07），口径仍是"消息组" |

## 5. 非功能需求 [可选]

- **成对性硬约束**：压缩后不得出现孤儿 `tool` 消息；带 `tool_calls` 的 assistant 回合必须与工具结果同进同出（既有约束，见 `_kept_tool_rounds`）。
- **不引入每轮查库**：压缩配置走进程内缓存 + 短 TTL（既有"不每秒查库"的口径）。
- **摘要失败不得让 Run 失败**：压缩是尽力而为，失败退化到"不压缩"。
- **可观测**：FEAT-06 的指标必须进 catalog（无流量也可见）。
- **不改模型可见语义之外的东西**：压缩只作用于"派生 request"，不改 `canonical_event` 里的原始事实。

## 7. 依赖与风险 [可选]

### 7.1 项目依赖

- `execution snapshot` 的 `policy_json`（配置冻结载体，`RULE-snapshot-001`）。
- 共享产物 store（RWX PVC）与 `runtime.artifact`（`TOOL_RESULT` 已有类型，transcript 需新增类型）。
- `canonical_event`（审计事件载体）与历史重建链（`context_builder`）。

### 7.2 风险识别

| 风险 | 影响 | 应对 |
|---|---|---|
| 压缩改变模型可见历史 ⇒ 行为回归 | 中 | 四层各自独立开关；默认只开"保头 + 批次预算"两条最便宜的；E2E 覆盖 |
| 摘要调用成本与延迟 | 中 | 默认关；阈值可配；失败不替换 |
| micro 让历史变长 | 低 | 断言"占位符必须短于原文"，否则跳过 |
| 摘要/transcript 造成新的对话原文出口 | **高（隐私）** | transcript 落共享 store 但 Console **无读取入口**；摘要只落五字段结构化内容 |
| 重建不一致（换 Pod 看到的压缩结果不同） | 高 | FEAT-08 用逐字节一致性测试钉住；前三层确定性重算、摘要落库 |
