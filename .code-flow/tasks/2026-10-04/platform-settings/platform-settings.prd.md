## 2. 背景与目标

### 2.1 问题陈述 [必填]

| 维度 | 内容 |
|------|------|
| **问题描述** | 平台级业务默认值（上下文压缩阈值、任务重试与并发、产物保留期、默认语言/时区、IM 展示节拍…）散落在各服务源码常量与 `.env` 里：改一个业务默认要么改代码重新发版，要么改 `.env` 重启服务；上下文压缩的「平台设置源」读取缝虽已在 Runtime 留出，但当前恒返回空字典，没有任何页面或表可以写。同时盘点发现 **10 组重复/冲突声明**（历史预算 40 出现在两处、工具结果 8 KiB 与 schema 默认同名两套、会话时长 12h 两处、默认租户两处、产物路径两套默认…），同一个业务语义有两个来源，改一处另一处会漂移。 |
| **当前替代方案** | 业务默认只能由开发改代码或由运维改 `.env` 后重启；上下文压缩配置只能逐 Agent 写 `runtime_config_json`，没有平台级默认；`context_settings_cache_ttl_sec`（10s TTL）意味着即便有源也不是「保存即生效」。**都不够用**：前者不满足「运行期可改」，后者不满足「一次改全局」与「可审计」。 |
| **触发原因** | `context-compaction` 需求（已归档）在设计阶段明确把 Console 系统设置页划为**需求二**，并要求「接口先按 FEAT-07 的 `policy_json` 口径写，避免返工」；2026-10-04 完成全仓配置盘点，逐项给出了归属与生效方式。需求二与盘点合并为本需求。 |

### 2.2 目标与价值 [必填]

| 维度 | 内容 |
|------|------|
| **核心目标** | 建立**一份按租户持久化、带版本、可审计的平台业务设置**，作为「平台默认」的唯一权威源；保存成功后开始的新 Run / 新 Task / 新业务操作立即使用新值，执行中的对象保留其已冻结的快照；Console 提供系统设置页；同时明确并收敛环境类与代码类配置的归属，消除重复默认源。 |
| **预期价值** | 运维不用为调业务默认而发版或重启；管理员在页面上一次改平台默认、资源级覆盖继续优先；同类语义只剩一处声明，不再漂移；配置改动可追溯到人、可回滚到上一版本。 |

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 修改一个平台业务默认所需的动作 | 改代码发版 / 改 `.env` 重启 / 逐 Agent 改配置 | 页面保存后，后续新操作立即使用新值 | E2E：保存后下一次 Run/Task/业务操作读到新 revision |
| 重复/冲突的业务默认声明（盘点 §必须收敛） | 10 组 | 每组只剩一个权威源 | 收敛清单逐项核对 + `tests/test_configuration_inventory.py` 分类机检 |
| Console 系统设置入口 | 无（`RULE-ui-001` 固定十项菜单） | 1 个入口 + 页面 | 前端 shell 测试 + E2E |
| 未授权读写的成功次数 | — | 0 | 契约/E2E：非管理员、跨租户读写被拒且留审计 |
| 执行中被换策略的 Run/Task | — | 0 | E2E：保存设置后，执行中的 Run/Task 仍用冻结策略 |

#### FEAT-01: 平台业务设置持久化与版本

- **描述**: 新增一张按租户的平台业务设置表，保存带版本号的设置文档；字段级 schema 与联动校验在服务端。
- **验收标准**:
  - [ ] 同一租户任一时刻只有一个「当前版本」；保存产生新版本且版本号单调递增
  - [ ] 非法类型 / 越界值 / 破坏联动关系的组合（如压缩的保留头尾组数与触发阈值关系、摘要启用但无有效模型引用）被拒绝，且**现状版本不变**
  - [ ] 跨租户不可见、不可改
  - [ ] 表结构符合数据规范（统一主键/时间字段、`jsonb` 配置、关键查询字段不藏在 JSON 里）

#### FEAT-02: 四服务按操作边界读取设置

- **描述**: 定义唯一的「取设置快照」入口与调用时机，四个服务一致。
- **验收标准**:
  - [ ] 新 Run / 新 Task / 新业务操作在**开始边界**取一次最新版本；不在每轮模型调用或每次轮询里重复取
  - [ ] 保存成功后开始的业务操作必定读到新版本（无 TTL、无重启、无跨 Pod 广播依赖）
  - [ ] 执行中的 Run/Task 继续使用其冻结快照，中途保存不影响它
  - [ ] 设置源不可读时业务操作明确失败（统一错误码 + 指标），不静默回退到过期默认值
  - [ ] 资源级显式配置仍然优先于平台默认

#### FEAT-03: 系统设置 API

- **描述**: Console 提供平台设置的读写接口，含权限、校验、乐观并发与审计。
- **验收标准**:
  - [ ] 读取返回分组后的设置项、每项的平台默认值、被哪些资源显式覆盖、以及本租户当前实际值
  - [ ] 保存携带版本号做乐观并发；版本冲突返回明确错误码，不静默覆盖他人改动
  - [ ] 仅授权管理员可读写；未授权与跨租户访问被拒并留下审计记录
  - [ ] 保存成功写审计（操作者、时间、变更前后的项），审计与日志内**不含密钥/凭据/DSN**
  - [ ] 请求/响应遵循统一封套与错误码规范

#### FEAT-04: Console 系统设置页

- **描述**: 新增系统设置页，按分组管理平台默认。
- **验收标准**:
  - [ ] 页面按分组呈现：上下文压缩、Agent 执行默认、任务与投递、记忆与附件、产物生命周期、认证安全、语言/时区与 IM 展示
  - [ ] 每项显示「平台默认 / 资源覆盖情况 / 本项生效方式（新操作立即生效 / 需重启服务 / 不开放）」
  - [ ] 保存前做前端预检（范围提示），但**服务端校验为准**；保存失败展示可定位的具体错误
  - [ ] 页面可查看并恢复到上一个版本
  - [ ] 仅 ADMIN 可进入并读写；非 ADMIN 无菜单入口、直接访问 URL 被守卫拒绝、API 亦拒绝（不做"只读角色可看"）

#### FEAT-05: 已有业务默认的迁移与重复源收敛

- **描述**: 把已存在的业务默认接入统一设置源，并消除重复声明。
- **验收标准**:
  - [ ] 上下文压缩 15 个叶子字段可由平台设置提供默认，且 Agent 级 `runtime_config` 覆盖仍优先
  - [ ] 至少收敛盘点 §必须收敛 中的重复源：历史预算、工具结果默认、会话时长、默认租户、产物路径、策略默认快照
  - [ ] 平台设置选择模型时**引用既有模型定义**，不新增默认模型回退
  - [ ] 业务设置读取不再依赖进程内 TTL 缓存表达「生效延迟」

#### FEAT-06: 环境配置收口

- **描述**: 环境类配置统一启动加载，补全运维契约。
- **验收标准**:
  - [ ] 去掉**重复默认源**：产物路径两套默认、默认租户两处、工具结果三常量、会话时长两处、历史预算两处各留一处
  - [ ] 去掉裸 `getenv` 的第二套默认；环境类配置经统一启动 settings 读取（请求内临时构造的全仓收口列为技术债，见设计 §2.4）
  - [ ] `.env.example` 覆盖全部环境类字段键名（补齐当前缺失项）；改为业务设置的键从示例与启动 settings 中移除并写入发布说明
  - [ ] 部署侧（Secret/ConfigMap/副本/容量）与业务设置的边界写入事实文档

#### FEAT-07: 配置盘点基线与机检同步

- **描述**: 盘点结论作为本需求交付物并保持可验证。
- **验收标准**:
  - [ ] 分类报告覆盖四类归属与「保存后立即生效」的落地契约
  - [ ] 逐项清单与真实源码声明一致，分类变更必须同步更新清单与期望
  - [ ] 机检在**不需要任何服务**的前提下可运行

#### FEAT-08: 菜单/规范/事实文档同步

- **描述**: 新增入口带来的规范与文档同步。
- **验收标准**:
  - [ ] Console 菜单规则更新为包含系统设置入口（`RULE-ui-001` 如实改写，不留旧文案）
  - [ ] 断言「不存在系统设置入口」的既有测试按新事实改写
  - [ ] 相关事实性文档（导航地图 / 规范 Conventions）同步

### 4.2 边缘情况 [可选]

| 场景 | 预期行为 |
|------|----------|
| 两个管理员并发保存 | 后提交者因版本冲突失败并提示重新加载；不静默覆盖 |
| 保存的压缩配置满足不了联动约束（如保留头尾组数 ≥ 触发阈值） | 拒绝保存，返回可定位到具体字段的错误；**不产生新版本** |
| 设置表尚无该租户记录 | 读取返回 schema 默认值（视为平台默认），不报错；首次保存创建记录 |
| 某资源显式覆盖了某项，管理员改平台默认 | 该项对**该资源**仍是覆盖值；页面必须显示「已被 N 个资源覆盖」 |
| 执行中的 Run 遇到配置保存 | 继续用冻结快照；新 Run 用新版本 |
| 设置源在业务操作边界不可读 | 明确失败（统一错误码 + 指标），不回退到过期默认值 |
| 管理员尝试把密钥/DSN 类值写进业务设置 | schema 不接受这类键；页面不提供入口 |
| 旧版本回滚 | 回滚产生**新版本**（内容等于旧版本），历史仍可追溯 |

## 5. 非功能需求 [可选]

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-SEC-01 | 安全 | 仅授权管理员（admin 角色）可读写；严格按租户隔离；未授权访问返回统一错误码并写审计 |
| NFR-SEC-02 | 安全 | 业务设置文档与接口**不得**承载密钥、凭据、DSN、内部 token；接口/日志/审计不回显敏感值 |
| NFR-REL-01 | 可用性 | 设置源不可读时业务操作明确失败，不得静默使用过期默认值；失败可观测（指标 + 日志） |
| NFR-REL-02 | 一致性 | 保存返回成功后开始的新业务操作必定读到新版本；执行中对象保持一致快照 |
| NFR-PERF-01 | 性能 | 取设置快照的次数与业务操作边界一一对应（新 Run/Task 一次），不进入每轮模型调用/每次轮询的热路径 |
| NFR-COMPAT-01 | 兼容性 | 不改变既有公开 API 契约与既有资源页面语义；不新增兼容别名、双写或过渡适配层 |

> 无量化性能指标时给定性要求；上表不含编造的数字目标。

## 6. 范围与边界 [必填]

| 类别 | 内容 |
|------|------|
| **范围（In Scope）** | ① 平台业务设置的持久化、版本、校验、权限与审计；② 四服务按操作边界读取设置与冻结语义；③ 系统设置 API 与 Console 系统设置页；④ 已有业务默认（压缩 / 执行预算 / 任务与投递 / 记忆与附件 / 产物生命周期 / 认证安全 / 语言时区与 IM 展示）接入统一源；⑤ 盘点清单中的重复源收敛；⑥ 环境配置收口与 `.env.example` 契约补全；⑦ 配置盘点基线与机检；⑧ 菜单、规范与事实文档同步 |
| **非范围（Out of Scope）** | ① DSN / 端口 / 身份 / 租约时长 / 路径等部署类配置进入页面；② 把 Agent / 模型 / MCP / 项目平台已有资源配置复制进系统设置（它们继续由各自页面管理，系统设置只提供平台默认）；③ 把 995 个盘点声明点都做成可配置项（协议、状态枚举、第三方硬上限、UI 原语、算法规则保留在代码）；④ 执行中 Run/Task 的**动态**策略变更（本次不改冻结语义；若将来要做需逐字段定义）；⑤ 前端构建期 `VITE_*` 变量运行时化；⑥ 部署侧容量参数（HPA/PDB/镜像钉版本/资源配额/多物理节点）——属生产可用缺口清单，不在本需求；⑦ 上下文膨胀可视化看板与非 OpenAI 兼容模型的精确 token 计数（沿用 `context-compaction` 的非范围） |
| **前置假设** | ① 四个服务与 Console 共用同一 PostgreSQL（现状）；② Console 已有 admin 角色门控与租户上下文依赖（`AccountTenantId` 一类）；③ 审计基础设施与统一错误码/封套规范可用；④ `context-compaction` 已交付 `budget.compaction` 的 schema 与冻结链路，本需求沿用其口径 |
| **有意妥协 / 技术债** | ① 设置文档采用整文档保存（非逐字段 PATCH）：实现简单、版本语义清晰，代价是并发编辑同一分组会冲突——按乐观并发明确失败，不做字段级合并；② 已有资源页面（Agent/模型/MCP/项目平台）本需求不改造成「统一设置中心」，只在系统设置页展示其覆盖情况，避免一次改动面过大；③ 盘点清单是快照，靠机检同步而非实时生成 |

### 7.1 项目依赖

| 依赖方 | 依赖内容 | 最晚交付时间 | 风险等级 |

### 7.2 风险识别

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|---------|
| R-01 | 新方案仍靠缓存/TTL 表达生效，退回「等一会儿才生效」 | 违背核心目标 | 以「保存后新操作读到新版本」为验收场景；明确禁止用 TTL 表达生效延迟 |
| R-02 | 迁移期新老来源并存（双写、兼容别名、旧常量兜底） | 两套默认继续漂移，比不改更糟 | 一次性切换：旧声明删除，不留别名；盘点收敛清单逐项核对 |
| R-03 | 前端把范围上限当权威 | 绕过服务端约束 | 服务端校验为准，前端只做预检；边界场景断言非法值被拒 |
| R-04 | 取设置成为 Run 关键路径的新失败点 | 可用性回归 | 明确失败 + 指标 + 告警；边界只取一次，不进入热路径；执行中对象不依赖设置源 |
| R-05 | 菜单规则与 shell 测试写死「十项菜单」 | 新增页面即破坏既有断言 | 规范随代码事实改写（本需求 FEAT-08），不留兼容分支 |
| R-06 | 盘点清单随代码变更过期 | 分类结论失效、误导运维 | 机检（FEAT-07）绑定真实源码声明与分类期望 |
| R-07 | 敏感值被误写进业务设置并对外返回 | 越权/泄漏 | schema 不接收敏感键；审计与日志脱敏；安全场景断言接口不回显 |
