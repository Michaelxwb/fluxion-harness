# TASK-003 并发租约与故障守卫设计草案

状态：设计草案；不代表实现或验收通过。依赖 TASK-009 的共享计数与许可修复；实现前仍需完成该任务的验收及冻结预算接线。

## 目标与边界

复用 Runtime/Worker 和现有 Redis Cluster，不增加服务。受控请求在发送前确认共享许可；Redis 故障或结果不确定时不外发。无规则请求不依赖 Redis。并发数表示本组件尚未结束的本地传输，不能代表上游后台任务是否结束。

## 租约生命周期

1. 宿主根据可信执行身份、当前策略、执行租约及强制请求 deadline 创建 attempt；公共规则和冻结预算必须在同 slot 脚本中一次判定。准入成功后形成与 attempt、规则、epoch 和执行段绑定的许可，发送前只能消费一次。
2. 并发租约由宿主生成的唯一 token 标识；准入原子登记，任何释放或续租都必须校验 token、许可与当前执行段，不能释放其他请求。已计入的累计次数不因取消或发送失败回退。
3. 先采用有界请求：宿主必须强制结束整个请求，包括流式读取。租约过期时间覆盖该 deadline 和进程终止、连接关闭的安全余量；许可的发送有效期应短于执行租约剩余安全期。无法建立或监督此 deadline 时，不允许启用并发上限。
4. EOF、显式关闭、错误或取消后，由持有传输的进程关闭连接并幂等释放自己的 token。释放失败时不提前假定槽位空闲；保留到安全过期。Skill 进程持有业务连接，宿主通过 IPC 监督与终止进程组；宿主直接发送的请求由宿主关闭。
5. 流式请求在 deadline 前一直占用，不在响应头返回时释放。续租必须校验 token、执行段及宿主监督状态；续租失败或状态不确定时，关闭本地传输并阻止后续发送。续租不能延长宿主强制 deadline；本草案不假定当前代码已实现续租。

该方案依赖宿主能在过期前终止持有连接的本地进程。进程卡死、宿主暂停、调度延迟或网络分区可能破坏这一前提；未证明强制终止和余量覆盖时，不得宣称并发上限严格成立。

## 计量不可用与恢复

- 连接失败、超时、ACL 错误、状态缺失、类型异常、epoch 不一致或时钟回拨均返回计量依赖故障，受控请求不发送；不得退回进程内计数。窗口/并发拒绝与累计耗尽分别返回可区分错误。
- 只有 Redis 协议结果不确定时，才用相同 attempt 查询或重试同一次准入；即使查到旧许可，也只能由原发送操作消费一次。业务重试使用新 attempt，不自动重试确定性预算拒绝。
- 请求明细和计量准入分离：明细写入故障按既有有界缓冲及缺口告警处理，不阻断业务；明细保留时间不决定累计键生命周期。
- Redis 计量键必须具备缺失检测，仍可恢复的执行不能以零初始化。epoch 必须来自 Redis 之外的权威控制流程；仅依赖 Redis 内部标记无法识别同步回滚或所有历史丢失。
- Cluster 主节点变化应由外部权威流程触发保护域关闭与代际切换；旧执行在状态不确定时阻断，窗口及本地请求的安全等待期过后才能按恢复流程开放新执行。检测有间隙或异步复制丢写时无法承诺严格历史累计，实际部署需验证检测和故障演练；无法验证则不得验收 B-05。
