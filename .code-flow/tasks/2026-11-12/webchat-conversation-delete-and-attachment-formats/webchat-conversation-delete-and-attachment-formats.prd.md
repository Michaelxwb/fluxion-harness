## 2. 背景与目标

### 2.1 问题陈述

| 维度 | 内容 |
|------|------|
| **问题描述** | （1）WebChat 没有任何会话删除能力：用户只能等保留期过期（默认 30 天），或等活跃会话数达上限被系统自动归档；侧栏只显示「已归档」标签，用户无法主动清理。（2）附件上传的单点 MIME 白名单不含 zip，用户上传 `.zip` 时网关返回 `ATTACHMENT_TYPE_NOT_ALLOWED`（400），前端提示「该附件类型不受支持」；同时界面从不展示支持哪些格式，用户只能试错，且 Runtime 侧本来也没有读取压缩包的能力。 |
| **当前替代方案** | （1）改名/换入口绕开；无删除替代。（2）改传 pdf/docx 等单文件；压缩包需用户自行解压后逐个上传（受单条 5 个附件上限约束）。 |
| **触发原因** | 用户反馈：历史会话堆积无法清理；上传 zip 直接报错且不知道哪些格式能用。 |

### 2.2 目标与价值

| 维度 | 内容 |
|------|------|
| **核心目标** | 让用户能一键删除自己的 WebChat 会话（删完列表、通知、详情一致不可见），并让 zip 成为可上传、可被 Agent 读取的正式格式，同时把「支持哪些格式」如实展示给用户。 |
| **预期价值** | 用户自主管理历史；减少「白传一次才知道不支持」的无效操作；压缩包一次传多个文档，直接突破单条附件数量上限。 |

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 会话主动删除能力 | 无 | 有（软删，含活跃 Run 处理） | API + 浏览器场景 |
| 可上传且可被 Agent 读取的格式 | 10 类 MIME，无压缩包 | 增加 zip（含 `x-zip-compressed`） | 网关用例 + Runtime 读取用例 |
| 界面对支持格式的展示 | 无 | 与后端白名单同源、随配置变化 | 前端契约测试 |

### 4.1 功能清单

| 功能ID | 功能名称 | 功能描述 | 优先级 | 来源用户故事 |
|--------|---------|---------|--------|-------------|
| FEAT-01 | 会话删除接口 | WebChat 公共路径提供删除；网关转 Owner，Runtime 按 (tenant,user,agent,入口) 核属后软删会话行。 | P0 | US-01 |
| FEAT-02 | 活跃 Run 处理 | 同一请求内先取消该会话的活跃 Run，再软删会话；删除接口不等 Run 到终态。 | P0 | US-02 |

| FEAT-04 | 前端删除入口与状态收敛 | 侧栏条目提供删除操作与二次确认；删除成功后条目移除、选中态回退并清空该会话的本地草稿/游标。 | P0 | US-01/02 |
| FEAT-05 | zip 准入 | 附件白名单增加 zip 两种 MIME；白名单收敛为 Gateway 与 Runtime 共享的单一事实。 | P0 | US-04 |
| FEAT-06 | Runtime 受限 zip 读取 | Agent 可列出压缩包成员并读取文本成员内容；带解压总量/成员数/压缩比上限与加密包拒绝。 | P0 | US-04 |
| FEAT-07 | 支持格式展示 | 客户端配置投影携带支持格式清单；Composer 展示清单并按清单设置文件选择器过滤。 | P0 | US-05 |
| FEAT-08 | 规范同步 | 按实现事实更新 `harness-im`、`harness-api` 等 Spec（归档阶段应用 Delta）。 | P0 | US-01/04/05 |

#### FEAT-01: 会话删除接口

- **描述**: `DELETE /api/v1/webchat/conversations/{conversation_id}`；网关按 CHAT 主体门控后转 Runtime 受信内部端点，Runtime 复用既有核属（租户/用户/Agent/入口同时成立）后置 `is_deleted=true`。
- **验收标准**:
  - [ ] 删除自己名下会话返回成功；会话随即从历史列表消失，详情/消息/续聊一律 `COMMON_NOT_FOUND`。
  - [ ] 他人会话、跨租户、跨入口、不存在的 id 一律 `COMMON_NOT_FOUND`，不泄露存在性。
  - [ ] 重复删除同一会话按「已达成」返回成功（DELETE 幂等），不因重试报错。
  - [ ] 删除不物理删除消息、产物与审计行；存储不做回收（软删口径）。

#### FEAT-02: 活跃 Run 处理

- **描述**: 删除请求内先定位该会话的活跃 Run（至多一个）并调用既有取消语义，再软删会话；删除响应不等待 Run 进入终态。
- **验收标准**:
  - [ ] 会话有排队/等待中的 Run：同一请求内取消并释放准入份额，随后软删成功。
  - [ ] 会话有执行中的 Run：请求内写入取消标记并返回成功；Run 在后台按既有协作取消停在下一个检查点。
  - [ ] 删除接口的响应时间与 Run 是否执行中无关（不轮询终态）。
  - [ ] 取消产生的终态事件与通知仍按既有契约落库；通知按 FEAT-03 不进入用户收件箱。

#### FEAT-03: 通知收口

- **描述**: 删除会话时把该会话的通知一并软删；通知列表与未读徽标只统计会话未删的行。
- **验收标准**:
  - [ ] 删除后该会话的历史通知不再出现在收件箱，未读数相应下降。
  - [ ] 删除后收尾 Run 新写入的该会话通知也不出现在收件箱与未读数里。
  - [ ] 其它会话的通知与未读数不受影响；通知分页游标不因过滤出现跳读/重复。
  - [ ] 投递回执（delivery_state）等审计字段保持既有保留策略，不因会话删除被破坏。

#### FEAT-04: 前端删除入口与状态收敛

- **描述**: 会话历史条目提供删除操作（条目右侧操作菜单），点击后二次确认；成功后本地状态收敛。
- **验收标准**:
  - [ ] 删除成功后条目立即从列表移除；若删的是当前选中会话，视图回到「无会话」状态且不自动新建。
  - [ ] 该会话的本地草稿、已应用游标与滚动锚点被清理，不残留到其它会话。
  - [ ] 删除失败按稳定码提示可重试；失败不移除条目。
  - [ ] 删除进行中防重复点击；删除不影响其它会话的活跃 Run 与流。

#### FEAT-05: zip 准入

- **描述**: 附件白名单增加 `application/zip` 与 `application/x-zip-compressed`；白名单从「网关常量 + Runtime 抽取器两份事实」收敛为一处共享定义。
- **验收标准**:
  - [ ] `.zip` 上传成功并返回权威元信息（`kind=DOCUMENT`），不再返回 `ATTACHMENT_TYPE_NOT_ALLOWED`。
  - [ ] 白名单仍显式拒绝可执行内容与未登记格式，拒绝码与文案不变。
  - [ ] 入站渠道（企微）与 WebChat 使用同一份白名单，行为一致。
  - [ ] 数量与大小上限口径不变。

#### FEAT-06: Runtime 受限 zip 读取

- **描述**: Agent 读取附件时可识别压缩包，列出成员清单；对文本类成员可读取内容（含分页）。
- **验收标准**:
  - [ ] 读取 zip 返回成员清单（名称、原始大小、是否可读为文本），不报「不支持的内容类型」。
  - [ ] 文本成员内容可读取并遵守既有分页/截断语义；非文本成员在清单中标注但内容不外泄、不内联为多模态。
  - [ ] 加密包、损坏包、成员数/解压总量/压缩比超限、嵌套压缩包的拒绝都是显式错误并指明原因。
  - [ ] 解压过程不落盘、不产生路径穿越风险（成员名按既有路径规范化规则处理）。
  - [ ] 压缩包本身仍可被用户下载（产物下载口径不变）。

#### FEAT-07: 支持格式展示

- **描述**: 客户端配置投影携带支持格式清单（与白名单同源），Composer 以「支持格式」提示展示，并用同一清单设置文件选择器过滤。
- **验收标准**:
  - [ ] 提示中出现的格式与白名单完全一致，白名单变化后提示随之变化（不在前端硬编码第二份）。
  - [ ] 文件选择器按清单过滤；拖拽/粘贴等绕过选择器的路径仍由服务端门控兜底。
  - [ ] 投影缺字段或格式非法时前端显式失败（沿用现有配置解析口径），不回落猜测值。
  - [ ] zh-CN/en-US 词条齐备。

#### FEAT-08: 规范同步

- **描述**: 按实现事实更新相关 Spec 与配置清单。
- **验收标准**:
  - [ ] `harness-im` 增加会话删除与通知收口规则、附件白名单来源说明。
  - [ ] `harness-api` 增补错误码/接口口径（若新增稳定码）。
  - [ ] `docs/configuration-inventory.csv` 与相关机检保持一致。

### 4.2 边缘情况

| 场景 | 预期行为 |
|------|----------|
| 删除已归档/已过期会话 | 删除成功（不因归档或超保留期拒绝）；结果同样从列表消失 |
| 删除与「发送消息」并发 | 消息提交与删除都按核属判：删除先成功则提交返回 `COMMON_NOT_FOUND`；提交先成功则其 Run 按活跃 Run 处理 |
| 删除时 Run 处于 `WAITING_INPUT` | 按未开始执行分支取消（中断行关闭、写取消事件），再软删 |
| 删除后浏览器仍持有该会话的 SSE 订阅 | 订阅按既有失效语义关闭；前端不因此报错 |
| zip 为空包 / 只有目录项 | 明确提示「压缩包内没有可读文件」，不当作损坏包 |
| zip 含超长/含控制字符/路径穿越成员名 | 清单中按规范化规则展示或标注为不可读；绝不写盘 |
| zip 成员为加密或非 UTF-8 文本 | 清单标注不可读；读取时给出明确原因 |
| 上传 MIME 为空的 zip（浏览器未识别） | 仍按未登记类型拒绝；前端按扩展名预检时给出「支持格式」提示 |

## 5. 非功能需求

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-PERF-01 | 性能 | 删除接口 P95 不高于同环境普通 WebChat 写接口；不随 Run 执行时长增长（不轮询终态） |
| NFR-SEC-01 | 安全 | zip 读取必须有界：成员数、解压总量、单成员大小与压缩比上限；拒绝加密包；不写盘解压；不因压缩包内容绕过附件门控 |
| NFR-REL-01 | 一致性 | 删除与通知收口在同一事务语义内完成；部分失败不留下「会话已删但通知仍在」的半状态 |
| NFR-COMPAT-01 | 兼容 | 现有 `ATTACHMENT_TYPE_NOT_ALLOWED` 等错误码与文案不变；已存量的非 zip 附件读取行为不变 |

## 6. 范围与边界

| 类别 | 内容 |
|------|------|
| **范围（In Scope）** | WebChat 用户侧会话删除（软删 + 活跃 Run 取消）、通知收口、前端删除入口与状态收敛；zip 准入与 Runtime 受限读取；支持格式的动态投影与展示；相关 Spec/配置清单同步。 |
| **非范围（Out of Scope）** | Console 管理侧会话管理（Console 现无会话管理面，本次不新建）；硬删/物理清理与存储回收；rar/7z/tar 等其它压缩格式；zip 内图片直接内联为多模态；会话重命名、手动归档/恢复。 |
| **前置假设** | 会话归属、CHAT 主体门控、取消语义、附件门控与产物下载均沿用现有实现；软删行即视为「用户不可见」的既有口径不变。 |

## 7. 依赖与风险

### 7.1 项目依赖

| 依赖方 | 依赖内容 | 最晚交付时间 | 风险等级 |
|--------|----------|--------------|---------|
| Runtime 取消语义（`RunService._cancel`） | 按会话定位活跃 Run 并取消 | 与实现同批 | 低 |
| 附件门控（`attachment_gate`） | 白名单收敛为共享定义 | 与实现同批 | 中 |
| Runtime 附件抽取（`read_attachment`） | 增加 zip 读取能力 | 与实现同批 | 中 |

### 7.2 风险识别

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|----------|
| RISK-01 | 白名单目前是网关常量、读取能力在 Runtime，两处会漂移 | 出现「能传不能读」或反之 | 收敛到 `packages/contracts` 单一事实，两侧引用同一清单，并有契约测试 |
| RISK-02 | zip 是典型攻击面（zip bomb、加密包、路径穿越、嵌套包） | 资源耗尽或安全问题 | 有界解压 + 显式拒绝 + 不写盘，单测覆盖全部拒绝路径 |
| RISK-03 | 通知过滤改变未读数与分页口径 | 徽标少算、分页跳读 | 过滤放在同一查询，游标口径按「已扫描行数」复核，补回归用例 |
| RISK-04 | 删除与消息提交/取消并发 | 半状态或误删 | 核属 + Run 行锁 + 状态 CAS 均在事务内；并发用例覆盖 |
| RISK-05 | 软删不回收存储，历史数据持续增长 | 存储成本 | 明确为非范围；如需回收另开需求 |

## 附录：术语表
