# WebChat 会话删除与附件格式支持 验收场景

> 这是给**人工测试者**使用的验收清单，不是 E2E 代码或测试注册表。
> 场景 ID 与 Task 的 `Scenarios` 字段对应；步骤用真实用户动作描述，期望写可观察结果。
> 「负责」在 `cf-task:plan` 阶段回填到具体 TASK。

## S-01 删除一个普通历史会话

- **负责**：TASK-待定
- **验收边界**：真实 Gateway + Runtime + PG，WebChat 页面
- **前置**：
  - 已有至少两个历史会话，其中一个含若干轮消息
  - 用户已登录 WebChat
- **步骤**：
  1. 在左侧会话历史中找到要删除的会话
  2. 悬停（或键盘聚焦）该条目，打开右侧操作菜单
  3. 点击「删除会话」
  4. 在确认框里点「删除」
- **期望**：
  - 确认框文案包含该会话标题，并说明不可恢复
  - 条目从列表消失，列表总数减一
  - 若删除的是当前打开会话，右侧回到「新对话」空态，且不会自动新建会话
  - 刷新页面后该会话仍不在列表中
- **实际结果**：待执行（通过/失败 + 实际观察）

## S-02 删除正在执行中的会话

- **负责**：TASK-待定
- **验收边界**：真实 Runtime，执行中的 Run
- **前置**：
  - 已在一个会话里发送一条需要较长处理的消息，界面显示「处理中」
- **步骤**：
  1. 在该会话处于处理中时，打开条目操作菜单并删除
  2. 确认删除
  3. 观察删除操作返回的速度，以及随后几秒内通知区域的变化
- **期望**：
  - 确认后很快返回（与普通删除无明显差别，不需要等待「停止」按钮）
  - 会话从列表消失
  - 数秒内该会话不再出现在通知收件箱，未读徽标不因它增加
  - 其它会话的进行中任务不受影响
- **实际结果**：待执行（通过/失败 + 实际观察）

## S-03 删除后通知收口

- **负责**：TASK-待定
- **验收边界**：真实 Runtime，通知收件箱与未读徽标
- **前置**：
  - 该会话已产生过至少一条完成通知（收件箱里有它、未读数大于 0）
- **步骤**：
  1. 记下删除前的未读数
  2. 删除该会话
  3. 打开通知收件箱查看
  4. 刷新页面再看一次
- **期望**：
  - 收件箱里该会话的通知全部消失
  - 未读数相应减少，且只减少该会话的条数
  - 其它会话的通知保持不变
- **实际结果**：待执行（通过/失败 + 实际观察）

## S-04 上传 zip 并让 Agent 读出内容

- **负责**：TASK-待定
- **验收边界**：真实 Gateway + Runtime + 模型
- **前置**：
  - 准备一个包含 2–3 个文本文件（如 `.md`、`.csv`）的 zip
- **步骤**：
  1. 新建会话，点击附件按钮选择该 zip
  2. 发送消息：「把这个压缩包里的文件列出来，并总结内容」
  3. 观察回复
- **期望**：
  - 附件上传成功，不再出现「该附件类型不受支持」
  - Agent 能列出包内文件名，并引用其中的文本内容
  - 长内容可按段继续读取，不出现「不支持的内容类型」
- **实际结果**：待执行（通过/失败 + 实际观察）

## S-05 选文件前看到支持格式

- **负责**：TASK-待定
- **验收边界**：真实 WebChat 页面
- **前置**：
  - 用户已登录且页面配置已加载
- **步骤**：
  1. 打开输入区，查看提示文案
  2. 点击附件按钮，观察系统文件选择器的可选类型
  3. 尝试选择一个不在清单里的文件（如 `.exe`）
- **期望**：
  - 输入区明确列出支持格式（与后端允许的一致，含 zip）
  - 文件选择器默认只显示名单内的类型
  - 即使在选择器里切到「所有文件」选中不支持的类型，界面立即提示该类型不支持，且该文件不进入待发送附件
- **实际结果**：待执行（通过/失败 + 实际观察）

## E-01 删除不属于自己的会话

- **负责**：TASK-待定
- **验收边界**：真实 Gateway + Runtime，两个用户
- **前置**：
  - 用户 A、用户 B 各有一个会话
  - 已取得用户 B 的会话标识
- **步骤**：
  1. 以用户 A 的身份，直接对用户 B 的会话发起删除请求
  2. 再对一个不存在的会话标识发起删除
- **期望**：
  - 两次都返回「未找到」一类的结果，不泄露该会话是否存在
  - 用户 B 的会话仍然存在，登录后可见
- **实际结果**：待执行（通过/失败 + 实际观察）

## E-02 上传加密或损坏的压缩包

- **负责**：TASK-待定
- **验收边界**：真实 Gateway + Runtime
- **前置**：
  - 准备一个带密码的 zip，以及一个被截断的 zip
- **步骤**：
  1. 分别上传并询问包内内容

- **期望**：
  - 上传本身成功（格式受支持）
  - Agent 明确说明该压缩包无法读取（加密或损坏），而不是编造内容
  - 会话与其它附件不受影响
- **实际结果**：待执行（通过/失败 + 实际观察）

## 场景编写约定

- 一个场景只验证一个用户可理解的目标。
- 步骤按真实操作顺序编号；期望写「用户看到什么/数据变成什么」。
- 不出现选择器、内部函数名或测试断言；这类内容在 Task 的 `### Tests` 与 E2E 里。
- 场景不生成 manifest、不登记执行结果、不阻断 `task finish` 或 `task archive`。
