## 2. 背景与目标

### 2.1 问题陈述

| 维度 | 内容 |
|------|------|
| **问题描述** | 技能可以执行系统命令（如 `cat`、`ps`、`kill`、`curl`、`shutdown`），模型发起调用后命令直接执行，**没有任何命令级的人工卡点**。平台唯一的“人工确认”能力是记忆保存确认，且整条链路硬编码为记忆专用（`interrupt_type=MEMORY_CONFIRMATION` 贯穿挂起、投影、恢复、过期与前端）。 |
| **当前替代方案** | ① 靠 Prompt/技能说明让模型“自己先问用户”——模型可以不问，也可以被诱导绕过，不可强制；② 从技能里删掉高危命令——能力不可用；③ 依赖沙箱隔离——沙箱只是执行边界（`/usr`、`/bin` 只读挂载、无二进制白名单），不提供任何“人确认”语义。 |
| **触发原因** | 已有技能集成了系统命令集合，其中 `kill`、`curl`、`shutdown` 属高危操作，产品要求：必须真实用户二次确认才放行，且命令与参数要让用户看到。 |

### 2.2 目标与价值

| 维度 | 内容 |
|------|------|
| **核心目标** | 技能声明的高危命令，在交互式会话中必须由真实用户明确确认后才执行；未确认、被拒绝、过期或取消的命令一律不执行。 |
| **预期价值** | 高危动作从“模型决定”变成“用户决定”；每一次待授权与执行都有可追溯的审计事实；用户可在半天内异步确认，不必盯着屏幕。 |

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 已声明高危命令的绕过路径 | 无卡点（任何命令都直接执行） | 0 条（未确认不得执行） | 集成测试 + 人工验收场景 |
| 待授权命令的参数可见性 | 无 | 100% 展示命令全文与参数 | 前端契约测试 + 人工验收 |
| 授权→执行的审计完整性 | 不适用 | 每条命令都有一条待授权事实 + 一条执行结果事实 | 审计表断言 |

## 4. 功能需求

### 4.1 功能清单

| 功能ID | 功能名称 | 功能描述 | 优先级 | 来源用户故事 |
|--------|---------|---------|--------|-------------|
| FEAT-01 | 技能声明高危命令 | 技能包声明一组需要人工授权的命令；声明随技能解析、快照与执行边界生效。 | P0 | US-01 |
| FEAT-02 | 执行边界拦截与暂存 | 命令类工具调用命中声明时**不执行**，只生成一条待授权事实并回给模型一个收据。 | P0 | US-02 |
| FEAT-03 | 待授权确认卡 | 复用现有确认卡形态展示：命令全文、参数、工作目录、命中原因、有效期；选项为确认/拒绝。 | P0 | US-02/07 |
| FEAT-04 | 确认消费与唯一执行 | 确认/拒绝在锁内消费；确认后按暂存内容**逐字**执行一次，拒绝则永不执行。 | P0 | US-02/03 |
| FEAT-05 | 执行前重校验 | 真正执行前复核命令身份与目标仍成立；不成立则拒绝执行并显式说明（模型重新提案）。 | P0 | US-04 |
| FEAT-06 | 授权有效期 | 待授权有独立有效期，上限 12 小时；与 Run 的机器执行预算解耦；超时收尾为明确终态。 | P0 | US-04 |
| FEAT-07 | 禁止定时下发 | 声明了高危命令的技能在创建/修改/触发（Fire）与执行期均不得被定时任务使用。 | P0 | US-06 |
| FEAT-08 | 审计与指标 | 待授权与执行两段事实都落审计（含确认人、时间、结果）；拒绝/过期/取消同样留痕。 | P0 | US-05 |
| FEAT-09 | 文本渠道确认 | 企微等文本渠道支持短动词确认/拒绝，文案与网页一致（同一份投影）。 | P1 | US-07 |

#### FEAT-01: 技能声明高危命令

- **描述**: 技能以声明方式给出“需要人工授权才可执行”的命令清单；未声明的技能行为不变。
- **验收标准**:
  - [ ] 声明可在技能包内表达，并随技能解析结果传递到运行时与任务侧（不依赖读取技能源码推断）。
  - [ ] 声明非法（空项、重复、超长、非法字符）在导入/审核/保存时显式拒绝，不落库。
  - [ ] Console 能展示某技能声明了哪些高危命令（技能详情可读）。
  - [ ] 未声明高危命令的技能，执行路径与现状完全一致。

#### FEAT-02: 执行边界拦截与暂存

- **描述**: 模型经统一执行入口（`execute` 的命令类目标及其兼容入口）发起命令时，运行时判定是否命中声明；命中则不执行，只暂存。
- **验收标准**:
  - [ ] 命中声明时命令**不执行**，模型收到一个明确的“待用户确认”收据（含授权编号），而不是成功结果或普通报错。
  - [ ] 未命中时执行行为不变（无新增延迟、无额外确认）。
  - [ ] 判定在服务端完成，模型无法通过参数、文本或“我确认了”跳过。
  - [ ] 无法可靠判定的命令形态（管道、`sh -c`、变量展开等）按**命中**处理，而不是放行。
  - [ ] 同一回合多个命中：至少第一个进入待授权，其余给出明确结论（见 OPEN-04），不得静默执行。

#### FEAT-03: 待授权确认卡

- **描述**: 复用现有确认卡片（服务端投影 + 前端只读渲染），展示内容由服务端生成。
- **验收标准**:
  - [ ] 卡片展示：命中命令原文、参数（逐项）、工作目录、命中原因、授权编号、有效期。
  - [ ] 选项只有确认/拒绝；前端不得自行改写、重新编号或新增选项。
  - [ ] 授权期间消息流显示“等待你的确认”，过期后显示过期提示且选项不可再提交。
  - [ ] 文本渠道展示同一份投影的文本版本，短动词“确认/拒绝”可消费。
  - [ ] 展示文案 zh-CN / en-US 齐备。

#### FEAT-04: 确认消费与唯一执行

- **描述**: 用户确认在锁内消费待授权，并以暂存内容执行，执行一次且仅一次。
- **验收标准**:
  - [ ] 确认绑定具体授权身份（编号 + 命令参数指纹），不能确认“别的授权”；不一致显式失败且不执行。
  - [ ] 执行使用暂存的命令与参数逐字比对，不从模型后续文本、不重新解析用户消息。
  - [ ] 重复确认（含并发、网络重试）幂等：不产生第二次执行。
  - [ ] 拒绝后命令永不执行，Run 继续，模型收到“被用户拒绝”的可读结论。
  - [ ] 执行结果（stdout/stderr/exit code）对用户可见，并作为事实进入后续模型上下文。
  - [ ] 用户在等待期间取消 Run：待授权随之取消，命令不执行。

#### FEAT-05: 执行前重校验

- **描述**: 从确认到执行之间可能隔很久，执行前必须复核“这条命令此刻仍然成立”。
- **验收标准**:
  - [ ] 执行前复核：命令与参数指纹、授权人身份、Run 归属、授权未过期、目标上下文未失效（如 Run 已被取消/终态）。
  - [ ] 任一不成立则不执行，给出明确原因，并允许模型重新提案（新授权编号）。
  - [ ] 复核失败同样留审计，不得静默丢弃。

#### FEAT-06: 授权有效期

- **描述**: 待授权本身有独立时限，不依赖 Run 的机器执行期限。
- **验收标准**:
  - [ ] 待授权有效期可配置，产品上限 12 小时；展示值即服务端权威值。
  - [ ] 等待期间 Run 不因机器执行期限到期被判失败；等待不消耗机器的执行预算。
  - [ ] 到期后授权自动收尾为“未确认/过期”，Run 以明确结论结束，命令绝不执行。
  - [ ] 到期后用户再点确认或回复“确认”得到显式过期错误，不产生任何执行。

#### FEAT-07: 禁止定时下发

- **描述**: 声明了高危命令的技能不得进入定时/后台执行路径。
- **验收标准**:
  - [ ] 创建或修改定时任务时解析到该类技能：显式拒绝，并给出可操作说明。
  - [ ] 每次定时触发（Fire）重新解析时命中：该次不执行，任务进入“需要处理”状态并说明原因，不反复刷屏。
  - [ ] 已存在、尚未执行的任务执行在领取时命中：不执行，显式失败并留痕（配置变更只影响后续执行，见 RULE-snapshot-001）。
  - [ ] 暂停/恢复（重新准入）时命中：恢复失败并说明原因。
  - [ ] 该限制按技能身份判定，不依赖某一次冻结快照里的旧版本标记。

#### FEAT-08: 审计与指标

- **描述**: 待授权与执行是两段事实，必须都可追溯。
- **验收标准**:
  - [ ] 审计可回答：哪个 Run、哪次调用、哪条命令（脱敏后的参数）、谁在何时确认/拒绝、何时执行、结果如何。
  - [ ] “待授权”与“执行结果”是可区分的两个状态，不得只留其一。
  - [ ] 拒绝、过期、取消三条路径都有审计行。
  - [ ] 有指标覆盖待授权/确认/拒绝/过期/执行失败，标签不含具体命令文本。

#### FEAT-09: 文本渠道确认（P1）

- **描述**: 企微等文本渠道复用同一套授权与消费语义。
- **验收标准**:
  - [ ] 企微用户能收到待确认提示与完整命令文本。
  - [ ] 用户只回复“确认/拒绝”即可；带编号时逐项核对，编号不属于当前 Run 显式失败。
  - [ ] 网页与文本渠道确认的是同一份授权，任一渠道消费后另一渠道不能再消费。

### 4.2 边缘情况

| 场景 | 预期行为 |
|------|----------|
| 用户长时间不在，超过授权窗口 | 授权过期、Run 收尾、命令不执行；用户回来可让模型重新提案 |
| 用户在等待期间发其他消息 | 见 OPEN-06：显式取消待授权或给出明确提示，不得被当作普通消息静默吞掉 |
| 用户拒绝后模型再次发起同一命令 | 产生新授权，仍需再次确认（不记忆“已拒绝”） |
| 同一命令在确认前被取消 Run | 授权取消，命令不执行 |
| 命令原文含凭据（如 `curl -H "Authorization: ..."`） | 确认人可见（见 OPEN-05）；审计与日志按密钥规范脱敏 |
| 命中命令在确认后、执行前技能版本更新 | 执行的是暂存的命令与参数，不因版本变化改变内容；若执行上下文失效则按 FEAT-05 拒绝 |
| 技能被下架/解绑 | 已批准的授权执行前复核失败，不执行 |
| 命令超长或参数过多 | 卡片有界展示并支持查看完整内容，不截断到无法判断 |
| 沙箱不可用（bwrap 缺失） | 与现状一致显式失败，不因确认流程改变错误语义 |

## 5. 非功能需求

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-SEC-01 | 安全 | 未确认的命令在任何路径下都不得执行；确认只能是真实用户动作，模型文本不得构成授权。 |
| NFR-SEC-02 | 安全 | 命令参数中的密钥不得进入日志、审计预览、指标标签；确认卡片按受控出口展示给确认人本人。 |
| NFR-REL-01 | 可靠性 | 服务重启、Pod 切换、滚动发布不影响待授权与恢复；执行一次且仅一次。 |
| NFR-REL-02 | 可靠性 | 确认链路失败不得让 Run 永久卡在等待态：过期与取消都有明确终态。 |
| NFR-PERF-01 | 性能 | 未命中声明时不引入可感知的执行延迟。 |
| NFR-CAP-01 | 容量 | 长时间等待人工确认不得占满用户的可并发执行名额（见 OPEN-03）。 |
| NFR-OBS-01 | 可观测性 | 待授权/确认/拒绝/过期/执行有指标与结构化日志；不得记录命令全文到日志。 |

## 6. 范围与边界

| 类别 | 内容 |
|------|------|
| **范围（In Scope）** | 交互式 Run（WebChat + 文本渠道）内的命令类执行；技能级高危命令声明；拦截与暂存；确认卡；确认/拒绝/过期/取消；执行前重校验；审计与指标；禁止定时下发。 |
| **非范围（Out of Scope）** | 定时/后台任务内的人工确认（本期直接禁止，不提供确认）；技能内部自执行命令的强制管控（见 RISK-01）；MCP 工具级授权；非命令类工具的通用审批；按租户的策略中心与审批流；多级审批/会签。 |
| **前置假设** | 技能代码可修改，高危动作可以被收口到平台执行边界（`execute` 命令类目标），技能内部不再自行执行高危命令。 |

## 7. 依赖与风险

### 7.1 项目依赖

| 依赖方 | 依赖内容 | 最晚交付时间 | 风险等级 |
|--------|----------|--------------|---------|
| 记忆确认链路 | 复用确认投影、卡片、resume 身份绑定与过期机制 | 本需求内 | 低 |
| 定时任务准入 | `NEEDS_ATTENTION` + 永久错误码分类 | 本需求内 | 低 |

### 7.2 风险识别

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|----------|
| RISK-01 | 技能内部自执行命令（沙箱 `/usr`、`/bin` 只读挂载、网络默认开启、无二进制白名单），卡点被绕过 | “强制”不成立 | 本期以平台执行边界为准，要求技能不自行执行高危动作并写入技能规范；沙箱白名单/禁网作为后续独立需求 |
| RISK-02 | 命令字符串解析不可靠（包装器、管道、变量展开） | 漏放或误拦 | 宁可误拦：无法可靠判定一律按命中处理 |
| RISK-03 | 12 小时等待与现有“人工交互有效期不得超出执行 deadline”的口径冲突 | 需要改口径，影响记忆确认与 Worker | 见 OPEN-03，需在 PRD 复核时决定 |
| RISK-04 | 长时间等待后执行旧命令（目标已变化） | 用户确认的不是真实执行的动作 | FEAT-05 执行前重校验；不成立则重新提案 |
| RISK-05 | 单槽位限制导致一轮多条命中时行为不直觉 | 用户困惑 | OPEN-04 决策后写清结论 |
| RISK-06 | 技能声明与技能实际行为不一致（声明了 kill，实际跑 `sh -c`） | 绕过 | 技能审核 + 文本渠道展示原文 + RISK-01 的后续治理 |

## 附录：术语表

| 术语 | 定义 |
|------|------|
| 高危命令 | 技能声明为必须人工授权才可执行的命令 |
| 待授权（Authorization） | 一条已暂存、尚未由用户确认的命令及其身份、参数与有效期 |
| 授权窗口 | 待授权从创建到过期的有效时间，产品上限 12 小时 |
| 暂存 | 命中高危声明后只记录动作、不执行 |
| 收据 | 工具调用返回给模型的“待用户确认”结果 |
| 执行边界 | 平台统一执行命令的工具入口（`execute` 的命令类目标及其兼容入口） |
