# 运行审计列表操作粒度 人工验收场景

> **文档版本**: v1.0
> **创建日期**: 2026-11-17
> **需求**: `audit-operation-view.prd.md`
> **设计**: `audit-operation-view.backend.design.md` / `audit-operation-view.frontend.design.md`

**使用约定**:

- 场景是人工验收资产，不是自动化清单；不记录 selector、内部 API 路径或实现细节。
- 每个场景写清目标、前置、人工步骤、可观察结果和负责人。
- 真实边界：真实构建产物、真实 PostgreSQL、真实 Runtime/Console。
- 未满足环境时记录缺失项与 owner，不把环境缺失伪装成产品失败。

## S-01 默认视图：一次对话只占一行

**目标**: 列表默认按业务操作成行，一次对话不再拆成多行。

**前置**:
- Console 已登录，当前租户至少有一次包含工具调用的对话（Run 内 1 次以上工具调用、多次模型调用）；
- 该对话可在「运行审计」中检索到。

**步骤**:
1. 打开「运行审计」。
2. 不设置任何筛选，观察列表。
3. 找到刚才那次对话对应的行。
4. 观察该行的时间列与各列对齐。

**预期**:
- 这次对话在列表里只有 **1 行**，审计类型为「运行」。
- 该行能看到：日期与时刻、耗时、操作人、Agent、运行标识与来源（如 WebChat）、本轮用户提问摘要。
- 列表没有「内部步骤」列；步骤统计在运行详情里看（见 S-04）。
- 两行行高的单元格内容垂直居中，关联对象与相邻列对齐。
- 拖动分页或刷新后，该对话仍只有一行。

**负责人**: 前端 + 后端

## S-02 失败的对话在默认视图可辨认

**目标**: 扫列表时能立刻认出失败的对话，再进详情定位具体步骤。

**前置**:
- 存在一次结果为失败的对话（工具参数校验失败或工具返回错误）；
- 另存在一次「模型重试过但最终成功」的对话。

**步骤**:
1. 打开「运行审计」，保持默认视图。
2. 找到失败的那次对话。
3. 观察该行行首与结果列。
4. 点开该对话的运行详情，查看「运行概览」的步骤统计与「失败原因」。

**预期**:
- 失败行行首有红色标记；结果列显示「失败」。
- 列表不展示失败步骤文案；运行详情的「失败原因」给出错误码与说明，事件轮廓里能看到失败的那一步。
- 重试但成功的行在列表显示为成功；运行概览的「其中重试」显示重试次数。

**负责人**: 前端 + 后端

## S-03 步骤明细视图：一行 = 一次调用

**目标**: 需要看单次调用时，仍能拿到与改造前一致的明细。

**前置**:
- 已知存在一次含多次模型/工具调用的对话。

**步骤**:
1. 打开「运行审计」。
2. 把「审计类型」切换为「工具调用」。
3. 观察列表与页面提示。
4. 再切换为「模型调用」。
5. 点提示条上的「返回操作视图」。

**预期**:
- 切到「工具调用」后，列表变为逐条调用记录：时间、操作人、Agent、关联运行、动作（调用工具 X）、结果。
- 顶部出现提示条，说明当前是步骤明细视图，并给出返回操作视图的入口。
- 「审计类型」下拉当前显示「工具调用」。
- 切到「模型调用」后同样为逐条模型调用记录。
- 点「返回操作视图」后，审计类型恢复为全部，列表恢复一次对话一行。

**负责人**: 前端

## S-04 点开运行：完整链路仍在详情里

**目标**: 折叠到详情里的步骤信息完整可读。

**前置**:
- 默认视图中有一次含模型调用与工具调用的对话。

**步骤**:
1. 打开「运行审计」，默认视图。
2. 点该行的运行标识。
3. 在右侧详情中从上到下查看时间线。
4. 关闭详情，改点该行首列的 Trace ID。

**预期**:
- 打开的是运行详情，能看到：发起人、Agent、来源、结果与耗时、Trace ID、模型名。
- 「运行概览」页签显示模型调用、工具调用与出网调用次数，有重试时额外显示「其中重试」。
- 时间线包含用户消息、每一次模型调用（模型名、耗时、token）、每一次工具调用（工具名、耗时、返回摘要）、最终回复与运行完成。
- 失败场景下，时间线里能看到失败的那一步及错误信息。
- 首列与运行标识打开的是同一个详情。

**负责人**: 前端

## S-05 配置变更与出网各自独立成行

**目标**: 其他审计类型不因本次改动被折叠或丢字段。

**前置**:
- 租户内存在至少一条配置变更记录与一条出网记录（被拒绝或成功均可）。

**步骤**:
1. 打开「运行审计」，默认视图。
2. 找到配置变更行与出网行。
3. 核对两行的字段。
4. 对配置变更行，尝试打开其审计详情。

**预期**:
- 配置变更、出网各自独立成行，审计类型分别为「配置变更」「出网」。
- 字段与改造前一致：操作人、对象、动作、结果；出网行能看到目标与策略结论。
- 配置变更行仍可打开原审计详情（含变更前后与来源 IP）。
- 两行的「内部步骤」列显示 `-`。

**负责人**: 后端 + 前端

---

## S-06 导出仍是全量明细

**目标**: 列表变粗不影响审计留档。

**前置**:
- 默认视图中存在一次含模型与工具调用的对话；
- 导出功能可用。

**步骤**:
1. 打开「运行审计」，保持默认视图。
2. 点「导出」，按默认条件创建导出任务。
3. 等导出完成后下载并打开文件。
4. 在该文件中查找刚才那次对话的记录。

**预期**:
- 导出文件里，这次对话的模型调用与工具调用仍是逐条记录（不是一行汇总）。
- 导出文件不包含「用户提问摘要」这一列。
- 再切到明细视图导出一次，文件内容与默认视图导出的一致。

**负责人**: 后端

---

## S-07 运行行的两个入口落点不同

**目标**: Trace ID 与关联对象各去该去的地方，不再重复打开同一个详情。

**前置**:
- 存在一次含模型/工具调用的对话，且该对话在列表中可见。

**步骤**:
1. 打开「运行审计」，默认视图。
2. 点该运行行的 Trace ID。
3. 观察列表变化与顶部提示条。
4. 点提示条上的「清除 Trace」。
5. 再点该运行行的「运行 …」链接。

**预期**:
- 点 Trace ID 后进入步骤明细视图：列表只剩该 Trace 下的审计记录，提示条显示当前 Trace 并提供「清除 Trace」。
- 点「清除 Trace」后回到操作视图（一次对话一行）。
- 点「运行 …」打开运行详情，与 Trace 下钻是完全不同的落点。

**负责人**: 前端

## E-01 列表请求失败时明确报错

**目标**: 查询失败不出现空白列表或半截数据。

**前置**:
- 可临时让 Console 后端不可用（或断网模拟）。

**步骤**:
1. 打开「运行审计」，设置一个筛选（例如操作人）。
2. 让后端请求失败。
3. 观察页面。
4. 恢复后端，点「重试」。

**预期**:
- 页面显示明确错误态与重试入口，不显示空列表假装没有数据。
- 重试后保留原筛选条件并正常返回。
- 两种视图下的失败表现一致。

**负责人**: 前端

---

## E-02 步骤聚合降级可见，不伪造 0

**目标**: 步骤统计失败时，用户看到的是「不可用」而不是「0 次调用」。

**前置**:
- 开发/测试环境可模拟步骤统计查询失败（例如临时移除该查询依赖的对象）。

**步骤**:
1. 打开「运行审计」，默认视图。
2. 造出一个会导致步骤统计失败的环境。
3. 刷新列表，观察操作行的「内部步骤」列。
4. 查看服务端日志。

**预期**:
- 列表其余字段正常返回，运行行仍可见。
- 「内部步骤」列显示 `-`，不显示 `模型 0 · 工具 0`。
- 服务端日志有明确的降级警告记录（含租户与当页运行数）。
- 恢复环境后刷新，步骤恢复显示。

**负责人**: 后端

## B-01 两个视图的分页与总数各自正确

**目标**: 切换视图不会出现页码错位或总数混用。

**前置**:
- 数据量足够翻到第 2 页（至少 2 页操作记录，且明细记录明显更多）。

**步骤**:
1. 默认视图下翻到第 2 页，记录页码与总条数。
2. 切到「工具调用」明细视图，查看第 1 页与总条数。
3. 在明细视图翻到第 2 页。
4. 返回操作视图。

**预期**:
- 两个视图的总条数按各自粒度计算，互不相同且稳定。
- 切换视图后回到第 1 页，不出现越界空页。
- 返回操作视图后，页码与总数回到操作视图口径。

**负责人**: 前端 + 后端

---

## B-02 只有任务关联的记录不被静默丢弃

**目标**: 定时任务/后台任务产生的审计记录在默认视图中不消失。

**前置**:
- 存在一次定时任务或后台任务执行，其出网记录只关联任务、没有 Run。

**步骤**:
1. 打开「运行审计」，默认视图。
2. 用时间范围定位该任务执行的时段。
3. 找到该任务产生的出网行。
4. 切到「工具调用」明细视图，再按同一时间范围查看。

**预期**:
- 默认视图里该任务的出网记录作为「出网」操作行独立展示，不被折叠或丢弃。
- 明细视图能查到同一时段的其他调用记录，字段完整。
- 切换视图过程中不出现记录丢失或重复。

**负责人**: 后端 + 前端

---

## B-03 进行中与已取消的对话

**目标**: 非终态对话在操作视图中显示正确。

**前置**:
- 存在一次仍在进行中的对话（模型或工具执行期间）；
- 存在一次用户取消的对话。

**步骤**:
1. 打开「运行审计」，默认视图。
2. 找到进行中的对话行。
3. 找到已取消的对话行。
4. 分别点开运行详情。

**预期**:
- 进行中的行结果为「进行中」，耗时列为空或显示已运行时长，不显示「失败」。
- 已取消的行结果为「已取消」，详情时间线显示取消位置。
- 两行都只有一行，不因状态变化产生重复行。

**负责人**: 后端 + 前端

## 场景编写约定

- 一个场景只验证一个用户可理解的目标。
- 步骤编号从 1 开始，按真实操作顺序编写。
- 期望写「用户看到什么 / 数据变成什么」，不写内部函数名或测试断言。
- 需要机器执行的快速回归放在 Task 的 `### Tests`；E2E 与全量回归留在 CI。
