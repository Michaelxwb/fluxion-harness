# 平台统一文件产物投递 人工验收场景

> **文档版本**: v1.0
> **创建日期**: 2026-11-17
> **需求**: `unified-artifact-delivery.prd.md`
> **设计**: `unified-artifact-delivery.backend.design.md` / `unified-artifact-delivery.frontend.design.md`

**使用约定**:

- 场景是人工验收资产，不是自动化清单；不记录 selector、内部 API 路径或实现细节。
- 每个场景写清目标、前置、人工步骤、可观察结果和负责人。
- 真实边界：真实构建产物、真实 PostgreSQL/Redis、真实 Runtime/Worker/Gateway；外部通道使用现有测试探针。
- 未满足环境时记录缺失项与 owner，不把环境缺失伪装成产品失败。

## S-01 交互式 WebChat：生成并交付一个文件

**目标**: 用户在 WebChat 对话中收到一次文件，任务/执行记录显示已交付。

**前置**:
- WebChat 入口已登录，Agent 授权正常；
- 平台文件工具可用。

**步骤**:
1. 在对话中要求生成一个文本测试文件并交付。
2. 等待助手完成。
3. 在对话中查看文件卡片。
4. 打开任务/执行记录（如当前会话有对应记录）。
5. 刷新页面后再次查看。

**预期**:
- 对话中只出现一份文件；
- 执行记录显示该文件与“已交付”；
- 刷新后仍只有一份，不重复发送；
- 下载可打开且内容与生成时一致。

**负责人**: 后端 + 前端

## S-02 ASYNC 后台任务（Run 侧）：完成后自动交付

**目标**: `execution: ASYNC` 的 Skill 由 Run 侧提交为后台任务；完成后用户收到 `SKILL_OUTPUT_DIR` 文件，模型无需再调交付工具。`JOIN` 只保留在任务内部，不在本场景。

**前置**:
- 已导入一个写 `SKILL_OUTPUT_DIR` 的 ASYNC Skill；
- 对话入口可接收附件。

**步骤**:
1. 在对话中触发该 Skill。
2. 等待后台任务完成（Run 不再等待结果）。
3. 查看对话/任务记录（WebChat 为任务中心「后台任务」分组）。
4. 刷新页面后再次查看。

**预期**:
- 文件自动出现在对话/任务记录；
- 不要求模型再次调用 `deliver_artifact`；
- 只出现一份；
- 状态显示“已交付”。

**负责人**: 后端

## S-03 定时 SKILL：无模型在环也能交付

**目标**: 定时任务没有模型等待时，文件仍按执行记录/通道交付。Run 侧 ASYNC 后台任务由 S-02 覆盖。

**前置**:
- 已配置定时 SKILL；
- 有 WebChat 或外部通道的交付路由；
- 触发间隔使用可等待的短周期（如 5 分钟）。

**步骤**:
1. 创建一个定时 SKILL。
2. 等待任务终态。
3. 查看任务/执行记录。
4. 若配置外部通道，查看通道收到的文件。
5. 等待下一次触发，确认不会把上一轮文件再发一次。

**预期**:
- 每轮执行只交付该轮文件；
- 无模型在环也能交付；
- 交付使用主动发送，不依赖任何入站回调；
- 任务记录状态跟随交付结果；
- 上一轮文件不重复发送。

**负责人**: 后端 + 运维

## S-04 定时 AGENTIC：不依赖业务 Skill 生成并交付文件

**目标**: 平台内置文件工具可用于定时 AGENTIC，不依赖 `big-output` 等演示 Skill。

**前置**:
- 定时 AGENTIC 任务可用；
- 平台文件工具已注册。

**步骤**:
1. 创建定时 AGENTIC 任务，要求生成一个文本测试文件并交付。
2. 等待触发。
3. 查看对话/任务记录。
4. 在任务详情查看文件状态。

**预期**:
- 文件生成并交付；
- 不需要业务 Skill；
- 不出现 `invalid tool arguments`；
- 状态显示“已交付”。

**负责人**: 后端

---

## S-05 任务/执行记录：状态随记录展示

**目标**: 文件与交付状态跟随所属任务/执行记录，不新增独立页面。

**前置**:
- 至少有一个已完成任务，包含文件。

**步骤**:
1. 打开任务中心 → 任务详情 → 执行记录。
2. 查看产物列表。
3. 刷新详情。
4. 切换其它任务再返回。

**预期**:
- 产物列表显示文件名、版本、状态；
- 每个目标一行状态，成功显示“已交付”；
- 未请求推送的文件显示“未推送”，不显示成已交付；
- 刷新/切换后状态一致；
- 没有新增“投递管理”页面或入口。

**负责人**: 前端

---

## S-06 外部通道：直发文件

**目标**: 外部推送通道收到文件，状态为已交付。

**前置**:
- 外部通道测试探针可用；
- 任务/对话配置了 PUSH 路由。

**步骤**:
1. 触发一次生成文件的任务。
2. 在通道测试探针查看消息。
3. 查看执行记录状态。

**预期**:
- 通道收到一份文件（主动发送，不挂到任何入站消息的回调上）；
- 执行记录显示“已交付”；
- 重复触发/重试不重复发送同一文件；
- 不同群/不同接收者各算一个目标，不互相折叠。

**负责人**: 后端 + 通道适配器

## E-01 重复交付调用：不产生第二份

**目标**: 已交付的同一文件再次请求交付时不重复发送。

**前置**:
- 一个已交付的文件；
- 可重复触发的交互式或任务入口。

**步骤**:
1. 对同一文件再次触发交付（重复点击/重复调用/刷新后重试）。
2. 查看对话或外部通道。
3. 查看执行记录状态。

**预期**:
- 用户只收到一份；
- 返回/显示首次交付结果；
- 状态仍为“已交付”，不出现第二张卡/第二条消息。

**负责人**: 后端

---

## E-02 并发重复交付：最多一次真实发送

**目标**: 两个并发请求交付同一 artifact + target 时最多一次成功发送。

**前置**:
- 可并发触发同一交付的场景。

**步骤**:
1. 同时触发两次同一文件交付。
2. 查看通道/对话。
3. 查看执行记录。

**预期**:
- 只出现一份文件；
- 不出现重复卡片/重复消息；
- 状态一致。

**负责人**: 后端

---

## E-03 外部通道失败后重试：最终成功且不重复

**目标**: 通道暂时失败后由平台重试，成功后只出现一份。

**前置**:
- 可注入外部通道失败/恢复。

**步骤**:
1. 注入通道发送失败。
2. 触发文件交付。
3. 观察执行记录为待投递/失败可重试。
4. 恢复通道，等待平台重试。

**预期**:
- 失败期间不显示“已交付”；
- 恢复后只出现一份文件；
- 状态最终为“已交付”；
- 失败原因可见。

**负责人**: 后端 + 运维

---

## E-04 渠道不支持直发：降级为取件链接

**目标**: 渠道不支持文件直发时返回取件链接，不谎报直发成功。

**前置**:
- 使用一个不支持直发文件的测试通道或注入降级。

**步骤**:
1. 触发文件交付。
2. 查看通道消息。
3. 打开取件链接。
4. 查看执行记录状态。

**预期**:
- 用户收到取件链接；
- 状态显示“已降级”/“取件链接”；
- 链接可下载且版本/校验值正确；
- 不标记为“已交付直发”。

**负责人**: 后端 + 通道适配器

---

## E-05 无交付路由：显式失败，不猜目标

**目标**: 没有可交付通道时明确失败，文件保留，不伪造送达。

**前置**:
- 一个没有交付路由的执行/任务。

**步骤**:
1. 触发文件交付。
2. 查看执行记录/工具结果。

**预期**:
- 显示“交付失败/无可用通道”；
- 不发送到其它会话；
- 文件仍保留在产物中，可供诊断/后续处理。

**负责人**: 后端

---

## E-06 执行失败/取消：不交付半成品

**目标**: 失败或取消的执行不会自动把半成品当成功文件发送。

**前置**:
- 可注入 Skill/Task 失败或取消，且执行已写入部分输出。

**步骤**:
1. 触发会失败/取消并写部分输出的执行。
2. 查看对话/通道。
3. 查看任务/执行记录。

**预期**:
- 用户没有收到半成品；
- 任务状态为失败/取消；
- 文件可保留用于诊断，但不显示“已交付”。

**负责人**: 后端

## E-08 `execute` 漏 `target`：返回可行动错误

**目标**: 模型漏传 `target` 时不再只得到笼统的 `invalid tool arguments`。

**前置**:
- 调试或测试环境可控制模型工具调用。

**步骤**:
1. 调用 `execute` 时故意不带 `target`。
2. 查看工具结果。
3. 用 `execute_skill` 或 `execute(target=skill, ...)` 正确调用同一 Skill。

**预期**:
- 错误明确指出缺少 `target`；
- 不执行任何 Skill；
- 正确调用可成功执行。

**负责人**: 后端

---

## E-09 `WORKSPACE_ROOT` 相对路径：启动归一/失败清晰

**目标**: 本地相对 `WORKSPACE_ROOT` 不再导致沙箱在启动阶段报模糊错误。

**前置**:
- 本地 `.env` 使用相对 `WORKSPACE_ROOT`。

**步骤**:
1. 启动服务。
2. 在 `target=workspace` 执行 `pwd`。
3. 写一个测试文件到 `/workspace`。
4. 检查启动日志中的 resolved workspace root。

**预期**:
- 相对路径被归一为绝对路径（或启动明确失败并说明原因）；
- `pwd` 成功；
- 写文件成功；
- 生产绝对路径行为不变。

**负责人**: 后端 + 运维

## E-10 发送结果未知：不自动重发，待核实

**目标**: 文件已发出但没拿到结论时，平台不重发、不补发链接，并在执行记录显示待核实。

**前置**:
- 外部通道探针可注入“接收不到发送回执/超时”；
- 一个已完成、已产生文件的任务。

**步骤**:
1. 注入发送无回执（连接保持、但不返回结果）。
2. 触发该任务的文件交付。
3. 观察执行记录状态。
4. 等待超过退避窗口，再次查看通道与执行记录。

**预期**:
- 通道侧最多出现一份文件（可能一份都没有，取决于服务端是否真的收到）；
- 执行记录显示“待核实”，不是“已交付”，也不是“失败可重试”；
- 平台不自动重发文件，也不补发取件链接；
- 核实后可显式处置，处置结果被记录。

**负责人**: 后端 + 通道适配器

---

## E-11 Run 终态后的晚到文件

**目标**: Run 已结束后才产生的会话产物仍能送达用户，不依赖 Run 流是否还开着。

**前置**:
- 可产生后台/延迟产物的任务（如 ASYNC DETACH 或定时任务），且目标为 WebChat 会话；
- 用户停留在该会话页。

**步骤**:
1. 触发该任务并等 Run 结束。
2. 不刷新页面。
3. 等待产物产生。
4. 刷新页面再次查看。

**预期**:
- 用户经统一消息通道收到通知/会话内出现该文件，不需要重新发起对话；
- 刷新后文件与状态一致，不重复出现；
- 没有第二份副本。

**负责人**: 后端 + 前端

---

## E-12 成功终态后崩溃：outbox 重放

**目标**: 执行成功提交后、投递意图生成前进程崩溃，恢复后不漏投也不重复投。

**前置**:
- 可在“终态已提交、投递尚未激活”窗口内停止服务；
- 一个会产出文件的 ASYNC 或定时任务。

**步骤**:
1. 触发任务，在终态提交后立即停止 Runtime（或 Worker）。
2. 查看执行记录与通道。
3. 重启服务，等待后台循环消费。
4. 再次查看执行记录与通道。

**预期**:
- 崩溃期间不出现半成品投递；
- 恢复后文件只出现一次，状态为已交付；
- 终态事务内的 outbox 被幂等消费，不产生第二份意图。

**负责人**: 后端 + 运维

## B-01 多文件部分失败

**目标**: 一次执行多个文件，部分失败不影响已成功文件，且不重发成功文件。

**前置**:
- Skill 输出 2–5 个文件；
- 可注入其中一个文件发送失败。

**步骤**:
1. 触发执行。
2. 查看执行记录中各文件状态。
3. 恢复失败文件后等待重试。

**预期**:
- 成功文件显示已交付且不重发；
- 失败文件显示失败/待重试；
- 恢复后只补发失败文件。

**负责人**: 后端

---

## B-02 重试产生同路径不同内容

**目标**: 同路径内容变化时按版本处理，不把旧版本当新版本交付。

**前置**:
- 可让 Skill 重试时写同路径不同内容。

**步骤**:
1. 触发执行并让首次尝试写入内容 A 后失败。
2. 重试写入内容 B。
3. 查看最终文件与版本/校验值。

**预期**:
- 最终交付内容 B；
- 版本/校验值与 B 一致，B 是独立的产物身份（新的不可变 `artifact_id`）；
- 内容 A 不重复交付，也不会被 B 顶替；
- 历史版本仍可按版本+校验值辨别。

**负责人**: 后端

---

## B-03 输出文件数量/大小超限

**目标**: 输出目录超限时显式失败，不静默截断或丢文件。

**前置**:
- 可配置/构造超出文件数或单文件大小的输出。

**步骤**:
1. 触发超限 Skill。
2. 查看执行记录与用户提示。

**预期**:
- 明确显示超限原因；
- 不悄悄少发文件；
- 已生成文件可按策略保留或清理，状态一致。

**负责人**: 后端

---

## B-04 跨租户/无权限访问

**目标**: 其它租户或无权限用户不能查看/下载/交付产物。

**前置**:
- 两个租户/两个用户，各有一个文件产物。

**步骤**:
1. 用户 A 打开任务/执行记录。
2. 尝试使用用户 B 的产物引用/链接。
3. 查看结果。

**预期**:
- 只看到自己的产物；
- 跨租户/越权请求显式失败；
- 不泄露文件名、大小、校验值或状态。

**负责人**: 后端

---

## B-05 同一文件多个目标

**目标**: 同一 artifact 发往不同目标时，每个目标独立一次，互不误判。

**前置**:
- 同一执行配置两个不同目标（如 WebChat + 外部通道）。

**步骤**:
1. 触发文件交付。
2. 分别查看两个目标。
3. 重复触发一次。

**预期**:
- 每个目标各收到一份；
- 重复触发不再新增；
- 一个目标失败不影响另一个目标；
- 状态按目标分别可见。

**负责人**: 后端

---

## B-06 追加版本：新版本独立投递，旧链接不变

**目标**: 同一逻辑文件追加新版本后，新版本按新身份投递，旧链接仍下载旧内容。

**前置**:
- 一个已产生文件并已交付的任务，可对同一路径再次写入；
- 已保存上一次的取件链接（或已发出的文件）。

**步骤**:
1. 对同一路径写入内容 B，形成新版本。
2. 用旧取件链接/旧消息里的文件下载。
3. 触发新版本的交付。
4. 查看执行记录与通道。

**预期**:
- 旧链接下载到的仍是旧内容，checksum 与发布时一致；
- 新版本有独立的产物身份与交付记录，可以再次投递；
- 旧版本不会被重发，也不会被新内容顶替。

**负责人**: 后端

---

## B-07 并发重复登记

**目标**: 同一逻辑文件的并发写入不会产生两份“当前版本”。

**前置**:
- 可对同一路径并发触发两次写入（同一执行）。

**步骤**:
1. 同一执行内并发写入同路径。
2. 查看产物列表与版本号。
3. 查看任务产物下载。

**预期**:
- 版本号连续且唯一，没有两个同版本号的行；
- 冲突的一方得到显式冲突结果，不静默覆盖；
- 下载按版本+checksum 定位，不返回“最新版”冒充。

**负责人**: 后端
