# 平台统一文件产物投递 人工验收场景

> **文档版本**: v2.0
> **创建日期**: 2026-11-17
> **需求**: `unified-artifact-delivery.prd.md` v2.0
> **设计**: `unified-artifact-delivery.backend.design.md` v2.0 / `unified-artifact-delivery.frontend.design.md` v2.0

**使用约定**:

- 场景是人工验收资产，不是自动化清单；不记录 selector、内部 API 路径或实现细节。
- 每个场景写清目标、前置、人工步骤、可观察结果和负责人。
- 真实边界：真实构建产物、真实 PostgreSQL/Redis、真实 Runtime/Worker/Gateway；企微使用现有测试探针。
- 未满足环境时记录缺失项与 owner，不把环境缺失伪装成产品失败。
- **Pull / Push 前提**：WebChat/MSSWWEB 是 Web pull；只有企微是 push。没有绑定/入口时，不产生对应表面，不报错。

## S-01 WebChat 直接对话：附件只在 Web

**目标**: WebChat 直接对话的附件出现在会话历史，不推送企微。

**前置**:
- WebChat 入口已登录，Agent 授权正常；
- 平台文件工具/一个会写 `SKILL_OUTPUT_DIR` 的同步 Skill 可用；
- 同一用户-Agent 已绑定企微（用于验证“不推送”）。

**步骤**:
1. 在 WebChat 对话中触发 Skill，生成 1 个文本文件。
2. 等待 Run 完成。
3. 查看会话历史与附件下载。
4. 刷新页面后再次查看。
5. 查看企微测试探针。

**预期**:
- Web 历史出现一条助手消息，带附件，可下载且 checksum 正确；
- 刷新后仍只有一份；
- 企微没有收到附件/消息；
- 不出现独立投递管理页。

**负责人**: 后端 + 前端

---

## S-02 企微直接对话：附件只在企微

**目标**: 企微直接对话的附件只推送到来源企微会话，不进入 Web 历史/任务中心。

**前置**:
- 企微入口与测试探针可用；
- 同一用户-Agent 有 WebChat 入口（用于验证“不进入 Web”）。

**步骤**:
1. 在企微对话中触发一个生成文件的 Skill。
2. 等待完成。
3. 查看企微探针。
4. 登录 WebChat，查看会话历史与任务中心。

**预期**:
- 企微收到结果与附件；
- WebChat 历史/任务中心没有该直接对话的附件；
- 没有重复发送。

**负责人**: 后端 + 通道适配器

## S-03 企微创建定时任务：企微 push + Web pull

**目标**: 企微创建的定时任务完成后，企微收到结果和附件，Web 任务中心也能看到任务结果和附件。

**前置**:
- 同一用户-Agent 同时有企微绑定与 WebChat 入口；
- 定时 SKILL 会写 `SKILL_OUTPUT_DIR`；
- Schedule 的投递目标为企微。

**步骤**:
1. 在企微创建定时任务，配置企微投递。
2. 等待一次触发完成。
3. 查看企微探针。
4. 登录 WebChat → 任务中心 → 任务详情/执行记录。
5. 刷新 Web 任务中心。

**预期**:
- 企微收到任务结果 + 附件；
- Web 任务中心显示同一任务结果 + 附件；
- Web 任务详情显示“企微已推送”；
- 刷新后不重复、不丢附件。

**负责人**: 后端 + 前端

## S-04 WebChat 创建定时任务：选择企微 push

**目标**: WebChat 创建的定时任务可以选择企微目标；完成后 Web 任务中心可看，企微也收到。

**前置**:
- 同一用户-Agent 有 WebChat 入口与企微绑定；
- Schedule 创建表单可读取当前用户-Agent 的可用企微目标。

**步骤**:
1. 在 WebChat 创建定时任务。
2. 在投递目标中选择企微（而不是“仅 Web”）。
3. 等待一次触发完成。
4. 查看 Web 任务中心。
5. 查看企微探针。

**预期**:
- Web 任务中心显示任务结果 + 附件；
- 企微收到任务结果 + 附件；
- 任务详情显示“企微已推送”；
- 选择“仅 Web”时，企微不收到，Web 仍可看。

**负责人**: 后端 + 前端

## S-05 MSSWWEB：同一 Web 数据的另一个入口

**目标**: MSSWWEB 作为 Web pull 入口，复用 WebChat 的会话/任务/文件/产物，不产生第二套投递。

**前置**:
- MSSWWEB 入口已接入（未来入口；本场景可在测试环境用等价 Web surface）；
- 同一用户-Agent 有 WebChat 数据。

**步骤**:
1. 在 WebChat 生成一个直接对话附件。
2. 在 MSSWWEB 查看同一用户-Agent 的会话/文件。
3. 在 WebChat 创建一个定时任务（仅 Web）。
4. 在 MSSWWEB 查看任务中心。
5. 检查企微探针。

**预期**:
- 两个 Web 入口看到同一份会话/任务/文件/产物；
- 不出现重复附件卡/重复任务；
- 没有 MSSWWEB 专用投递意图/泵；
- 企微不收到仅 Web 的任务。

**负责人**: 后端 + 前端

## S-06 无企微绑定：只 Web，不报错

**目标**: 用户没有企微绑定时，任务/对话正常，不产生 push，也不显示失败。

**前置**:
- 用户只有 WebChat 入口，没有企微绑定；
- 一个会生成附件的任务/对话。

**步骤**:
1. 在 WebChat 触发任务/对话。
2. 查看 Web 历史/任务中心。
3. 查看 Schedule 详情/任务详情。

**预期**:
- Web 正常显示结果与附件；
- 没有 push 记录；
- 不显示“推送失败”，显示“仅 Web 可查看/未配置企微推送”；
- 不产生 outbox/message_delivery 失败。

**负责人**: 后端 + 前端

## S-07 无 Web 入口：只企微 push

**目标**: 用户没有 Web 入口时，企微仍能收到任务/对话结果与附件。

**前置**:
- 用户只有企微绑定，没有 WebChat/MSSWWEB 入口；
- 企微定时任务/直接对话可用。

**步骤**:
1. 在企微触发一个生成附件的任务/对话。
2. 查看企微探针。
3. 尝试访问 Web 任务中心（应无该用户入口）。

**预期**:
- 企微收到结果与附件；
- 不产生 Web pull 投影；
- 不因为“没有 Web 入口”而失败。

**负责人**: 后端

---

## S-08 多文件：一条消息多个附件

**目标**: 一次执行多个文件时，Web 与企微都把它们作为一条消息的多个附件，而不是多条独立消息。

**前置**:
- Skill 输出 2–5 个文件；
- 同一用户-Agent 有 Web 与企微。

**步骤**:
1. 在 WebChat 创建一个带企微 push 的定时任务，输出多个文件。
2. 等待完成。
3. 查看 Web 任务中心附件列表。
4. 查看企微探针消息。

**预期**:
- Web 一条任务结果下显示多个附件，顺序保留；
- 企微一条结果消息包含多个附件（或通道能力允许的批量发送）；
- 不出现每个文件一条独立任务结果；
- 失败/降级时消息级状态清晰。

**负责人**: 后端 + 前端

## S-09 显式再发一次

**目标**: 用户要求“再发一次”时，允许产生新的消息/附件可见，不破坏自动重试去重。

**前置**:
- 一个已交付的附件；
- 可再次触发 `deliver_artifact` 的入口。

**步骤**:
1. 用户要求把之前的附件再发一次。
2. 查看 Web 历史/企微。
3. 检查自动重试/刷新是否产生额外重复。

**预期**:
- 显式重发生成新的消息/附件条目；
- Web/企微各收到一次新的发送；
- 自动重试仍复用原 message key，不因刷新/重连重复；
- 旧消息/旧附件不受影响。

**负责人**: 后端

---

## S-10 发送结果未知：待核实，不自动重发

**目标**: 企微发送超时/无回执时，不自动重发，任务中心显示待核实。

**前置**:
- 企微探针可注入“连接保持但不返回结果/超时”；
- 一个已完成、有附件的任务。

**步骤**:
1. 注入发送无回执。
2. 触发任务附件推送。
3. 查看任务中心状态。
4. 等待超过退避窗口，再次查看企微探针与任务中心。

**预期**:
- 任务中心显示“企微待核实”（UNKNOWN），不是已推送/失败可重试；
- 平台不自动重发；
- 核实后可显式处置，处置结果被记录。

**负责人**: 后端 + 通道适配器

## E-01 同一条消息重试/重放：不重复

**目标**: 自动重试、刷新、崩溃恢复不产生第二条用户可见消息。

**前置**:
- 可注入一次失败后恢复的企微通道；
- 同一任务/对话。

**步骤**:
1. 触发附件推送。
2. 注入首次失败，等待平台重试。
3. 刷新 Web 任务中心/企微探针。
4. 重启 Runtime/Worker 后再查看。

**预期**:
- 企微只出现一条/一批最终消息；
- Web 任务中心只有一条消息状态；
- 重试/恢复复用同一 message key。

**负责人**: 后端

## E-02 渠道降级：取件链接

**目标**: 企微不能直发文件时，降级为取件链接，不谎报直发成功。

**前置**:
- 企微测试通道可注入大小/类型不支持；
- 一个已生成附件。

**步骤**:
1. 触发企微推送。
2. 查看企微消息与取件链接。
3. 查看任务中心状态。
4. 打开链接下载。

**预期**:
- 企微收到取件链接；
- 任务中心显示 `DEGRADED` 与链接；
- 链接内容/checksum 与附件版本一致；
- 不标记为 `DELIVERED` 直发。

**负责人**: 后端 + 通道适配器

## E-03 企微路由撤销：失败但不影响 Web

**目标**: 企微路由被撤销/删除时，push 失败，Web 任务中心仍然可读。

**前置**:
- 一个配置了企微 push 的定时任务；
- 可在任务完成后撤销路由。

**步骤**:
1. 撤销企微路由。
2. 触发定时任务。
3. 查看 Web 任务中心与 Schedule 状态。
4. 查看企微探针。

**预期**:
- Web 任务中心仍显示任务结果与附件；
- push 显示 `FAILED`/路由不可用；
- 来源 Schedule 进入 `NEEDS_ATTENTION`，不无限重试；
- 不猜替代会话。

**负责人**: 后端

## E-04 失败/取消：不挂半成品

**目标**: 失败或取消的执行不会把 partial 输出挂到结果消息。

**前置**:
- 可注入 Skill 失败/取消，且已写部分输出；
- Web 与企微都有入口。

**步骤**:
1. 触发会失败/取消并写部分输出的 Skill/任务。
2. 查看 Web 历史/任务中心。
3. 查看企微探针。

**预期**:
- 用户没有收到半成品附件；
- 任务状态为失败/取消；
- partial 文件可保留诊断，但不显示“已交付”；
- 不产生 push 消息。

**负责人**: 后端

## E-05 输出目录超限：显式失败

**目标**: 输出文件数量/大小超限时显式可见，不静默少发。

**前置**:
- 可构造超出文件数/单文件大小的输出。

**步骤**:
1. 触发超限 Skill。
2. 查看任务/执行记录。
3. 查看 Web/企微。

**预期**:
- 明确显示超限原因；
- 不悄悄少发附件；
- 任务状态/附件状态一致，不显示“全部成功”。

**负责人**: 后端

## E-06 附件保留：pending push 不被清理

**目标**: 消息已入 push 队列但尚未发送时，附件不会被保留期清理。

**前置**:
- 可注入企微通道长时间不可用；
- 可配置较短的附件保留期。

**步骤**:
1. 触发一个带附件的企微任务，使 push 停在 PENDING。
2. 等待超过普通保留期。
3. 恢复通道，等待发送。
4. 下载附件。

**预期**:
- pending 消息引用的附件仍可发送；
- 发送成功后可下载/取件；
- 不出现“消息在、文件没了”的死链。

**负责人**: 后端 + 运维

## E-07 `execute` 漏 `target`：可行动错误

**目标**: 模型漏传 `target` 时返回明确字段错误，不执行 Skill。

**前置**:
- 调试/测试环境可控制工具调用。

**步骤**:
1. 调用 `execute` 不带 `target`。
2. 查看工具结果。
3. 用 `execute_skill` 或 `execute(target=skill)` 正确调用。

**预期**:
- 错误明确指出缺少 `target`；
- 不执行任何 Skill；
- 正确调用成功。

**负责人**: 后端

## E-08 `WORKSPACE_ROOT` 相对路径：启动归一/失败清晰

**目标**: 本地相对 `WORKSPACE_ROOT` 不再导致沙箱模糊错误。

**前置**:
- 本地 `.env` 使用相对 `WORKSPACE_ROOT`。

**步骤**:
1. 启动 Runtime/Worker。
2. 执行 `target=workspace` 的 `pwd`。
3. 写测试文件。
4. 查看启动日志。

**预期**:
- 相对路径归一为绝对路径（或启动明确失败并说明原因）；
- `pwd`/写文件成功；
- Runtime/Worker 使用同一 resolved root；
- 生产绝对路径行为不变。

**负责人**: 后端 + 运维

## E-09 `MEDIA:` 兼容（若实现）

**目标**: 最终助手文本的独立 `MEDIA:` 行可生成附件；非独立行/代码块/工具 stdout 不生效。

**前置**:
- 已启用 `MEDIA:` 兼容解析；
- 一个可控的助手最终文本。

**步骤**:
1. 让助手最终文本包含独立 `MEDIA:<workspace 文件>`。
2. 让同一文本包含代码块/行内 `MEDIA:`。
3. 让工具 stdout 包含 `MEDIA:`。
4. 查看 Web/企微附件。

**预期**:
- 仅独立行生成附件；
- 代码块/行内/tool stdout 保持文本，不生成附件；
- 无效路径显示可见失败说明；
- 与 `SKILL_OUTPUT_DIR` 同文件去重。

**负责人**: 后端

## B-01 版本追加：旧消息/旧链接不变

**目标**: 同一逻辑文件追加新版本时，旧消息/旧链接仍指向旧内容，新版本按新身份投递。

**前置**:
- 一个已交付的附件；
- 可对同一路径再次写入。

**步骤**:
1. 对同一路径写入内容 B，形成新版本。
2. 用旧消息/旧链接下载。
3. 触发新版本的交付。
4. 查看 Web/企微。

**预期**:
- 旧链接下载旧内容，checksum 不变；
- 新版本有独立 `artifact_id`，可再次投递；
- 旧版本不重发，也不被新内容顶替。

**负责人**: 后端

---

## B-02 跨租户/无权限

**目标**: 其它租户或无权限用户不能查看/下载/推送附件。

**前置**:
- 两个租户/用户，各有一个附件。

**步骤**:
1. 用户 A 打开任务/历史。
2. 尝试使用用户 B 的附件引用/链接。
3. 查看结果。

**预期**:
- 只看到自己的附件；
- 跨租户/越权显式失败；
- 不泄露文件名、大小、checksum 或 push 状态。

**负责人**: 后端

---

## B-03 JOIN 子任务：由父任务聚合

**目标**: 任务内部 JOIN 子任务的附件不直接发给用户，由父任务结果聚合。

**前置**:
- 一个 Agentic/任务内部 JOIN 场景，子 Skill 生成附件。

**步骤**:
1. 触发父任务，内部 JOIN 子 Skill。
2. 查看子任务/父任务详情。
3. 查看 Web/企微。

**预期**:
- 子任务不单独产生用户可见 push；
- 父任务结果包含子附件（或父任务明确聚合）；
- 任务中心聚合展示，不重复。

**负责人**: 后端
