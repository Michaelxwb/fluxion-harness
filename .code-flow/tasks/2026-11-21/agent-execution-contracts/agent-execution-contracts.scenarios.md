# Agent 执行契约统一 验收场景

> 这是给**人工测试者**使用的验收清单，不是 E2E 代码或测试注册表。
> 每个场景保留 S-/E-/B- 编号，供 design 和 Task 的 `Scenarios` 字段引用。
> 步骤用测试者可执行的界面动作、CLI/API 请求或测试夹具描述；期望写可观察结果，避免内部函数名与断言细节。

## S-01 MCP 返回 JSON 数组仍按数据处理

- **负责**：待 TASK 分配
- **前置**：
  - 已准备一个测试 MCP server，工具返回文本内容 `[1,2,3]`
  - Agent 已绑定该 MCP server，Run 可正常受理
- **步骤**：
  1. 在对话中让 Agent 调用该 MCP 工具并“把返回的数据原样告诉我”。
  2. 等待 Run 结束，查看最终回复。
  3. 打开 Run 详情，查看工具调用事件与错误信息。
- **期望**：
  - 最终回复包含 `1,2,3`，不是错误提示。
  - Run 状态不是因 `AttributeError`/`tool failed` 失败。
  - 工具事件没有把成功结果标成失败。
- **实际结果**：待执行

## S-02 长任务保留原始目标与已加载 Skill 说明

- **负责**：待 TASK 分配

  3. 等待 Run 结束，查看最终回复与 Run 详情里的压缩事件。

  - 压缩事件中 micro 真的触发了，且历史里能看到被降级的工具结果占位符。
  - 没有出现“忘记原始要求”或“未按 SKILL.md 执行”的表现。

## S-06 提交后、回合收口前崩溃仍按 prepared 事实恢复

- **负责**：待 TASK 分配
- **前置**：
  - 已准备一个 ASYNC Skill 或异步 MCP 操作，提交后会等待外部结果
  - 模型调用省略 `argv`（或由测试 Hook 修改参数），验证恢复不重放原始参数
  - 具备故障注入能力：在“operation 已登记、回合结果尚未收口”时停止 Worker
- **步骤**：
  1. 触发一次异步调用。
  2. 在 operation 已登记、回合尚未收口时停止执行进程。
  3. 重新启动 Worker/恢复执行，等待结果返回。
  4. 查看 prepared 事件、Task 执行详情、操作记录与最终回复。
- **期望**：
  - operation 行中的参数是归一化/Hook 后的最终值（例如 `argv: []`），prepared 的 `args_hash` 与 operation `input_hash` 一致。
  - 恢复按 operation 参数找回同一 operation，不出现 `TOOL_OPERATION_INPUT_MISMATCH`。
  - 若子 Task 尚未创建，恢复幂等补齐；不会等待一个没人执行的操作。
  - 恢复后只存在一个业务操作，没有重复提交；历史中每个工具声明都有对应结果。
- **实际结果**：待执行

## 场景编写约定

- 一个场景只验证一个用户可理解的目标。
- 步骤按真实操作顺序编号；期望写可观察结果，不写内部函数名或测试断言。
- 场景不生成 manifest、不登记执行结果、不阻断 `task finish` 或 `task archive`。
- 需要机器执行的快速回归放在 Task 的 `### Tests`；浏览器 E2E 按 `scenarios.md` 由人工在真实构建产物、真实浏览器和真实服务上执行并记录，不进 CI；全量 pytest/acceptance/component 由 CI 独立执行。
