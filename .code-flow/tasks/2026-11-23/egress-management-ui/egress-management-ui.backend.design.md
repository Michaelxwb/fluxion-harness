# 系统设置回滚范围设计

> v0.1 · 2026-11-23 · 待评审 · FEAT-04

## 服务端契约

继续使用现有管理员回滚接口、幂等机制和 `RESTORE` 审计。系统设置分组的恢复范围由 Console 服务端决定，所以旧客户端或直接调用同一接口也适用。

1. 按当前租户读目标历史版本和最新设置版本。最新记录同时提供当前版本号和当前配置基准。
2. 从目标历史文档恢复系统设置，出站分组取当前基准的 `egress` 完整配置，包含总开关及全部规则。基准缺少出站分组时按现有 schema 默认处理。历史出站字段先替换，再解析和校验合成的文档。
3. 保留现行设置校验和内存配额保护。出站平台引用的业务校验继续由出站规则保存入口执行，回滚仅原样带入当前配置。
4. 继续用 append-only 方式插入新版本并写入同事务审计。版本冲突沿用现有租户版本唯一约束。并发修改先写入时，回滚要么读取到新版本并保留其出站配置，要么报告并发冲突，由管理员重新发起。成功回滚的前后审计快照都应包含相同的当前出站配置。

规则保存继续走现有统一设置写接口。发布时沿用现有存储结构、运行时读取路径和限流计量。已存在的历史记录原样保留，出站管理界面展示当前规则。

## 验证

- PostgreSQL 集成回归覆盖拆分前目标版本包含不同规则、历史目标缺少出站分组、现行配置并发变更以及历史行保留。使用 `tests/console_platform/test_platform_settings_service.py` 和 `tests/console_platform/test_platform_settings_api.py`。
- 人工场景 B-02 使用有两个已知历史版本的测试租户，验证非出站设置被恢复，同时对比回滚前后的出站开关及规则。

## 部署

构建独立的本机 Console 镜像，更新实际 Console 镜像上的前端产物和 Console 回滚实现。仅重建 Console 容器，必要时刷新 Web 代理的上游连接。核对 Console 与 Web 就绪，以及当前 Runtime、数据库、Redis 容器身份。保留部署前 Console 镜像供发布回退，数据库结构和已有记录照常使用。
