# PRD：出站管理独立入口

> v0.2 · 2026-11-23 · 待评审

v0.2 按用户澄清明确系统设置回滚与出站规则的边界。

## 1. 背景与目标

当前出站监控位于「概览」，规则编辑位于「系统设置」。为让配置、触发验证和查看拦截结果处在同一操作入口，将这两个现有页面收拢到一级导航「出站管理」。

## 2. 用户与场景

- **US-01** · 具备现有监控查看权限的操作者，从统一入口查看出站请求和拦截情况。
- **US-02** · 管理员从同一入口核对、编辑并保存租户出站规则，然后切回监控验证结果。

## 3. 功能需求

- **FEAT-01 · 入口与导航**。新增左侧一级入口「出站管理」，内有「出站监控」和「出站规则」两个页签，默认进入监控。系统设置移除出站规则分组。概览可保留通往监控的快捷入口，现有监控链接可打开新入口。
- **FEAT-02 · 监控展示**。复用现有统计、时间范围、刷新、排行和异常状态。继承当前查看权限和租户隔离。
- **FEAT-03 · 规则编辑与保存**。复用租户开关、规则字段、增删改、校验、保存和生效说明。规则页仅由管理员访问。保存使用现有设置版本校验，以规则页加载时的版本为基准，保留其他设置并提示并发冲突。切换页面时应避免静默丢掉未保存的规则。
- **FEAT-04 · 全局回滚**。「系统设置」保留现有版本历史和回滚入口。回滚恢复选中版本的其他设置，保留当时已生效的出站总开关与全部规则。出站管理页提供当前规则的查看、编辑和保存。历史版本按原样保留，本次无需迁移或补建出站规则历史。

## 4. 验收

- 从新入口切换两页签，现有监控链接正常打开监控，并核对相同时间范围的统计值。
- 现有普通查看角色仍可看监控，直接访问规则页也无法编辑。管理员从新页面编辑并保存一条规则，刷新后可见。
- 验证规则保存前后的其他系统设置相同。另一管理员先行保存时，新页面提示版本冲突。从系统设置回滚到一个出站配置不同的历史版本，核对其他设置已恢复，当前出站总开关和规则仍然保留。历史记录可继续从系统设置查看。
- 前端构建并部署到当前本机 Docker。使用已部署 Runtime 进行验证，保持当前数据卷、规则和运行环境。界面调整基于独立工作区，与待审的限流提示 PR 分开。

## 5. 范围与约束

本次调整 Console 前端导航、页面和现有保存交互，并收窄 Console 后端设置回滚的数据范围。沿用原有设置和监控 API、权限与版本校验。出站准入、限流计量、监控指标算法、数据结构和规则生效沿用当前实现。Docker 更新范围为 Console。

按 `test/harness-test#RULE-test-001` 提供定向回归，并用真实构建的本地控制台验收导航、权限和保存行为。
