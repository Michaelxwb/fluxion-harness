# Skill 执行结果与对话收尾验收场景

人工验收使用实际构建、真实浏览器和本地验收环境。S-01 使用真实审查 Skill、真实草稿与实际 Agent。需要故障的场景由测试维护者准备可重复触发的环境和测试服务。每次验收记录实际环境、操作者、可见结果、关联 Run/Task 和可分享的报告，分别说明真实业务数据与受控测试数据。

## S-01 有 findings 时修订并重审

- **负责**：Skill 作者，运行维护者协助检查。
- **前置**：在测试租户准备一个真实草稿，带有一项易修复的 error 级问题。当前 Agent 已绑定这组版本的创建、审查和上传 Skill。
- **步骤**
  1. 在 WebChat 请 Agent 通过草稿创建流程继续处理该草稿，审查、修复可确定的问题并重审。
  2. 阅读聊天结论和报告，在运行审计中展开两次审查。
  3. 刷新会话，打开草稿及有权限的报告，核对修订位置。
- **期望**：初审报告可读且显示执行完成、审查未通过，详情保留退出码 1。Agent 根据报告修订同一草稿且实际再次审查。重审通过显示退出码 0，仍有 findings 时如实列出。刷新后回复、报告与草稿版本一致。只有创建及修订请求时，草稿尚未提交审批。
- **部分实测**：2026-11-24，通过本机 Chrome 在 Docker WebChat 向测试 Agent 发消息。`local-review-final` 初审 revision 2，持久审计为 `COMPLETED / REVIEW_FINDINGS / 1`。Agent 补齐 `muad.skill.json` 后重审 revision 3，审计为 `COMPLETED / REVIEW_PASSED / 0`，草稿未提交审批。Run `94957274-2204-4fab-8a65-20a853cc3d51` 最终为 `COMPLETED`。浏览器已核对回复，刷新后报告与 Console 逐项展示待验。

## S-02 客户无设备

- **负责**：对话验收人。
- **前置**：授权测试账号可查询一个已确认无设备的客户，查询服务与结果格式已准备。
- **步骤**
  1. 在同一会话查询该测试客户的设备。
  2. 阅读回复，打开该次调用详情。
- **期望**：用户看到已经成功查询、当前范围没有设备。调用已完成，业务结论为无设备。回复不把零设备解释成技术调用失败。

## S-03 多客户待选择后续接

- **负责**：对话验收人。
- **前置**：测试查询会返回多个同名且当前可见的客户。
- **步骤**
  1. 在 WebChat 按简称查询设备，等 Agent 返回候选。
  2. 刷新页面，确认问题仍在。回答选择其中一个客户。
  3. 查看回复和运行记录，对照选择前后的查询范围。
- **期望**：Agent 发出一个明确问题。选定前未查询任一候选客户的设备。选定后只查询选中的授权客户。答复在原会话继续，已回答问题不会同时出现两次。

## S-04 真实工具错误后安全恢复

- **负责**：对话验收人和测试维护者。
- **前置**：受控 Skill 组合可先取得有效结果，再出现一次不可照原参数重试的执行错误。另有已授权替代查询。
- **步骤**
  1. 通过聊天发起需要两部分结果的查询。
  2. 检查回复、运行事件和测试服务请求记录。
- **期望**：实际失败保留原因，已有结果仍可用。Agent 可走替代查询并如实给出结果。失败的原调用未以原参数重做。

## S-05 同步与后台结果语义一致

- **负责**：运行维护者。
- **前置**：测试租户可以同步调用审查。维护者已准备只读目标及获授权的后台提交入口。两次使用同一审查器版本，目标版本内容一致。
- **步骤**
  1. 分别发起同步审查和后台审查，等待报告。
  2. 在 Console Run、Task 详情和对应任务中心查看结果。
  3. 用有权限的账户打开报告，核对退出码及审查结论。
- **期望**：已完成审查在各处有同样的业务结论，保留实际退出码及各次报告。Task 执行完成可以与审查未通过同时成立。任务投递状态按各自真实情况展示。

## E-01 崩溃、错误报告或过期报告

- **负责**：测试维护者和运行维护者。
- **前置**：准备受控包及审查目标，可触发目录不可读、进程崩溃、退出 1 但报告缺失或损坏、输出被截断，以及报告属于旧目标的情形。
- **步骤**
  1. 逐个触发失败，至少分别检查同步和后台记录。
  2. 查看聊天、调用详情及附带的部分产物。
- **期望**：记录实际执行失败、有证据的退出码与可分享的原因。缺失或不匹配报告不显示为审查完成。能访问的部分成果保留，并可看出受影响范围。

## E-02 任务无法继续后在原会话接着聊

- **负责**：对话验收人。
- **前置**：可先生成一份能交付的部分结果，再触发无法用现有权限或替代查询解决的真实错误。另准备一个模型不可用的受控对照。
- **步骤**
  1. 在 WebChat 发出请求并阅读最终回复，检查已提供的附件。
  2. 展开技术详情，刷新后再次检查正文、附件和详情。
  3. 在同一会话追问已取得部分的内容。对照分支在模型恢复后再追问。
- **期望**：回复说明已做什么、卡在哪里与可行的下一步。技术码及 Run ID 可在详情查到。原有有效正文和附件仍在，刷新无重复。追问在原会话受理。模型不可用时，兜底只说明已记录的事实。

## E-03 权限拒绝与硬停止

- **负责**：运行维护者。
- **前置**：准备独立的权限拒绝、用户主动取消、预算用尽、总期限到期和单次工具超时对照。
- **步骤**
  1. 逐个触发条件，在适用的用例点击停止。
  2. 查看聊天、状态和测试服务调用记录。
- **期望**：权限拒绝后没有绕过授权的请求，可以解释缺少的权限。取消、预算或总期限阻止后续执行。单次工具超时记录真实原因，后续动作受安全判定、预算和期限约束。已交付的有效结果仍可见。

## B-01 外部效果未知且不可安全重试

- **负责**：测试维护者。
- **前置**：隔离测试服务能记录一次可计数操作，执行后可模拟回包不可达，准备多个可能触及同一资源的调用入口。
- **步骤**
  1. 触发操作并让回包丢失，要求 Agent 尝试恢复，提示有同义入口。
  2. 在服务恢复后查看调用详情及测试服务的变更历史。
  3. 在同一会话继续询问状态，再核对操作次数。
- **期望**：Agent 可解释结果未知或通过授权的独立检查确认。改变入口或参数不会绕过边界。未完成可信核实前，操作次数未增加。

## B-02 重复失败或 findings 无改善

- **负责**：Skill 作者和测试维护者。
- **前置**：准备产生同一错误的工具，以及可反复产生同类 findings 且没有实际改善的测试草稿。
- **步骤**
  1. 分别发起查询恢复及反复修订重审请求。
  2. 在其中一次穿插无关诊断请求，查看执行记录和最后一条答复。
- **期望**：第一次失败或 findings 后 Agent 能获取事实并评估下一步。同类问题持续无改善后停止派发。无关诊断、换入口和同一报告未重置保护。最终回复说明仍未解决的问题。

## B-03 提问后取消或过期

- **负责**：对话验收人。
- **前置**：准备可以触发客户选择的测试数据，测试人员可以在两次执行中分别取消及等待有效期结束。
- **步骤**
  1. 触发选择问题，分别取消和等待到期。
  2. 刷新后尝试回答旧问题，再发起下一条新查询。
- **期望**：旧问题显示已结束，原执行不会因迟到答复恢复。新查询仍可提交。原等待期间没有替用户选客户。

## B-04 中断、恢复和重复交付

- **负责**：运行维护者。
- **前置**：隔离环境可在后台结果入库后暂停消费，再重启消费进程并重放同一通知。另备一个结果不明确的有副作用操作。
- **步骤**
  1. 启动后台审查，在结果已经可于 Task 详情读取、聊天尚待处理时暂停消费并断开浏览器连接。
  2. 恢复服务，重放同一通知，并打开原会话与详情。
  3. 以中断发生在状态未知时再做一次对照，核对隔离服务的操作次数。
- **期望**：已提交结果恢复后仍显示原审查结论、报告和退出码。后台通知和答复各显示一次。已有派发记录且结果未知时不会重做，能够从会话查看安全的后续说明。

## B-05 窗口限流且存在部分结果

- **负责**：对话验收人和测试维护者。
- **前置**：使用隔离平台查询服务，准备可触发的窗口规则和可独立复现的故障。
- **步骤**
  1. 发起能取得部分结果后触发限流的查询，核对测试服务请求。
  2. 再运行一轮同时存在独立故障的用例，查看说明和已有结果。
- **期望**：窗口超限请求未发到测试平台，已得到的有效部分及原正文保留。本轮仅因限流结束时文案说明查询受限。并存独立故障时反映真实障碍。

## B-06 上传前保持报告与草稿版本一致

- **负责**：Skill 作者和测试维护者。
- **前置**：可使用自建 Skill 三件套。准备一份结构合法的测试草稿，以及能使审查无法完成的受控对照。测试维护者可在上传流程审查完成后，通过另一会话修改草稿。
- **步骤**
  1. 在 WebChat 明确要求上传测试草稿。审查出具报告后修改草稿，使继续提交时发生版本冲突。
  2. 查看冲突后的审查结果。先保持未确认状态，再在完成必要的风险说明后明确答复。
  3. 对另一份结构合法的草稿发起上传，使用受控条件让审查本身执行失败。分别查看聊天及审批列表。
- **期望**：旧报告不能用于新版本。Agent 对当前版本重新做规范审查和平台结构校验。有效报告仍有 error 时，先说明风险并等待用户确认。提交完成后只产生当前版本的待审批记录。审查本身无法完成时给出原因，审批列表无新增记录。
