## 2. 背景与目标

### 2.1 问题陈述

| 维度 | 内容 |
|------|------|
| **问题描述** | `runtime.canonical_event` 是唯一无上限增长的表，承载全部会话事件（用户消息、助手回合、工具调用、增量、摘要等）。当前保留机制只做软删（`is_deleted=true`），没有任何物理删除路径：开发库 123,196 行中 122,451 行已软删，而表占用 368 MB（其中索引 341 MB、堆 26 MB、payload 1.6 MB）。行与索引只增不减，长期会拖慢查询、扩大备份、增加 autovacuum 压力。 |
| **当前替代方案** | `cleanup-artifacts` 只能清理产物行与文件，且没有自动调度；Runtime 的保留循环（`run_retention_sweep`）只做软删；平台没有"删除过期会话"的产品入口。运维只能手工连库删除，既无守卫也无对账。 |
| **触发原因** | 需要把"6 个月前无业务价值的会话数据"从 DB 中真正清出去，保持数据库规模与索引健康；同时保留"过期会话对用户不可见"的既有产品语义。 |

### 2.2 目标与价值

| 维度 | 内容 |
|------|------|
| **核心目标** | 提供一次可由管理员在 Console 触发、由后台执行、可续跑、可对账的过期会话清理：按会话维度删除超过保留期的全部关联数据，结束后统一做一次 VACUUM 与索引重建。 |
| **预期价值** | 控制事件表与索引的无限增长，回收磁盘与内存页，降低备份与查询成本；把不可逆删除变成有预览、有守卫、有审计的标准操作，替代手工连库。 |

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 过期会话能否被完整清除 | 无入口 | 单次任务按批清理全部候选会话，会话行不再存在 | 任务报告 + 清理后计数 |
| 清理对在线请求的影响 | 不适用 | 在线 P99 无可观测劣化；无锁等待超时事件 | 运行指标与锁等待监控 |
| 任务可续跑 | 不适用 | 进程中断后从断点继续，不重复删除、不漏删 | 中断演练 + 报告 |
| 索引空间回收 | 开发库索引 341 MB | 重建后与活数据规模匹配 | 任务报告中每个索引前后大小 |

## 3. 用户与场景

### 3.1 目标用户

| 维度 | 内容 |
|------|------|
| **用户画像** | Console 管理员（ADMIN）与平台运维；间接受影响的终端用户（WebChat / IM 会话的拥有者）。 |
| **使用场景** | 管理员在系统设置页看到"可清理会话数"，在业务低峰触发一次清理；清理期间可查看进度，可取消，失败后再次触发续跑；终端用户不再能看到超过保留期的会话（与现有 `CONVERSATION_EXPIRED` 语义一致）。 |

### 3.2 用户故事

| 编号 | 用户故事 | 优先级 |
|------|---------|--------|
| US-01 | 作为 Console 管理员，我希望在设置页看到保留期与当前可清理的会话数量，并能触发一次清理，以便用标准操作回收过期数据。 | P0 |
| US-02 | 作为 Console 管理员，我希望触发前先看到预览（会话数、行数、估算字节），并能看到执行进度与最终报告，以便确认删除范围和结果。 | P0 |
| US-03 | 作为 Console 管理员，我希望清理任务可以取消，并在失败或中断后从断点续跑，以便不因一次失败重头再来。 | P0 |
| US-04 | 作为平台运维，我希望清理分批执行且不长时间持锁，重建索引单独按序进行，以便清理不影响在线会话。 | P0 |
| US-05 | 作为终端用户，我希望超过保留期的会话不再出现在历史列表中，也不能继续对话，以便行为与现有保留期语义一致。 | P1 |
| US-06 | 作为审计/运维，我希望每次清理的触发人、范围、删除量、索引重建结果都有记录，以便事后追溯。 | P0 |

## 4. 功能需求

### 4.1 功能清单

| 功能ID | 功能名称 | 功能描述 | 优先级 | 来源用户故事 |
|--------|---------|---------|--------|-------------|
| FEAT-01 | 保留期设置 | 会话保留期可配置（默认 180 天），到期后不可见并进入可清理范围 | P0 | US-01、US-05 |
| FEAT-02 | 清理预览 | 返回当前租户可清理的会话数、行数与估算字节，不删除任何数据 | P0 | US-02 |
| FEAT-03 | 创建清理任务 | 管理员二次确认后创建一次性任务；同一租户同一时刻只允许一个任务 | P0 | US-01、US-03 |
| FEAT-04 | 分批删除 | 按会话维度处理，每批 100 个会话，每会话一个事务，守卫跳过不可删会话，断点续跑 | P0 | US-03、US-04 |
| FEAT-05 | 维护阶段 | 删除完成后执行一次 VACUUM (ANALYZE)，再逐个重建大索引 | P0 | US-04 |
| FEAT-06 | 进度与报告 | 任务状态机、批进度、删除量、索引前后大小；页面轮询可见 | P0 | US-02 |
| FEAT-07 | 取消任务 | 可取消未完成任务，当前批次回滚，进度保留 | P1 | US-03 |
| FEAT-08 | 审计 | 创建、开始、取消、完成均写审计记录 | P0 | US-06 |

#### FEAT-01: 保留期设置

- **描述**: 保留期以会话最后活跃时间为准，超过保留期的会话对用户不可见、不可续聊，并进入清理候选。
- **验收标准**:
  - [ ] 保留期缺失或非法时显式失败，不静默回落到猜测值；
  - [ ] 超过保留期的会话不出现在历史列表，详情与续聊返回稳定的"已过期"错误；
  - [ ] 保留期为 0 时的语义明确（不自动过期/不自动清理）。

#### FEAT-02: 清理预览

- **描述**: 在创建任务前，返回候选会话数、关联行数与估算字节。
- **验收标准**:
  - [ ] 预览不修改任何数据；
  - [ ] 预览结果与随后任务实际处理的候选集一致（在无新写入的前提下）；
  - [ ] 预览只统计当前租户。

#### FEAT-03: 创建清理任务

- **描述**: 管理员在设置页二次确认后创建任务，接口返回任务标识；执行不由 HTTP 请求驱动。
- **验收标准**:
  - [ ] 仅 ADMIN 可创建；
  - [ ] 创建请求幂等，重复提交不产生第二个任务；
  - [ ] 同一租户已有运行中任务时拒绝或返回已有任务；
  - [ ] 任务创建写审计。

#### FEAT-04: 分批删除

- **描述**: 执行器按批领取候选会话，按外键顺序删除该会话在 22 张关联表中的数据及产物文件，最后删除会话行。
- **验收标准**:
  - [ ] 每批 100 个会话，批大小可配置；
  - [ ] 每个会话的数据在单独事务中删除并提交；
  - [ ] 有活跃 Run、未结束 job、等待中确认、有效工具结果引用的会话一律跳过并记录原因；
  - [ ] 进程中断后从已提交的进度继续，不重复、不漏删；
  - [ ] Golden Set 用例随其源 Run 一起删除，避免留下不可回放的用例；
  - [ ] 用户记忆、学习经验、Skill 包、审计表不被删除。

#### FEAT-05: 维护阶段

- **描述**: 全部批次完成后执行一次 `VACUUM (ANALYZE)`，再逐个重建 `canonical_event` 的大索引。
- **验收标准**:
  - [ ] 删除 0 行时跳过维护阶段；
  - [ ] 索引逐个重建，不并发；
  - [ ] 单个索引重建失败时记录失败与残留索引名，任务标记为部分成功，不静默忽略；
  - [ ] 报告给出每个索引重建前后的大小。

#### FEAT-06: 进度与报告

- **描述**: 任务状态为 PENDING / RUNNING / MAINTENANCE / SUCCEEDED / SUCCEEDED_WITH_WARNINGS / FAILED / CANCELLED，页面可查询进度与最终报告。
- **验收标准**:
  - [ ] 进度包含已处理会话数、总候选数、已删除行数、当前阶段；
  - [ ] 终态报告包含删除明细汇总、跳过原因分类、索引前后大小；
  - [ ] 页面刷新或重新打开后仍能看到最新进度。

#### FEAT-07: 取消任务

- **描述**: 管理员可取消运行中的任务。
- **验收标准**:
  - [ ] 取消请求在批次边界生效，当前批次事务回滚或提交完成后停止；
  - [ ] 取消后保留已完成进度，可再次创建任务续跑；
  - [ ] 取消写审计。

#### FEAT-08: 审计

- **描述**: 清理任务的全生命周期写审计。
- **验收标准**:
  - [ ] 创建、开始、取消、完成、失败均产生审计记录；
  - [ ] 审计包含操作者、租户、任务标识、时间范围与删除量。

### 4.2 边缘情况

| 场景 | 预期行为 |
|------|----------|
| 候选会话在清理过程中被续聊 | 会话不再满足过期条件，守卫跳过，不删除 |
| 候选会话有活跃 Run / 未结束 job / 等待中的记忆确认 | 跳过并记录原因 |
| 删除过程中执行器进程重启 | 从已提交进度继续，当前未提交批次重做 |
| 删除 0 行 | 任务直接进入终态，跳过维护阶段 |
| 单会话行数异常大 | 超过单会话上限时跳过并记录，下次重试 |
| 索引重建失败 | 记录失败与残留无效索引，任务标记部分成功 |
| 同一租户重复触发 | 返回已有运行中任务或显式冲突 |
| 孤儿软删行（会话行已不存在） | 不在本需求的清理范围内（见 6.2） |

## 5. 非功能需求

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-PERF-01 | 性能 | 删除按小事务分批提交；每批有界；在线请求 P99 无可观测劣化；锁等待超时视为失败并跳过 |
| NFR-REL-01 | 可靠性 | 任务可续跑、可取消；执行器单实例（advisory lock）；失败不阻塞在线服务 |
| NFR-SEC-01 | 安全 | 仅 ADMIN 可触发；按租户隔离；不允许跨租户删除；审计不可缺 |
| NFR-OPS-01 | 可运维性 | 报告与日志可对账；索引重建独立可追溯；不引入新的部署单元或定时调度器 |

## 6. 范围与边界

| 类别 | 内容 |
|------|------|
| **范围（In Scope）** | 保留期设置与可见性语义；清理预览；任务创建/取消/进度/报告；按会话维度的物理删除（事件、运行、快照、提交、租约、工具操作、通知、Golden Set 用例、产物行与文件、会话行）；结束后的 VACUUM 与大索引重建；审计与指标；设置页入口 |
| **非范围（Out of Scope）** | 冷备/导出/恢复；按时间区间分区与 DROP PARTITION；软删孤儿行的物理清扫（通道 B）；学习内容与原文解耦（`eval_case` 弱引用化）；IM 渠道专有逻辑；用户记忆、学习经验、Skill 包、审计表的清理；新增 CronJob 或独立守护进程；自动周期调度 |
| **前置假设** | 清理由管理员在业务低峰人工触发；执行器复用 Runtime 既有维护循环并使用 advisory lock 单实例执行；保留期到期即不可见，清理不改变用户可见语义；所有关联数据都可以在删除会话后一并丢弃 |

## 7. 依赖与风险

### 7.1 项目依赖

| 依赖方 | 依赖内容 | 最晚交付时间 | 风险等级 |
|--------|----------|--------------|---------|
| 平台设置 | 保留期与批大小配置、按租户读取 | 与功能同批 | 低 |
| Runtime 维护循环 | 任务领取、advisory lock、失败不杀循环 | 与功能同批 | 中 |
| Console 设置页与 API | 预览、创建、进度、取消、权限与审计 | 与功能同批 | 低 |
| 产物存储 | 删除会话关联的产物文件 | 与功能同批 | 中 |
| Alembic | 新增任务表的迁移 | 与功能同批 | 低 |

### 7.2 风险识别

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|---------|
| RISK-01 | 无冷备，删除不可逆 | 误删无法恢复 | 预览 + 二次确认 + ADMIN 限制 + 审计 + 守卫 |
| RISK-02 | 大批量删除导致长事务、锁等待、复制延迟 | 影响在线请求 | 小批次、每会话事务、lock/statement timeout、限速、低峰触发 |
| RISK-03 | 索引重建的 IO 与临时磁盘开销 | 重建期间性能下降或失败 | 逐个索引、低峰、失败留痕、报告前后大小 |
| RISK-04 | 会话数据分散在 22 张表，漏删或顺序错误 | 删除失败或留下悬空数据 | 以外键顺序驱动，集成测试覆盖每张表，失败整批回滚 |
| RISK-05 | 学习用例强关联源 Run | 源 Run 删除后用例不可回放并污染评测 | 本需求随源 Run 删除用例；弱引用化另立需求 |
| RISK-06 | 孤儿软删行不被本需求覆盖 | 空间无法完全回收 | 明确记录为已知缺口，后续单独评估 |
