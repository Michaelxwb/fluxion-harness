## 单项结论

### 工具预算

- 30 次对“资产 + 天气”两步任务足够，基线 4 次工具调用完成。
- 3 次会在完成资产查询后、天气查询前停止，说明预算是真实硬约束。
- 停止文案保留“已取得 1 个工具结果”，续行“继续”只补天气，不重复资产查询。
- 工具预算 3 过低，不建议作为默认值；30 次与当前基线匹配。

### 历史预算

- 256 tokens 足以保留当前输入，但会丢掉 23 条历史记录；本次 Agent 仍使用当前条件完成查询，没有追问历史。
- 长对话需要更早事实时，256 不足以支撑；默认 65536 不应下调到该量级。
- 本次没有对比 65536 与其它候选值在同一长对话上的完成率/追问率，只验证了低预算边界。

### 失败阈值

- 旧 Run 导出 `max_identical_failures=3`，新 Run 导出为 2，历史预算 65536、摘要关闭，二者可区分。
- 没有在同一失败提示词下分别用 2 和 3 跑 A/B，因此不能从本次数据判断阈值对体验的影响；只验证了冻结与导出正确。

### 摘要

- 当前设置 `summary_enabled=false`，且没有可用摘要模型/容量的评估准备。
- 本次未评估开启摘要后的完成率、token 和延迟，不能给出摘要默认值建议。

## 默认值建议

本次证据支持继续使用：

```text
max_turns=20
max_tool_calls=30
history_budget_tokens=65536
max_identical_failures=2
summary_enabled=false
```

不建议根据本次有限对照提高/降低默认值。要完成完整 B-02，还需：

1. 同一失败提示词下对阈值 2/3 做 A/B；
2. 同一长对话下对历史预算候选值做 A/B；
3. 在可用摘要模型与容量下对比摘要开关；
4. 记录 token 用量（本次导出摘要提供模型/工具延迟和调用数，未提供 token 计数）。
