# Agent 对话续行与运行设置生效 · 后端设计

## 1. 文档控制

v0.9，按 2026-11-27 代码 review 收敛写身份、未知写入生命周期、统一派发门禁和执行事实传播。开发阶段不保留旧会话、旧 checkpoint、旧别名或旧设置修订的兼容分支；最优设计优先。后端负责人覆盖 Agent Core、Runtime、Worker、Console 和 IM Gateway 的契约。验收负责人按人工场景记录用户侧结果。前端交互见 [前端设计](agent-tool-failure-chain.frontend.design.md)。

## 3. 技术设计

### 3.1 工具事实、进展及重试

共享内核使用同一判定处理现场完成、自动重试、事件重放和跨 Run 继承。Runtime/Worker 负责读取持久化事实并传给内核。准备阶段、外部请求发送和业务结果是独立证据。

| 执行事实 | 重试和续行 |
|---|---|
| 参数或策略在派发前拒绝 | 保留调用身份、拒绝原因及未派发事实。可纠正拒绝允许修改参数。明确不可重试的失败只阻断原调用形状，并由同一派发门禁在 policy 之前执行。 |
| 已派发且结果已知 | 按工具重试契约、结果与剩余预算判定。一次普通失败允许 Agent 做下一步；不可重试约束原调用。 |
| 已派发且结果未知，或副作用已进入执行边界但无法证明未派发 | 写入和外部副作用进入待核实集合。即使 transport 为 OK、业务为 UNKNOWN 或 failure layer 为 NONE，也参与判定。获授权的只读核实和可证明独立的操作继续。 |
| 仅有已准备事件 | 结合已持久化的完成、可核实未派发事实及异步 operation/child 状态。挂接已有异步操作。没有决定性证据的同步副作用按待核实处理。 |
| 触发既有宿主硬停止条件 | 按宿主规则停止，基于已持久化事实收尾，保留可交付结果。 |

- **写身份**。effectful 工具在装配期声明按调用解析的 `CallSemantics`：`effect`、`retry_safety`、`write_targets` 和 `operation_key`。目标使用命名空间（MCP 服务、Skill、平台实例、workspace、draft、delivery、artifact、task、memory），禁止隐式全局 `*` fallback。`target=skill` 取 skill key，`target=workspace` 取用户 workspace，`deliver_artifact` 取 delivery；同一工具的不同目标不得共享一个无限范围。
- **操作身份与解除**。既有脱敏参数 hash 用于调用形状去重。跨次执行的写操作优先采用已有且能跨尝试匹配、由宿主或下游验证的业务操作身份。单次 call ID 和 Task 提交幂等键仅在原调用重放范围内使用。缺少受信身份时，按冻结能力的写入目标设置待核实范围，涵盖可能触及同一外部资源的入口。能证明独立的目标可继续。目标重叠无法排除时，要求核实后再写，提示模型先查询或交付已知事实。超时、输出格式、分页大小和换入口均不能单独证明写操作独立。现有读取安全声明必须来自受信定义，模型与 Skill 自述无法授予权限。

  目标范围从实际授权的资源取得，例如平台实例、MCP 服务或已隔离的草稿与工作区。用同一受信映射识别通向同一资源的入口。MCP 服务与 Skill 可以访问同一平台时，只有已验证的资源映射才能判定其关系。缺失映射的外部能力按潜在重叠处理，但不得用隐式 `*` 把 delivery 等独立入口一并锁死。工具返回的普通文字不能解除待核实状态。同 operation key 的受信完成结果可以解除原操作；无 key 的 target 只接受宿主或人工处置解除。
- **只读核实**。未知写入不放开原 workspace 门禁；Runtime 提供 `read_workspace_file`（READ、无 shell、workspace 路径校验、分段读取）读取落盘事实。它不进入写目标集合，因此可在原写入仍待核实时安全执行；`deliver_artifact` 等独立目标继续按各自门禁判定。
- **统一派发门禁**。`blocked_attempts`、未知写入和 policy deny 在 `ToolExecutionPipeline` 的同一 pre-dispatch gate 判定，且在 policy 之前执行。Runner 不再在 handler 前保留第二套门禁。`IDEMPOTENT` 操作在复用原 operation key 时按工具重试契约放行；`NON_RETRYABLE` 的同形状调用直接阻断。
- **生产者**。MCP 两端透传 SDK 的 `sent/outcome_known`，覆盖 SDK 错误到工具结果及审计转换。Skill 由执行器报告 `execution_started`、`sent/outcome_known`，并通过 `SkillExecutionError` 传播，而不是从通用 `FAILED` 或 `SandboxUnavailable` 名称推断。已启动、结果截断或超时且无法证明没有副作用时保留不确定性。检查 workspace/draft、异步提交、中间件与 handler 后处理失败。后处理异常时保留已拿到的 content、artifacts 与 follow-ups。
- **持久化**。沿用 `TOOL_CALL` 和检查点载体，完成事件记录执行阶段、发送及结果事实与使用的操作身份。准备事实只用于进入 handler 前的持久化边界。派发前拒绝写完成事实及拒绝阶段，恢复按阶段识别。实时和恢复使用同一操作身份生成规则与计数规则，按租户、会话、Run、调用身份和消费水位去重。跨 Run 查询匹配所有未解决调用，使用规范化事实判断，覆盖明确拒绝、已完成已知和无业务结论三个分支。异步 `TOOL_TASK_ACCEPTED` / `BACKGROUND_RESULT` 事件带 `source_tool_call_id`，恢复时挂接 operation，不把已受理的异步调用记成未知写入。
- **自动重试**。等待期间重新验证执行权、期限和预算，派发前再用同一事实门禁。外部写在现有串行边界内决策，并发读取按既有规则执行。重试预算与正常调用使用同一计数口径。
- **进展**。连续失败计数按工具/技能作用域、错误码和失败层维护。确认正常的同作用域成功清零，包括 `load_skill` 的 `OK / NOT_APPLICABLE / NONE`。失败计数与待核实写操作分别维护。未知结果、跳过的调用和无关工具成功均无需清除此计数。对已发生的同类拒绝保留真实原因；硬停止优先于进展判定。

### 3.2 Execute 与 Skill 可见性

| 宿主 | 目标 | 约定 |
|---|---|---|
| Runtime | `skill` | 按冻结 Skill 执行默认入口，SYNC 校验后本地执行，ASYNC 按现有规则提交 Task。传递业务 input、argv 与模式允许的执行选项。 |
| Runtime | `draft` | 使用 `draft_id` 和 `command` 在草稿副本试跑，保留现有授权、沙箱、测试数据隔离和 revision 校验。 |
| Runtime | `workspace` | 使用 `command` 按既有用户、Agent 和平台范围执行。 |
| Worker | `skill` | 使用冻结的任务工具和 Skill 路由。 |

- 删除 Runtime 模型定义、说明和参数校验里的 `script`，删除 `enable_run_skill_script`、对应 handler 和仅由其调用的辅助逻辑。入口按目标校验键，参数错误指出出错字段。开发阶段不保留 `execute_skill` / `run_skill_script` 执行别名；历史审计展示继续解析原工具名。Spec 通过 `modify` 替换旧规则，不使用只追加的 `add`。
- 冻结策略和 handler 共享 `SKILL_NOT_EFFECTIVE` 契约及本地化提示，覆盖执行、加载和资源读取。给出请求 key，指导用 `search_skills` 查看本 Run 生效目录或请管理员核实。冻结集合无法提供的具体原因保留为可能性。目录按既有授权和容量收口。
- 核对仓库中的活跃 Skill 说明、提示和运维文档，并在发布前抽查授权的已部署 Skill 包说明。涉及 `script=` 的业务步骤改为默认入口支持的调用形状，或在草稿中试跑。测试覆盖共享沙箱安全规则和正常发版路径。

### 3.3 当前输入与企微澄清

- **上下文**。保留 ContextPlan 当前输入锚点，标记根据实际保留材料形成。已保留当前输入时，标记明确模型应优先使用它。只有早期必要事实缺失时才询问该项。验收在同一模型请求中核对标记与当前输入；原有裁剪计数、摘要降级和审计沿现行规范。
- **跨 Run 续行**。按同会话、用户和有效 Run 片段核对 canonical 历史、ContextPlan 和实际模型请求。复现上一轮含大量工具往返以及上一轮耗尽模型或工具预算后用户说“继续”。若目标或进展在加载或裁剪阶段丢失，定点修复其进入请求的路径。上一轮投影至少包含明确的用户目标、最终回答，以及受预算约束的工具往返事实（声明、结果、失败码、未完成/待核实状态）；不能只保留最后一条 assistant 文本。只有 summary 未覆盖当前投影时才注入原文，避免与 summary 重复。显式新目标优先，上一轮失败保留原结局，继续执行仍经过写入门禁。
- **生成与待送达**。Runtime 当前在 `HumanQuestion.suspend` 事务内写提问、检查点、`RunInterrupt` 和等待状态，并调用现有等待通知。企微路由通过 `write_run_notification` 写 `HUMAN_QUESTION` 消息意图，身份使用 Run 与 interrupt。对正常、重试及回复句柄失效路径逐段核验路由、回复关联、意图和真实回执。若受支持的企微路由无法建立可发送的意图，返回可诊断失败并避免留下无可见提问的等待；对已提交意图的后续投递失败沿现有状态机归类。
- **发送**。沿用 Runtime 消息投递泵、Gateway 与 Connector 的现有企微发送能力。持久消息路径对同一提问负责，进度或流式展示不重复发送正文。确认未发送才按现有重试策略处理，发送结果未知保持可对账。日志关联 Run、interrupt、投递身份和回执，保持租户及路由核属。
- **回答与恢复**。同用户在原企微会话直接回复，沿现有 active Run resume 和中断锁合并补充参数。会话、用户、入口和有效期约束由 Runtime 校验。重复回复按既有入站幂等处理，有效回答推进同一 Run 一次，过期或取消后按现有通道反馈。会话在等待提问期间被删除时沿用“删除即收口”，通知事务不抛错、不产生不可见的等待通知。
- **历史证据**。`b24a7c19` 的 seq 895 是工具完成，896 是提问正文落库，897 是等待状态。导出无法确认 `message_delivery` 及企微最终回执。先按 Run 与 interrupt 核验消息意图、Gateway/Connector 回执和客户端。只修复该链路中可复现的断点。

### 3.4 设置、诊断与默认值评估

- **控制与执行**。定义“连续同类失败停止阈值”为累计到该次数时停止，首个普通失败仍给 Agent 一次续行机会。页面、后端校验、任务快照和共享内核统一采用最小值 2；`AgentPolicy` 在构造和 runtime_config 覆盖时做同一校验，避免快照显示 1、运行时却按 2 执行。把当前有效阈值写入新 Run 的 `policy_json`。新 Run 读取该冻结值，恢复与重放沿用它。Worker 维持任务预算的冻结来源，覆盖相同阈值语义和设置覆盖优先级。
- **已有设置与运行**。开发阶段不写旧修订兼容或迁移分支；旧 revision 1 的设置直接作废并重置为有效值。普通 Run 旧策略若缺少阈值，按当前 schema 默认值执行；发布前只清点活跃旧执行，旧终态只保留审计。历史终态诊断对缺失字段显示未记录。
- **诊断接口**。在现有授权执行导出中从冻结快照投影有效模型轮次、工具调用数、失败阈值、历史预算、摘要启用状态与是否有冻结摘要模型，关联用量及停止类型。Run 与 Task 共用同一投影口径：Run 读 `policy_json`，Task 读 `execution_snapshot_json.budget`，缺失字段保留未知语义。已有裁剪/摘要事件用于区分配置开启和本次实际运行。只投影所需非密钥标量，沿用既有执行归属和导出授权。
- **评估**。内网候选组合为模型轮次 200、工具调用 300、截止 3,600,000 ms、模型重试 3、同类失败阈值 2、历史预算 123,904、摘要开启。现场先核验新 Run 冻结值、摘要模型和外置阈值，再复验原本达限和丢目标的任务。固定模型修订、Skill 版本、授权、历史材料、输入与部署约束。分别对比模型轮次、工具预算、历史预算和摘要，再复跑选定组合。用成功、部分交付、重复追问、所达预算、有效工具调用、延迟和 token 决定默认值。摘要候选须有可用模型和容量，历史预算取部署窗口校验允许范围。

### 3.5 正文与产物交付

| 阶段 | 后端契约 |
|---|---|
| 选择产物 | Agent 优先满足用户指定类型。未指定时，按数据、用途以及现有生成和交付能力选择。需要机器处理的数据可保留结构，趋势可用图，成组文件可用归档包。渠道不支持直发时使用已有授权下载能力。 |
| 准备与核验 | 模型已有完整正文时可用 `write_artifact`。Skill 可返回已登记的产物，临时脚本可把原始输出和最终产物写到授权工作区。根据类型验证文件可打开或可解析，并核对来源与范围，例如图的数据点、归档成员、文本覆盖范围或列表分页。 |
| 正文或附件 | 结果能完整放进正文且用户未要求产物时直接回复。正文超限或需要产物时，Agent 通过现有附件入口发送，并在最终回复说明所含内容、范围和送达状态。 |
| 发送和恢复 | 复用 `deliver_artifact(artifact_id=…)` 或 `deliver_artifact(path=…)`、现有渠道适配和产物归属。交付声明为 `IDEMPOTENT`，operation key 由交付键导出；同次交付复用原产物与交付键。明确未发送按可重试失败；送达未知保留原 key 并如实反馈，不写入会阻塞后续独立写入的全局未知范围。 |

- **已有产物链**。当前 `write_artifact` 写 Markdown。工作区文件已有安全路径解析、按内容复用登记、真实媒体类型和归属校验。继续复用现有产物 ID 和 checksum，用户工作区内的一次性文件在实际交付时才走既有登记。无需新增业务跟踪表、迁移或格式专用交付工具。
- **运行路径**。Agent 从既有工具描述获知正文与附件的选择策略。超限结果通过既有附件入口交付，最终说明走原会话回复。
- **取数与状态边界**。按实际证据声明来源、范围与完成度。列表可核查授权、客户映射、筛选和分页。其他类型按其数据边界核验。程序生成的完整产物可独立于截断的 stdout 检查。仅有截断预览时保留部分结果或安全补取。宿主依据实际投递结果报告状态。现有显式产物投递路径把通用交付异常处理成可重试，须区分明确未发出、结果未知及实际送达。
- **证据**。MSSP 清单、跨平台资产查询和临时脚本作为列表回归样本。验收另使用全文、图或归档包验证模型按不同用途选型。本地夹具 `mssp-asset-query-local` 提供 `1001` 小客户与 `9001` 的 1200 条批量资产，覆盖默认截断、按 IP 段缩小、完整 CSV 导出和交付。

### 3.6 质量与发布

| 验证层 | 必须覆盖 |
|---|---|
| 共享内核单元 | 发送与结果事实组合、未派发拒绝、未知写入按命名空间目标阻断、同 operation key 的受信解除、`IDEMPOTENT` 重试、变参与换入口、同作用域成功清零、硬停止和自动重试。 |
| Runtime/Worker 集成 | 生产者到规范事件和恢复的往返。Runtime 数据库实测跨 Run 查询、租户隔离、已知拒绝与真实未知区分、异步 operation 挂接。Worker 任务恢复、预算和 `execution_started` 一致。 |
| 契约回归 | Runtime 三个 target、Worker skill、草稿隔离、资源读取、历史详情、冻结与设置保存的非默认值 round-trip、授权导出，以及真实 `execute` / `deliver_artifact` 定义的写目标。 |
| 渠道验收 | 可控集成覆盖企微意图写入与发送、原 Run 恢复及重复事件。真实客户端人工执行 S-03，WebChat 执行 S-07。 |
| 产物交付集成 | 业务 Skill 输出和工作区文件导入走实际产物链。覆盖用户指定类型、Agent 自选至少一种非文档非表格产物、正文可容纳时直接回复、超限时附件加最终说明、截断时原产物完整、同一产物重试及结果未知。 |
| 发布前清点 | 以租户为界核实旧等待/恢复执行和未核实写入。有可信旧事件时按事实判断；缺少操作身份的未核实写入先处置再切换。Runtime/Worker 同步验证事件和检查点口径。 |
