# PRD · Agent 对话续行与运行设置生效

**文档编号** PRD-2026-11-27-01  
**版本** v0.8 · FEAT-06  
**需求目录** `agent-tool-failure-chain`

## 1. 背景与目标

用户在 WebChat 或 IM 请求资产明细时，可能遇到工具拒绝、输出不完整、Skill 不可用或需要补充信息。现有链路中，一次可纠正的失败可能拦住后续可用路径，已有信息可能被误认为丢失，提问进入等待后也可能缺少用户端交付证据。用户需要重新解释目标，或无法判断任务还在等待什么。

本次需求让 Agent 在遇到阻碍后继续服务原目标。有安全路径时继续执行，有已核实的部分结果时可交付，确有信息缺口时只询问缺的一项。管理员能确认系统设置实际如何影响新 Run，并根据对照结果决定是否调整默认值。

| 证据 | 对需求的影响 |
|---|---|
| `bb329b5c` 的调试参数在派发前被拒绝，随后无关的外部调用也被拦；`230d2a58` 有同类记录 | 修复模型工具契约与宿主误锁。 |

## 3. 功能需求与验收

| 编号 | 功能 | 可验收结果 | 用户故事 |
|---|---|---|---|
| FEAT-01 | 工具失败后继续原任务 | 参数、权限或策略等派发前拒绝给出可行动的原因，并允许获授权的其他操作继续。外部写入结果未知时，允许安全核实，宿主阻断可能重复原操作的调用，包括仅改超时、输出选项或换入口的调用。实时执行、自动重试、同 Run 恢复和同会话后续 Run 判定一致。成功的 `load_skill` 清除同工具的连续失败计数。 | US-01 |
| FEAT-02 | 收敛 `execute` 与冻结能力契约 | `execute` 是模型侧统一执行入口。各宿主的定义、允许参数与实际支持的目标一致。从 `target=skill` 移除 `script` 参数，删除 Runtime 的 `enable_run_skill_script` 开关及其专用执行分支。显式传入 `script` 时返回可纠正的参数错误。未生效的 Skill 返回 `SKILL_NOT_EFFECTIVE`，明确请求的 key，并说明如何查找当前生效的能力或请管理员核实。原因及目录信息以本 Run 可见事实为界。 | US-01 |
| FEAT-03 | 保住上下文并完成澄清 | 同一会话后续 Run 能沿用最近一次用户目标、已确认参数、已完成步骤和未完成事项。覆盖工具结果较多的两次用户对话，以及达到预算后用户说“继续”的场景。续行使用已核实事实，遵循未知写入门禁。长对话裁剪后保留当前输入并准确描述省略历史。确需澄清时只问缺失项。企微用户在原会话看到明确问题并直接回复，原待输入 Run 继续。WebChat 同步验证。 | US-01、US-02 |
| FEAT-04 | 设置实际生效且可核验 | 系统设置页接受的失败阈值有确定的执行语义。新普通 Run 采用当次有效值，同 Run 的重试与恢复沿用冻结值。使用区分度足够的非默认值验证从设置保存到宿主实际停止行为，并检查 Worker 的同类预算契约。授权排查者能核验该 Run 的有效失败阈值、历史预算和摘要状态，诊断只展示所需的非密钥事实。 | US-03 |
| FEAT-05 | 用真实场景评估默认值 | 复用复杂资产查询、工具结果密集的短对话和长对话案例。在固定模型、Skill 版本和输入条件下建立基线，分别调整模型轮次、工具调用数、历史预算或摘要，最后验证选定组合。记录实际冻结值、达到的预算类型、有效工具调用、任务完成、部分交付、重复追问、已确认信息复用、延迟和 token。失败阈值在生效和计数逻辑修复后评估。默认值调整以对照结果为依据。 | US-04 |
| FEAT-06 | 由 Agent 选择并交付适合用途的产物 | 适用于任意数据类型。用户指定产物类型时优先遵从。未指定时，Agent 根据实际数据、用户用途和现有能力自主选择产物。文字可承载且用户未指定产物时直接回复。正文超限或结果需要产物时，原 Run 交付附件或授权下载入口，再用一条简短的最终回复说明所含内容、覆盖范围及实际送达状态。若只能取得部分内容或交付失败，说明缺口和状态。用户只需发送一次请求。 | US-05 |

产物可以是文档、表格、图片、机器可读数据、归档包或其他当前能力支持的类型。类型示例用于验收。已有完整文本可沿用 `write_artifact`，业务 Skill 和授权工作区脚本可直接生成其他产物。程序已生成文件时，由 `deliver_artifact(path=…)` 导入并交付。一次性中间文件留在用户工作区，发布沿用现有附件归属、产物和投递记录。

核验按数据和产物类型进行，确认成品可打开或可解析，且与原始数据及用户请求的范围相符。列表按需核对来源、授权、筛选、分页及记录数。跨平台复用客户标识须有受信映射。控制台截断时从完整文件或安全查询补齐，禁止从预览推断缺失内容。确认未发送且允许重试时，使用同一产物继续交付。发送结果未知时按现有语义核实。

### 验收时需要区分的结果

| 情况 | 通过条件 |
|---|---|
| 资产查询结果不完整 | 通过较小范围的安全查询完成原目标，或明确交付已核实部分并说明缺口。 |
| MSSP 客户清单超长 | 在企微发起一次授权客户列表查询。收到可打开的完整明细产物和一条简短说明。行数与来源可核实的匹配总数一致，缺页或未送达时说明缺口或状态。 |
| 超长文本查询 | 在 WebChat 发起一次查询，收到可打开的文本产物和简短说明。对照原始结果核对范围和完整性，刷新会话后还能看到说明和产物。 |
| 无预设格式的其他数据 | 请求查看数据趋势或取回一组异构文件，给出用途即可。Agent 自主选择合适产物，例如可阅读的图或便于取回的归档包。检查成品可打开，且展示的数据或包内成员与实际来源对应。 |
| 临时脚本取数与跨平台归属 | 模拟控制台截断、分页总数与实际行数不一致、跨平台客户映射未知，以及完整文件首次未送达。确认表格逐行来自程序取数，能核对分页和文件范围。未验证映射的结果按实际来源陈述，首次投递失败后继续处理已核验的同一文件。 |
| 外部写入结果未知 | 重做被可靠阻断，Agent 能核实结果或清楚说明等待事项。 |
| 用户自建 Skill 草稿 | 在具备权限的对话中创建或修改草稿，使用 `execute(target=draft, draft_id=…, command=…)` 在草稿副本内试跑并读取结果。草稿与测试数据沿用租户、用户及所属 Agent 的隔离。另验草稿按既有流程发布并对新 Run 生效后，能经 `execute(target=skill)` 调用默认入口。 |
| 按执行目标验收 | Runtime 的 `skill` 验证默认入口、异步提交与参数传递，`draft` 验证草稿试跑，`workspace` 验证授权工作区命令。Worker 验证其现有 `skill` 执行路径。分别验证跨目标参数拒绝、Skill 资源读取及旧 `run_skill_script` 执行记录仍可查看。 |
| 企微缺少必填参数 | 用真实企微客户端发起查询并看到具体提问，如“请回复客户名或客户 ID”。直接回复后，原 Run 使用补充参数继续。分别记录问题落库、出站结果、客户端收到、答复关联和原 Run 恢复。只看到进度状态或 `WAITING_INPUT` 时，该场景未通过。 |
| 长对话缺少更早的必要条件 | 只询问确实缺失的条件，复用当前输入和仍可用的已确认信息。 |
| 两次用户对话之间有大量工具往返 | 第一条给出客户、平台和任务目标，第二条仅补条件或说“继续”。验证同一会话的新 Run 仍能用已确认条件完成剩余工作。另覆盖第一次 Run 因模型轮次或工具预算收尾后继续的路径。 |
| 设置保存后又有并行 Run | 保存前后创建的 Run 分别采用各自的冻结值，同一 Run 恢复沿用其原值。 |

## 4. 范围与依赖

- **本期交付**包括现有四项框架修复、跨 Run 对话续行验收、普通 Run 失败阈值的设置生效修复、运行设置默认值评估，以及普通正文和超限附件的同一 Run 交付。
- **一次性产物**复用用户工作区、现有附件登记和渠道投递事实。FEAT-06 范围以这些能力和实际复现的交付断点为界。
- **渠道范围**包括企微 `ask_user` 的可见提问、直接回复续接及这条链路上复现的断点修复，同时验证现有 WebChat 路径。沿用现有渠道与消息投递能力。投递协议重构和通用补投机制留在原范围之外。
- **Skill 清理边界**限于 `target=skill` 指定包内脚本的调试入口。`target=draft` 试跑走独立的 `skill_draft_shell` 执行路径，纳入 FEAT-02 回归。保留 Skill 包脚本文件、默认入口选取和入口内部调用辅助脚本。评估旧 Skill 说明或提示模板中引用 `script` 的影响，并在设计中明确修订方式。
- **其他事项**。通用 Skill 包入口与 SYNC 结果契约整改、通用输出超限语义改判、通用历史裁剪算法重做和更换主模型作为独立事项。FEAT-06 在超长场景中分别保留工具执行事实、明细完整性和渠道交付事实。先按实测定位目标丢失环节，再确定对话续行的最小修复。
- **证据依赖**。七份导出展示模型版本、事件和部分预算，完整冻结策略及内网实际生效设置需从授权来源核验。历史策略缺失时，以记录了有效配置的新 Run 建立对照基线。默认值评估同时受模型窗口、摘要模型容量和延迟约束。
- **评审项**。系统设置的“同一失败最多重复次数”应明确表示停止阈值还是允许失败后再尝试的次数。页面、校验、运行和恢复应采用同一语义。默认值是否调整，依据验收和对照证据决策。
