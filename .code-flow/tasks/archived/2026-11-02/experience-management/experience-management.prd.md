## 2. 背景与目标

### 2.1 问题陈述 [必填]

| 维度 | 内容 |
|------|------|
| **问题描述** | 自进化学习闭环（Golden Set 抽取 → 经验候选 → 两臂回放 → TRIAL/ACTIVE）已经接入运行时，但管理面只有命令行（`scripts/learning_admin.py`）与直接查库。Console 的「用户详情 → 记忆」把经验当普通记忆展示：状态只有 `ACTIVE / DISABLED / EXPIRED`，看不到 `PROPOSED / TRIAL / ACTIVE / RETIRED` 状态机、任务族、触发文本、来源 Run 和回放证据；也没有任何按任务族的视图。结果是管理员与运维无法回答「这条经验为什么被激活」「这次 Run 为什么没注入它」「这个任务族学得怎么样」，出问题时只能查库。更严重的是三个事实缺陷让「解释」本身不可信：①`eval_report` 没有用户维度，而经验 key 只由任务族哈希生成（同族跨用户同名），晋升校验可以借用他人报告；②`activation_state` 变更是直接 UPDATE，不递增版本、不写 `user_memory_history`、不产生记忆幂等回执，状态变更没有可复核的历史；③`MEMORY_INJECTED` 记录的 score 是事后重算值（不是选择时的真实分数），且不记录通道、未注入原因、被渲染预算丢弃的条目。 |
| **当前替代方案** | `scripts/learning_admin.py`（list / replay / activate / retire / explain）+ SQL。问题：不可视化、不可按族聚合、操作不进 Console 审计可追溯链路、非管理员不可用、用户维度与族维度无法互相跳转；同时上述三个事实缺陷使 CLI 的 `explain` 也无法给出可信解释。 |
| **触发原因** | 2026-11-01 dev 端到端验收打通了「经验影响回答」，但验收过程暴露：解释与排障完全依赖人工查库；通用记忆 tab 的停用/删除与学习状态机是两套语义；回放报告跨用户混用。 |

---

### 2.2 目标与价值 [必填]

| 维度 | 内容 |
|------|------|
| **核心目标** | 为「经验」提供一个唯一的、双视图（用户维度 + 任务族维度）的管理模块：两个视图对同一条经验展示同一份事实，且每条经验都能解释「从哪来、为什么是当前状态、为什么注入/未注入、影响了哪些 Run」。 |
| **预期价值** | 学习闭环从「能跑」变成「可运营、可解释、可追责」：管理员无需查库即可定位学习问题；生命周期操作全部经状态机并留审计；排障链路从 Run → 族 → 经验 → 回放/审计双向可达。 |

**产品定位**：本需求是学习闭环的**观测、解释与干预面**；它不提供「Agent 自主掌握一个全新平台接口」的能力。当前学习链路只从**成功 Run**抽取族级过程经验（自然语言、非可执行命令），回放只比较回答文本、不执行工具，失败尝试与技能创建都不在自动闭环内。真正的智能自进化（能力创作 → 沙箱验证 → 失败修复 → 受控发布）是独立需求，缺口清单见 §6 非范围。人工干预是兜底入口，不是学习主路径。

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 经验管理操作落审计比例 | 仅 CLI 手动操作有部分审计 | 100% 生命周期操作写 `control.config_audit_log`（operator/reason/前后状态） | 机检 + 审计表断言 |
| 双视图一致性 | 不存在族视图 | 同一 `(user_id, memory_key, version)` 在用户视图与族视图的状态、计数、回放结论完全一致 | 集成测试对两 API 结果逐字段比对 |
| 排障链路可达 | 人工 SQL | Run → 族 → 经验 → 回放/审计 → 来源 Run 全程可点击/可深链 | E2E 场景 |
| 「为什么没注入」可回答 | 无 | 给定 Run 返回逐候选原因（开关/冻结集合/未 ACTIVE/族不匹配/低于阈值） | 集成测试 + 页面展示 |
| 回放报告归属正确 | 报告无用户维度，可跨用户混用 | 候选臂报告 100% 绑定经验所属用户；跨用户借用报告的晋升被拒绝 | 负向集成测试 |
| 状态变更可复核 | 直接 UPDATE，无版本/历史 | 100% 状态变更产生新版本 + history + 幂等回执 | 集成测试逐字段断言 |
| 审计可发现 | 审计页无法筛选/识别经验事件 | 审计页可按 MEMORY_EXPERIENCE 筛选并跳转经验 | 集成 + E2E |
| 管理面不影响并发 | 未验证 | 1000 用户负载下管理查询 p95 ≤500ms，用户侧 admission/first-delta 不回归 | 容量混合场景 |

> P0=核心必做，P1=重要

#### FEAT-01: 用户经验视图

- **描述**: 在用户详情新增独立「经验」页签，展示该用户的全部经验（`PROCEDURE` / `FAILURE_PATTERN` / `VERIFICATION`），而不是把它们混在普通记忆列表里。
- **验收标准**:
  - [ ] 列表列：memory_key、任务族、分类、状态（PROPOSED/TRIAL/ACTIVE/RETIRED）、版本、回放结论、更新时间；支持按状态、族、分类过滤与分页。
  - [ ] 每条经验的「状态」与学习状态机一致，不把 `enabled/expires_at` 的 ACTIVE/EXPIRED 当学习状态。
  - [ ] 普通「记忆」页签不再对经验类条目提供停用/删除操作，改为跳转经验详情（避免两套写语义）。
  - [ ] 空态、加载态、错误态显式；学习服务不可用时提示且不展示伪造状态。

#### FEAT-02: 任务族视图

- **描述**: 新增租户级「任务族」页面，按 `task_family` 汇总学习资产。
- **验收标准**:
  - [ ] 族列表列：family、来源类型（skill / agent）、Run 数（按声明的统计窗口，默认 7 天，含「上限封顶」显示）、经验数（按状态分列）、最近回放结论与通过率、最近活跃时间；支持按来源类型与关键字过滤。
  - [ ] 族 Run 数来自增量汇总（按族按天），不得在页面请求时扫描全量 Run 历史；统计窗口在页面上显式标注，切换窗口只改变展示范围。
  - [ ] 族详情包含：族下 Run（可跳 Run 详情）、Golden Set（`eval_case`）、按用户分组的经验列表、回放历史（`eval_report`）。
  - [ ] 族键语义在页面上显式说明：`skill:<key>` 不含 agent；`agent:<id>` 为兜底族；`task_family` 为空的历史 Run 归入「未归类」且不计入族统计。
  - [ ] 族详情中的每条经验可进入 FEAT-03 详情，且与 FEAT-01 展示同一份事实。

#### FEAT-03: 经验详情与解释

- **描述**: 经验详情是可解释性的核心载体，用户视图与族视图共用同一数据来源与组件。
- **验收标准**:
  - [ ] 身份区：tenant/user/memory_key/version/category/author/**authority（USER_EXPLICIT/ADMIN_EDIT/AGENT_INFERRED）**/task_signature/trigger_text/expires_at。
  - [ ] 状态时间线：每次状态变化的时间、from→to、operator（自动/人工）、reason、关联审计记录；TRIAL 期展示基线信号阈值。
  - [ ] 来源证据：`evidence_json` 中的 source_run_ids、success_runs、item_total，并可跳转来源 Run。
  - [ ] 回放证据：每次 `eval_report` 的 decision（PASSED/REJECTED/INCOMPLETE/BASELINE）、baseline 与 candidate 成功数、improvement、当时的门槛（min_cases/max_cases/min_improvement）、base_config_hash、时间、**经验所属用户**。
  - [ ] 未知/新增的报告字段、诊断原因码与状态值必须原样透出（extras/未知码兜底），不得因为枚举扩展而丢弃或报错。
  - [ ] 注入记录：哪些 Run 的 `MEMORY_INJECTED` 包含本经验，含选择时的真实分数、命中通道（族命中/目标文本命中）、selection_hash，并可跳 Run。
  - [ ] 未注入解释：同一次注入的快照中，本经验若未入选，必须给出原因（学习关闭/未 ACTIVE/被本 Run 冻结集合排除/低于阈值/被预算丢弃）；历史 Run 若无诊断字段，明确标注「该 Run 未记录诊断」，不得用当前状态反推。
  - [ ] 当前生效阈值：来自该租户 learning 设置（以及经验激活时的冻结口径），页面标注「当时生效」与「当前设置」的区别。

#### FEAT-04: 生命周期操作

- **描述**: 管理员在经验详情/族详情对经验执行受控操作。
- **验收标准**:
  - [ ] 手动回放：提交后返回可查询的任务标识（长耗时操作不占用同步请求）；完成后生成该**用户**该经验的 `eval_report`；不满足样本门槛时明确返回 INCOMPLETE 及原因。重复提交同一幂等键不重复执行。
  - [ ] 回放任务有并发与额度边界：同一租户同一时刻只执行一个回放；模型调用必须走既有容量预占/配额（不得绕过限流），额度不足时任务排队/重试，不抢占用户请求的额度；单任务有超时与最大样本数。
  - [ ] 晋升按权威分流：`AGENT_INFERRED` 经验仅当**该用户**该经验有 PASSED 且满足门槛的回放报告时可用；`USER_EXPLICIT`（用户确认的教学）与 `ADMIN_EDIT`（管理员修订）可按权威路径直接激活，但必须带原因、写审计并进入劣化监控；不得借用其他用户的报告；状态转换只允许状态机定义的边。
  - [ ] 退休：必须填写原因；写审计（from → RETIRED）；不再参与注入。
  - [ ] 「重新沉淀」：仅对 RETIRED 经验可用，产生新的内容版本并回到 PROPOSED（保留完整历史与审计），不依赖候选生成器的自动绕过。
  - [ ] 所有写操作经学习状态机与记忆写入主通道（与调度器同一实现），Console 不直接改状态列；请求带幂等键，重复提交不重复生效。
  - [ ] 权限：仅租户管理员；actor 从登录会话派生，不接受请求体自报。

#### FEAT-05: Run ↔ 学习对象追溯

- **描述**: 把运行时可观测面与学习管理面连起来。
- **验收标准**:
  - [ ] Run 详情展示 task_family，并可跳到族详情。
  - [ ] Run 时间线中的 `MEMORY_INJECTED` 事件可展开为经验链接（memory_key + version + score + decision）。
  - [ ] 给定 Run 可查看「本次注入/未注入诊断」：learning 是否启用、本 Run 冻结的 ACTIVE 经验集合、逐候选未注入原因（未 ACTIVE / 族不匹配 / 低于阈值 / 被冻结集合排除）。
  - [ ] 经验详情与族详情均可跳回关联 Run 详情。

#### FEAT-06: 双视图一致性与聚合口径

- **描述**: 同一经验对象在两个入口必须逐字段一致；族是唯一 join 键。
- **验收标准**:
  - [ ] 用户视图与族视图返回的经验身份、状态、版本、回放结论来自同一服务层与同一查询口径（非两套 SQL 各算一遍）。
  - [ ] 族视图按 `(tenant, user_id, memory_key)` 分组展示；不把不同用户的同名族经验合并成一个状态；回放结论按经验所属用户区分，不展示他人的报告。
  - [ ] `memory_key` 是不透明标识：管理面只按 `(tenant, user_id, task_signature)` 分组与展示，不解析 key 结构；同一任务族允许多个 key（教学/版本演进），不得假设“一族一 key”。
  - [ ] family 字符串的唯一事实源是 `run_record.task_family`；`eval_case` / `eval_report` / `user_memory.task_signature` 必须与之一致。
  - [ ] 一致性由集成测试逐字段断言（两 API 结果对照），而非人工约定。

#### FEAT-07: 经验治理边界

- **描述**: 明确经验的写边界，避免通用记忆入口破坏学习状态。
- **验收标准**:
  - [ ] 学习生成的经验（`exp.proc.*`）不允许通过任何 Console 入口修改内容；通用记忆 API 对经验类条目拒绝写操作并返回明确错误码。
  - [ ] RETIRED 经验不会被候选生成静默复活；「重新沉淀」是显式动作（产生新版本/新一代），并在页面可追溯。
  - [ ] 经验类条目的删除/停用只能经经验生命周期操作完成（或明确保留给非学习类经验）。

#### FEAT-08: 学习事实修正（前置，无兼容层）

- **描述**: 管理模块的可解释性必须以真实事实为前提，先修正三个缺陷，再做页面。
- **验收标准**:
  - [ ] `eval_report` 候选臂报告绑定经验所属用户；回放、晋升校验、页面展示一律按 `(tenant, user, key)` 过滤；基线报告仍按族共享。跨用户报告不得影响本用户经验状态（负向测试必须红）。
  - [ ] `activation_state` 变更经记忆写入主通道：同事务递增版本、写 `user_memory_history`（完整 after 快照）、写幂等回执与 scope revision；审计中的操作者是真实账号 UUID，资源标识包含 tenant/user/key。
  - [ ] `MEMORY_INJECTED` 记录选择时的真实分数与命中通道，并记录本 Run 的未注入候选原因与被渲染预算丢弃的条目（有界条数）；渲染后实际未进入上下文的条目标记为 dropped，不得混在 items 里。
  - [ ] 注入侧的任务族切换与 `run_record.task_family` 采用同一判定（只看成功 skill），避免「Run 记 skill:B、注入按 skill:A」。
  - [ ] 以上修正是本需求所有可解释断言的前提；修复前对应的管理页断言必须失败（RED 证据）。
  - [ ] 记忆行新增 `authority`（USER_EXPLICIT/ADMIN_EDIT/AGENT_INFERRED）并与 `author` 一致映射；激活路径按权威分流；迁移对存量行按 author 回填，未知值按 AGENT_INFERRED 处理。

#### FEAT-09: 审计可见性与深链

- **描述**: 经验生命周期已经写入 `control.config_audit_log`，但 Console 审计页面看不到可用信息：资源类型下拉缺 `MEMORY_EXPERIENCE`、动作无词条、列表被 MODEL 审计淹没、无法跳到经验。
- **验收标准**:
  - [ ] 审计页资源类型筛选包含 `MEMORY_EXPERIENCE`；可按动作（TRIAL_START/TRIAL_PROMOTE/TRIAL_RETIRE/ACTIVATE/RETIRE/REGENERATE）筛选。
  - [ ] 列表与详情展示可读标签：资源类型、动作、操作者（真实账号名；历史合成 actor 显示「系统/自动」并在详情给出 operator）、目标展示 `experience_key`（含用户）。
  - [ ] 详情可从审计行直接跳转到对应经验详情（user_id + memory_key 深链）；跳转后能返回审计列表且筛选保持。
  - [ ] 审计写入与状态变更同事务：没有状态变更就没有审计、没有审计就没有状态变更。
  - [ ] 历史行（修复前的合成 actor/无 experience_key 目标）按原样展示为「归属未知」，不伪造。

#### FEAT-10: 止损与族级暂停

- **描述**: 把「发现坏经验 → 停用」的路径缩短到一次操作，并支持按任务族批量止损。
- **验收标准**:
  - [ ] 从 Run 的注入归因一键停用本次注入的经验（逐条或全部），逐条按 `user_id + memory_key` 生效并写审计；当前 Run 的回答不变，后续新 Run 不再注入。
  - [ ] 族级暂停：按 `(tenant, family)` 暂停该族的学习候选生成与经验注入；只影响暂停后的新 Run，已在飞 Run 的冻结集合不变；可恢复，恢复后不自动复活已退休经验。
  - [ ] 暂停/恢复有原因与操作者审计；跨租户、非管理员拒绝。
  - [ ] 暂停不删除任何数据；族详情显式展示暂停状态与操作者。
  - [ ] 暂停是学习控制面契约：后续的候选生成、教学确认、自动修复任务都必须检查该状态（agent-learning-core 同样适用）。

#### FEAT-11: 经验内容修订

- **描述**: 管理员可以修正经验正文，生成新版本并重新走验证，而不是只能退休。
- **验收标准**:
  - [ ] 修订必须带当前版本（乐观并发）与原因；生成新版本、完整历史、审计，状态回到 PROPOSED。
  - [ ] 修订后的版本必须经回放 PASSED 才能晋升（或管理员在 PASSED 后手动晋升）；禁止直接改成 ACTIVE。
  - [ ] 修订不改变族、来源证据与已注入记录；旧版本的注入历史保留。
  - [ ] 学习生成的经验键不变（同族仍是一族一 key），版本递增；不允许通过通用记忆接口绕过。

#### FEAT-12: 差回答反馈闭环

- **描述**: 把「这条回答不对」变成显式学习信号，驱动相关经验复核。
- **验收标准**:
  - [ ] Run 详情可标记「差回答」并填写可选说明；同一 Run 幂等，重复提交不产生多条信号。
  - [ ] 标记写入 `LEARNING_SIGNAL`（source_run_id 指向该 Run，包含操作者与原因）；该 Run 不再作为未来 Golden Set 的成功样本。
  - [ ] 标记后优先为该 Run 注入过的 ACTIVE 经验排一次复核回放（走异步 job 与容量边界）；回放回归则按 TRIAL 规则退休或标记待人工处理。
  - [ ] 反馈入口对管理员开放；权限与审计同 FEAT-10。
  - [ ] 反馈信号是学习控制面契约：后续教学/修复/候选生成必须消费该信号（agent-learning-core 同样适用），不得只做展示。

## 6. 范围与边界 [必填]

| 类别 | 内容 |
|------|------|
| **范围（In Scope）** | 用户经验视图、任务族视图（含 Run 计数增量汇总）、共用经验详情与解释、生命周期操作（异步回放/晋升/退休/重新沉淀，含回放并发与模型额度边界）、Run↔学习对象追溯与「为什么没注入」诊断、双视图一致性、经验治理边界、审计页面的经验资源可见性与深链、Run/族级止损、经验内容修订、差回答反馈闭环；使能这些能力的学习事实修正（回放报告用户归属、状态变更走记忆写入主通道、注入归因真实性、注入侧族判定对齐）。 |
| **非范围（Out of Scope）** | 学习阈值调参（已有「系统设置 → 学习与记忆」）；跨租户视图；历史 Run 重新分类；注入选择算法改动；自动生成报告/导出；历史学习数据的用户归属回填。**智能自进化能力本身不在本需求**：当前链路不含 ①从接口文档自动生成可执行技能（技能创建仍需用户确认与 Console 审批）、②可执行经验（现有经验是族级自然语言，不保存方法/参数/凭据模板）、③失败驱动的修复（候选只取成功 Run，失败尝试与修复轨迹不进入学习）、④执行级回放验证（回放只比对回答文本，不执行工具，也无沙箱/契约端点）。这四项需独立需求承接。 |
| **前置假设** | 现有数据模型（`runtime.user_memory` / `eval_case` / `eval_report` / `user_memory_history` / `control.config_audit_log`）足以承载；`task_family` 可作为族键；Runtime 提供 internal admin API、Console 有桥接范式。 |

## 7. 依赖与风险 [可选]

### 7.1 项目依赖

| 依赖方 | 依赖内容 | 最晚交付时间 | 风险等级 |
|--------|----------|--------------|---------|

### 7.2 风险识别

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|---------|
| RISK-01 | 族键 `skill:<key>` 不含 agent，用户可能误以为经验按 agent 隔离 | 解释错误 | 页面显式说明判定规则与范围；详情展示实际来源 Run 的 agent |
| RISK-02 | 通用记忆入口与经验状态机存在两套写语义 | 状态被外部破坏、审计缺失 | FEAT-07 收口；通用 API 拒绝经验写操作 |
| RISK-03 | 历史 Run 的 `task_family` 为空，族统计口径不一致 | 数字对不上 | 明确「未归类」分组与统计排除口径 |
| RISK-04 | 聚合查询随数据量退化为全表扫描 | 页面卡顿 | 需要索引与单查询聚合；NFR-PERF-01 验收 |
| RISK-05 | 手动晋升绕过门槛 | 低质量经验被注入 | 服务层强制校验 PASSED + 门槛 + 用户归属；页面只是入口 |
| RISK-06 | 历史 `eval_report` 无用户维度 | 老报告无法确定归属，页面若混用会误导 | 迁移只加列不回填；历史候选报告标记「归属未知」且不参与晋升校验 |
| RISK-07 | 状态变更改走记忆写入主通道后锁序/事务变化 | 写路径回归、锁冲突 | 复用既有 Conversation→Run→scope 锁序；新增转换作为记忆命令动作，不另建写路径 |
| RISK-08 | 族级暂停误伤 | 整族停止学习，影响所有用户 | 暂停只影响新 Run、可恢复、显示状态与操作者；默认不动历史数据 |
| RISK-09 | 内容修订绕过回放 | 未经验证的错误内容被注入 | 修订只能回到 PROPOSED；晋升仍要求 PASSED（或 PASSED 后人工晋升）；修订写完整审计 |
| RISK-10 | 反馈被滥用 | 正常经验被错误退休 | 反馈需要权限与幂等；只触发复核回放，不直接改状态；回放回归才退休 |
