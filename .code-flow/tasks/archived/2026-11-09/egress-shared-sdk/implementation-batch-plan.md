# 共享出口 SDK：实现批次与验证计划

本计划补充任务文件，历史任务编号保留，场景责任以 `egress-shared-sdk.scenarios.md` 为准。规划不等于代码已实现或真实链路已验收。

## 主路径

1. **TASK-009，共享计数内核**：实现公共规则、execution 和 invocation 冻结预算的一次原子判定；独立进程用可信测试身份覆盖 S-01/S-02/B-01/B-04。执行身份的真实存储和恢复仍归 TASK-006，不以其完成为内核验收前提。见 `task-009-frozen-budget-design.md`。
2. **TASK-003，故障和生命周期**：实现计量不确定时关闭准入、执行期监督、并发租约和代际守卫；E-01/B-03/B-05 的真实边界不可由单元测试代替。见 `task-003-lease-failure-design.md`。
3. **TASK-004 与 TASK-005，真实发送边界**：两者均依赖 003，可按改动冲突程度交错实施；各自保留真实探针和验收。004 接入受控 Skill 的 requests 发送路径与私有 IPC；005 接入宿主平台 Adapter 与 MCP。物理重定向、认证、握手、显式重试均各自申请新 attempt；未经声明支持的客户端不可标成已覆盖。Proxy 的响应、Retry-After 和认证语义保持原样。
4. **TASK-006，权威身份和停止**：Run/Task 的冻结快照与权威持久身份接入宿主；恢复和重领沿用 execution/invocation，换 segment 不清累计。累计耗尽时停止该脚本并回收进程组；验证 Worker 不将确定性预算错误当普通重试。S-03/E-02 必须覆盖真实 PG、Runtime/Worker、Redis 和进程/HTTP 边界。
5. **TASK-007，监控**：复用现有事件和维护路径，按 attempt 标识去重；明细、汇总及故障缺口按既定保留策略落地。计量故障和记录故障分离；无凭据、正文或完整 query 泄漏。
6. **TASK-008，统一验收**：对实际接入覆盖清单、真实 Cluster/恢复/失败注入、接口错误与监控补齐证据，运行需求终验；不可凭内核探针或单项 CI 绿色宣称整体完成。

## 实施前核对

- 旧的进程内控制器仍在使用，不能把它与共享 Redis 并列作为两个互不关联的配额来源；按接口接入顺序替换并验证无规则旁路。
- 宿主决定可信身份和规则；Skill 不持有 Redis 凭据或自行选择计量身份。目录安全化后的短 ID 可能碰撞，不作为权威计数身份。
- 连续窗口必须覆盖跨整分和区间边界；真实 Redis 时钟测试需隔离且可复现，不能调整共享 Redis 的系统时钟。
- 故障切换期间 Redis 异步复制可能丢失已确认数据；外部代际检测和阻断需要演练。无法检测的历史丢失不声称已解决。
- 先检查合入主线后的实际调用栈、snapshot 和 CI 权限；保留现有 Worker 的冻结 `execution_timeout_sec` 契约。

## CI 批量策略

先汇总当前完整 run 的所有失败并分类；对失败诊断不足的地方补证据，对确定的缺陷补实现和有区分力的测试。将任务/场景/manifest 更新、失败修复和必要的测试准备合并为可审查批次；不为单项文档或测试改动反复推送。每次完整 CI 结束后先查看全部失败再处理；通过的旧 commit 或失败重跑只证明对应版本和边界。

代码实施按当前 active TASK 和 Code Flow 上下文推进；测试按用户要求交由 CI，不将本地静态检查当功能验证。TASK-009 的未实现测试、S-02 旧证据和所有后续任务继续保持未验收状态。
