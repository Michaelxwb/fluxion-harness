## 2. 背景与目标

### 2.1 问题陈述 [必填]

| 维度 | 内容 |
|------|------|
| **问题描述** | 运行审计列表是四张表 `UNION ALL` 的平铺投影（`control.config_audit_log` + `runtime.{tool_call_audit,egress_audit,model_invocation_audit}`，`audit_query_repository.py`），一行 = 底层一条事件。一次对话在列表里出现 6~10 行（每轮模型调用 + 每次工具调用），且模型审计是**逐 attempt** 落库（`AuditedModelProvider`，重试再 +1 行）。这些行指向同一个运行详情，「关联对象」的导航完全重复；审计真正要回答的「谁、对什么、做了什么、结果如何」被执行步骤淹没。 |
| **当前替代方案** | 用户按 Trace ID / 运行 ID 手工归并同一次对话的记录；或直接忽略列表，逐条点进运行详情看链路。 |
| **触发原因** | 2026-11-17 Console 实际使用：一次对话（运行 4553659e）在审计列表占 6 行，横跨两次页面滚动，与左侧「运行审计」的检索目的不符。 |

### 2.2 目标与价值 [必填]

| 维度 | 内容 |
|------|------|
| **核心目标** | 审计列表默认按**业务操作**成行：一次对话（Run）、一次配置变更、一次出网各占一行；模型调用与工具调用作为 Run 内部步骤折叠进运行详情，同时以计数与失败摘要保留在列表行上。步骤明细仍可按需检索，导出保持全量明细。 |
| **预期价值** | 审计列表从「事件流」变为「操作流」：一次对话一行，扫描成本降到 1/N；失败在默认视图即可发现；审计留档完整性不下降（明细视图 + 导出不变）。 |

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 一次对话在默认列表的行数 | 6~10 行（随轮次增长） | 1 行 | 列表按同一 trace / run 计数 |
| 失败步骤的发现路径 | 逐行点开或看结果列 | 默认视图行内可见失败步骤摘要 | 列表行渲染断言 |
| 步骤明细可检索性 | 平铺即明细 | 不下降：类型筛选进入明细视图，字段与现在一致 | 明细视图用例 |
| 审计列表查询耗时（同等数据量） | 基线 | 不高于基线 | `EXPLAIN ANALYZE` + 集成测试 |
| Runtime 执行链路变更 | — | 0 处 | 代码改动范围 |

## 4. 功能需求

### 4.1 功能清单 [必填]

| 功能ID | 功能名称 | 功能描述 | 优先级 | 来源用户故事 |
|--------|---------|---------|--------|-------------|
| FEAT-01 | 操作视图默认粒度 | 默认一行 = 一次 Run / 一次配置变更 / 一次出网 | P0 | US-01, US-06 |
| FEAT-02 | 内部步骤列 | Run 行展示模型/工具（/出网）调用计数与失败摘要 | P0 | US-02 |
| FEAT-03 | 步骤明细视图 | 类型筛选选模型/工具调用时退化为逐条明细 | P0 | US-03 |
| FEAT-04 | 运行详情入口 | 运行 ID 打开运行详情侧栏，展示完整链路 | P0 | US-04 |
| FEAT-05 | 导出保持全量明细 | 导出不受列表视图影响 | P0 | US-05 |
| FEAT-06 | Run 级投影与聚合查询 | 分页/计数打在运行实体上，步骤计数两阶段聚合 | P0 | US-01, US-02 |

#### FEAT-01: 操作视图默认粒度

- **描述**: 默认列表一行 = 一次业务操作：Run（一次对话）、配置变更、出网。模型调用与工具调用不再单独占行。
- **验收标准**:
  - [ ] 同一 Run 的模型调用、工具调用在默认列表中合并为 1 行。
  - [ ] 配置变更与出网仍各自独立成行，字段口径不变。
  - [ ] Run 行展示：时间 + 耗时、审计类型「运行」、操作人、Agent、运行标识与来源、本轮用户消息摘要、内部步骤、执行结果。
  - [ ] 其他筛选（关键字、操作人、Agent、资源类型、执行结果、时间）在操作视图下继续生效；按步骤字段筛选时进入明细视图（见 FEAT-03）。
  - [ ] 默认视图不丢失任何现有审计记录：每条记录要么聚合进操作行，要么在明细视图可达。

#### FEAT-02: 内部步骤列

- **描述**: Run 行新增「内部步骤」列：`模型 N · 工具 N`（有出网时追加 `· 出网 N`），失败时追加失败步骤摘要（工具名 / 模型 + 错误码或错误文案）。
- **验收标准**:
  - [ ] 计数与明细视图中的记录数一致（口径见 OQ-02）。
  - [ ] 失败时摘要点名具体工具或模型，并标红；成功时不显示失败行。
  - [ ] 配置变更、出网行的内部步骤列为 `-`。
  - [ ] 无步骤的 Run（刚创建、已取消）显示 `模型 0 · 工具 0` 或空，不显示编造数据。

#### FEAT-03: 步骤明细视图

- **描述**: 当审计类型筛选选「工具调用」或「模型调用」时，列表退化为现有的逐条明细（一行 = 一次调用），并显示提示条说明当前为明细视图与返回操作视图的出口。
- **验收标准**:
  - [ ] 明细视图的字段、筛选、详情与改动前一致（Trace ID/审计 ID、时间、类型、操作人、Agent、关联对象、动作、结果）。
  - [ ] 提示条提供「返回操作视图」，恢复筛选为「全部」。
  - [ ] 分页与总数按当前视图的行语义计算，不混用两种语义（OQ-04）。

#### FEAT-04: 运行详情入口

- **描述**: 运行对象（运行 ID）点击打开既有运行详情侧栏，展示完整链路：每一步模型调用、工具调用、耗时、token、失败原因与最终回复。
- **验收标准**:
  - [ ] 运行详情不新增页面，沿用现有侧栏与时间线。
  - [ ] 从操作视图与明细视图进入的运行详情一致。
  - [ ] 侧栏内可见失败步骤（若存在）。

#### FEAT-05: 导出保持全量明细

- **描述**: 审计导出继续导出全量事件明细（四类记录），不随列表视图变粗。
- **验收标准**:
  - [ ] 操作视图下导出结果包含模型/工具/出网的逐条记录。
  - [ ] 导出筛选口径与列表筛选一致，但行粒度保持明细。

#### FEAT-06: Run 级投影与聚合查询

- **描述**: 新增 Run 级投影分支；主查询的分页与计数发生在运行实体上，步骤计数按当页运行标识批量聚合。
- **验收标准**:
  - [ ] 不使用逐行相关子查询、不对全量审计表做每页聚合（NFR-PERF-01）。
  - [ ] 租户隔离与现有投影一致（所有分支按租户过滤）。
  - [ ] 查询计划经 `EXPLAIN ANALYZE` 验证，耗时不超过基线。

### 4.2 边缘情况 [可选]

| 场景 | 预期行为 |
|------|----------|
| 定时任务 / 后台任务执行（只有 task_id，无 run_id） | 不丢失；是否与 Run 同口径聚合成「任务执行」行见 OQ-03，本期至少保证明细视图可达 |
| 同一 Run 含重试（429/5xx） | 计数与失败摘要需说明重试，具体口径见 OQ-02 |
| Run 已软删除 / 审计记录已归档 | 保持现有过滤口径，不因聚合出现空行或重复计数 |
| 步骤级筛选与操作视图并存（如关键字命中工具名） | 自动进入明细视图，并在提示条说明原因 |
| 同一时刻多条记录（分页稳定性） | 保持现有排序键（时间 + ID）的稳定次序 |

## 5. 非功能需求 [可选]

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-PERF-01 | 性能 | 默认视图查询不得慢于现状：主查询分页/计数打在运行实体；步骤计数按当页运行标识一次批量聚合；新增支撑按租户 + 时间倒序分页的索引；禁止逐行相关子查询与全量预聚合。 |

| NFR-TEST-01 | 质量 | 现有 7 个审计后端测试与 2 个审计 E2E 规格同步更新；新增聚合与视图切换的集成用例。 |

| 风险ID | 描述 | 影响 | 缓解方案 |

## 9. 开放问题（已确认）

| 编号 | 问题 | 结论 |
|------|------|------|
| OQ-01 | 模型/工具调用是否继续作为「审计类型」筛选值保留（作为明细视图入口）？ | 保留；只改默认视图，枚举不删 |
| OQ-02 | 「内部步骤」的模型计数按逻辑调用还是按 attempt（含重试）？失败摘要如何体现重试？ | 按 attempt 计数；重试以中性「重试 N」后缀展示，失败摘要只在 Run 失败时出现 |
| OQ-03 | 只有 task_id 的执行（定时任务/后台任务）是否与 Run 同口径聚合成「任务执行」行？ | 本期不做聚合，只保证明细视图可达；同口径聚合作为后续增量 |
| OQ-04 | 两个视图的 `total` / 分页语义如何定义？ | 各视图按自己的行语义计数，切换视图回到第 1 页 |
| OQ-05 | 操作行的「动作」摘要取本轮首条用户消息还是最后一条？ | 取本轮首条用户消息（`run_record.input_text` 摘要），仅展示、不参与关键字筛选、不进导出 |
| OQ-06 | 失败摘要常驻还是仅失败时出现？ | 仅失败时出现；成功行只保留计数 |
