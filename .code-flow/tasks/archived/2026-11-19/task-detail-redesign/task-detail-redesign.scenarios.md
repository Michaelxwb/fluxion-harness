# 任务详情页改版 验收场景

> **修订版本**：v1.0；状态为待实现/待人工执行，本文不代表验收已通过。

> 这是给**人工测试者**使用的验收清单，不是 E2E 代码或测试注册表。
> 每个场景保留 S-/E-/B- 编号，供 design 和 Task 的 `Scenarios` 字段引用。
> 步骤用用户能执行的界面动作描述；期望写用户可观察的结果，避免选择器和内部实现细节。
> 浏览器场景按真实构建产物、真实浏览器和真实服务执行；E2E 不是 CI 门禁。

## 公共前置

- Console / Runtime / Worker 已启动；WebChat 任务中心可打开。
- 测试账号至少有一个定时任务和一个后台任务，且任务范围授权正常。
- 定时任务已有多次运行记录（准备 24 次左右的 Fire）和至少 2 个结果文件；结果发送到 2 个企微机器人。
- 后台任务准备两类数据：
  - 有子任务：5 个子任务、4 成功、1 失败、8 个结果文件；
  - 无子任务：单次任务，8 个结果文件。
- 浏览器时区 `Asia/Shanghai`，语言 `zh-CN`；另准备 `en-US` 检查词条。
- 如需验证窄屏，使用 420×900 视口；桌面使用 1440×900。

## 测试分层建议

| 层 | 覆盖内容 | 说明 |
|----|---------|------|
| component | 布局、状态映射、分页 footer、空态、弹层开合 | 真实 React 静态渲染 + mock API，可自动化 |
| integration | Fire 字段、耗时口径、产物数、租户/软删过滤、无 N+1 | 真实 PostgreSQL / Worker 读接口 |
| manual | 视觉、真实分页交互、技术信息位置、窄屏、真实文件下载 | 真实构建产物 + 真实浏览器 + 真实服务 |

## S-01 定时任务首屏能一眼看懂

- **负责**：待 plan 分配
- **层级**：manual（视觉）/ component（结构）
- **边界**：任务已运行 24 次；最近一次成功；结果发送到 2 个企微机器人；2 个结果文件
- **前置**：公共前置已满足；任务为「进行中」。
- **步骤**：
  1. 打开 WebChat → 任务 → 定时任务。
  2. 点击目标任务，进入任务详情。
  3. 观察页头、指标卡和最近运行列表的首屏内容。
- **期望**：
  - 页头显示任务名、`进行中`、`每 5 分钟运行一次 · 下次运行 今天 17:40`。
  - 四张指标卡显示：下次运行、最近一次（成功/用时/文件数）、结果发送到（2 个机器人）、运行次数。
  - 最近运行每行只有一个用户状态（成功/失败/进行中/等待中/已跳过），不再出现「已创建执行 + 已完成」双标签。
  - 首屏不出现 Revision、Snapshot、sha256、MIME、Agent UUID、原始 JSON、夏令时空提示。
- **实际结果**：待执行

## S-02 最近运行分页与右侧详情联动

- **负责**：待 plan 分配
- **层级**：manual（交互）/ component（分页状态）
- **边界**：共 24 次运行；每页 6 条；跨 4 页
- **前置**：任务有 24 次运行，且第 2 页有可查看的执行。
- **步骤**：
  1. 打开定时任务详情，观察运行列表和分页。
  2. 点击分页「下一页」。
  3. 在新一页点击一条运行。
  4. 再点击「上一页」。
- **期望**：
  - 列表默认 6 条；分页显示「显示第 1-6 条，共 24 条」和「1 / 4」，上一页禁用。
  - 翻页后列表更新为第 7-12 条，页码变为「2 / 4」。
  - 点击某条运行后，左侧行高亮，右侧显示该次运行的结果、文件、发送结果；左右两栏等高（桌面端）。
  - 右侧内容不足时底部操作区贴底，列表分页贴底；页面不出现明显高度跳动。
  - 返回第 1 页时，选中规则稳定：当前选中仍在页内则保留，否则选当前页第一条有执行的运行。
- **实际结果**：待执行

## 场景编写约定

- 一个场景只验证一个用户可理解的目标。
- 步骤编号从 1 开始，按真实操作顺序编写。
- 期望写「用户看到什么/数据变成什么」，不写内部函数名或测试断言。
- 场景不生成 manifest、不登记执行结果、不阻断 `task finish` 或 `task archive`。
- 需要机器执行的快速回归放在 Task 的 `### Tests`；E2E 和全量回归留在 CI。
