## 2. 背景与目标

### 2.1 问题陈述

| 维度 | 内容 |
|------|------|
| **问题描述** | ① 平台设置 `locale.default_locale` 没有约束 Agent 的回复语言，也没有接进 Run 失败收尾；en-US 租户会看到中文失败文案。② 失败收尾把审计证据（`RUN_NO_PROGRESS`、`PLATFORM_AUTH_REJECTED`、内部平台 key、平台原文）直接拼成用户消息，用户不知道“发生了什么、该找谁”。③ 新建定时任务必须显式给 IANA 时区；服务部署地的平台时区没有成为默认值。④ `.env` 仍保留已失效的 `DEFAULT_LOCALE`。 |
| **当前替代方案** | 失败文案仅靠 `render_finalization` 的固定模板；没有工具/平台错误码的直白描述；Agent 回复语言完全由模型自行判断；定时任务时区由模型或用户显式提供。 |
| **触发原因** | 2026-11-20 一次 `PLATFORM_AUTH_REJECTED` Run 的用户可见消息只有错误码和平台原文；同时系统设置页的英文/时区设置对 Agent 输出没有完整生效。 |

### 2.2 目标与价值

| 维度 | 内容 |
|------|------|
| **核心目标** | 让系统设置真正成为 Agent Runtime/Worker 的默认语言与默认时区来源；让用户可见失败消息同时具备“直白描述 + 可排查错误码”。 |
| **预期价值** | 降低用户自助排查成本；减少“平台码直接甩给用户”的体感问题；让国际化租户的 Agent 输出语言一致；让定时任务少一步时区确认。 |

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 用户可见失败消息含直白描述 | 0（仅码/证据） | 100% 失败终态 | 收尾渲染契约测试 + 人工验收 |
| en-US 租户 Agent 默认回复英文 | 不稳定 | 新 Run 默认英文 | 验收场景 |
| 新建 Draft 未指定时区时使用平台默认 | 0 | 100% | 集成/单元测试 |

## 4. 功能需求

### 4.1 功能清单

| 功能ID | 功能名称 | 功能描述 | 优先级 | 来源用户故事 |
|--------|---------|---------|--------|-------------|
| FEAT-01 | Agent 默认回复语言 | 每个新 Run 开始时读取当前 `locale.default_locale`，作为系统提示的默认回复语言并在本 Run 内固定 | P0 | US-01 |
| FEAT-02 | 用户语言覆盖 | 当前消息显式要求优先；长期偏好复用 memory 的 `language` predicate | P0 | US-02 |
| FEAT-03 | 失败消息直白描述 | 用户可见失败文本 = 直白描述 + 下一步 + 技术信息（错误码/Run ID） | P0 | US-03 |
| FEAT-04 | 平台文案 locale 一致 | 失败收尾、IM/Worker 固定文案按租户 `default_locale` 渲染，移除硬编码中文 | P0 | US-01/US-03 |
| FEAT-05 | 定时任务默认时区 | 新建 Draft（含从 Run 提升）未指定时区时读取当前平台 `default_timezone` 并显式存储；更新 Draft 仍要求完整配置；已建 Schedule 保持原值 | P0 | US-04 |
| FEAT-06 | 配置与规范收口 | 删除失效 env 键；澄清设置页作用域；修订与代码矛盾的 Spec | P1 | US-05 |

#### FEAT-01: Agent 默认回复语言

- **描述**: 每个新 Run 在执行开始时读取当前 `locale.default_locale`，写入 Run 策略并在系统提示中声明“默认回复语言”；模型默认按该语言回复。同一 Run 内固定，避免对话中途切换语言。
- **验收标准**:
  - [ ] 平台设置为 `en-US`，新 Run 未收到任何语言要求时，Agent 默认用英文回复；`zh-CN` 时默认中文。
  - [ ] 修改平台设置影响后续新 Run；已创建 Run/恢复 Run 使用该 Run 开始时的值，不中途切换。
  - [ ] 该默认值不依赖模型自行猜测或依赖 `current_time` 等工具调用。

#### FEAT-02: 用户语言覆盖

- **描述**: 当前用户消息中的显式语言要求优先于平台默认；用户表达的长期语言偏好通过现有 memory `language` predicate 记录并复用，不新增记忆子系统。
- **验收标准**:
  - [ ] 平台默认 `en-US`，用户说“请用中文回答”时，本轮用中文回复。
  - [ ] 用户说“以后都用中文”时，Agent 通过现有 `remember` 流程提出 `language=zh-CN` 偏好；用户确认后，后续 Run 默认中文。
  - [ ] memory 中已有 `language` 偏好时，平台默认被该偏好覆盖；当前消息显式要求又覆盖 memory。
  - [ ] memory 写入被禁用时，仅当前消息的显式要求生效，不持久化。

#### FEAT-03: 失败消息直白描述

- **描述**: 用户可见失败消息分两层：先给直白描述与下一步，再给技术信息（终止码、工具/平台错误码、Run ID）。错误码保留，供用户提供给开发排查。
- **验收标准**:
  - [ ] `PLATFORM_AUTH_REJECTED` 失败时，正文说明“平台登录失败/凭据或签名问题”并给出下一步；技术信息保留 `PLATFORM_AUTH_REJECTED` / `RUN_NO_PROGRESS`。
  - [ ] 预算/截止期限/模型不可用/沙箱不可用等码族各有可读描述；未知码回退到通用描述，但仍展示错误码。
  - [ ] 首次确定性失败不再显示“重复失败”这一与事实不符的标签。
  - [ ] 不再把 `platform_sessions: key=...` 这类内部证据串作为正文主句；平台 key、HTTP 状态、脱敏原文只出现在技术信息/Console 详情。
  - [ ] 失败收尾保持确定性：同一 facts 渲染同一文本，不新增模型调用。

#### FEAT-04: 平台文案 locale 一致

- **描述**: Run 失败/取消收尾、IM 状态文案、后台任务投递文案统一按租户 `default_locale` 渲染；移除用户可见的硬编码中文常量。
- **验收标准**:
  - [ ] en-US 租户的失败收尾、取消收尾、IM“任务已受理/已停止/断流”文案为英文；zh-CN 保持中文。
  - [ ] IM 终态空正文兜底使用租户 locale，而不是进程级 `zh-CN`。
  - [ ] 失败技术信息中的错误码不翻译；描述文本按 locale 取词条。
  - [ ] Console 前端界面语言/显示时区不在本需求范围，行为不变。

#### FEAT-05: 定时任务默认时区

- **描述**: 新建 Schedule Draft（含 `promote_run` 从 Run 提升）未指定时区时，读取**当前**平台 `locale.default_timezone`（方案 A；不复用 Run 创建时冻结的旧值），把具体 IANA 时区显式存进 Draft 并在确认卡片展示；用户可指定其他时区覆盖；更新 Draft 仍要求完整配置（含时区），避免未指定时被平台默认静默改写；已建 Schedule 保持创建时存储的时区。
- **验收标准**:
  - [ ] 平台默认 `Asia/Shanghai`，用户说“每天 9 点”且未指定时区，Draft 的 `timezone=Asia/Shanghai`，确认卡片可见。
  - [ ] Draft 创建时读取当前平台设置；即使当前 Run 在设置变更前创建，也使用最新值。
  - [ ] 用户明确说“按纽约时间”，Draft 使用 `America/New_York`。
  - [ ] 更新 Draft 未提供时区时明确报字段错误；更新要求完整配置（含时区），不静默用平台默认。
  - [ ] 已创建的 Schedule 保持创建时存储的时区；后续平台时区变更不自动改写（B 方案的调度器重算不在本次范围）。
  - [ ] 平台时区非法或不可用时明确失败，不用服务器本地时区/UTC 静默兜底。
  - [ ] 定时任务仍按本地壁钟计算，DST 规则不变。

#### FEAT-06: 配置与规范收口

- **描述**: 清理失效配置，澄清系统设置作用域，修订与当前代码不符的 Spec。
- **验收标准**:
  - [ ] `.env` 中删除 `DEFAULT_LOCALE`；`.env.example` 保持无迁移键（现有 `tests/test_configuration_convergence.py` 继续通过）。
  - [ ] 系统设置 `locale` 分组有说明：用于 Agent 回复与后台任务投递，控制台界面语言不受影响。
  - [ ] `harness-arch` 的失败跟进口径与确定性收尾代码一致；`harness-time` 允许“平台配置默认时区”；`harness-i18n` 覆盖 Agent 默认语言/用户覆盖/错误码描述；`harness-project-platform`、`harness-snapshot`、`harness-im` 同步修订。
  - [ ] 所有 Spec 修改通过 Task 的 Spec Delta 落地，不直接改已接受规则文本。

### 4.2 边缘情况

| 场景 | 预期行为 |
|------|----------|
| 平台默认语言为 en-US，用户用中文提问且未要求中文 | 默认英文回复；用户显式要求后切换 |
| 用户说“这次用英文”，未说“以后” | 只影响本轮；不自动写入长期偏好 |
| memory 中 `language` 与当前消息冲突 | 当前消息优先 |
| 失败工具无错误码 / 未知码 | 通用直白描述 + “错误码：UNKNOWN/原码”技术信息 |
| 平台默认时区在 Draft 创建后被修改 | 已建 Draft/Schedule 保持创建时存储值；后续新建/修改 Draft 使用新值 |
| Draft 更新时未提供时区 | 明确字段错误；更新要求完整配置（含时区），不静默用平台默认 |
| 定时任务显式时区非法 | 明确字段错误，要求提供合法 IANA 时区 |

## 5. 非功能需求

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-I18N-01 | 国际化 | 用户可见失败描述、IM/Worker 固定文案均支持 zh-CN/en-US；错误码本身不翻译。 |
| NFR-DET-01 | 确定性 | 失败收尾仍由平台确定性渲染；同一 facts 输出同一文本，不依赖模型可用性。 |
| NFR-SEC-01 | 安全 | 平台原文/凭据/headers 不进用户正文；技术信息只保留已脱敏、有界的码与平台原因。 |
| NFR-PERF-01 | 性能 | 语言在每次新 Run 开始时读取一次并在本 Run 固定；时区在 Draft 创建/修改时读取一次；执行期不新增每轮读取，不增加每轮模型调用。 |
| NFR-COMPAT-01 | 兼容性 | 既有 Run/Schedule 不改写、不回填；新策略只影响新 Run/新 Draft。 |

## 6. 范围与边界

| 类别 | 内容 |
|------|------|
| **范围（In Scope）** | Agent Runtime/Worker 的默认回复语言、用户语言覆盖（复用 memory）、失败/取消收尾文案、IM/Worker 平台固定文案、定时任务 Draft 默认时区、失效 env 清理、相关 Spec 修订。 |
| **非范围（Out of Scope）** | Console 前端界面语言与页面时间显示；Console 概览自然日统计时区（保持现状，若要改另开需求）；已建 Schedule 随平台时区变化自动重算（B 方案，需调度器重算 `next_fire_at`）；自动语言识别/机器翻译；新增记忆子系统；模型微调；控制台设置页的大改版。 |
| **前置假设** | `locale.default_locale` / `locale.default_timezone` 是按租户持久化的平台设置且已校验；memory taxonomy 已含 `language` predicate；`remember` 写入需用户确认；新 Run 会把 `default_locale` 固定进本 Run 策略；Draft 创建时读取当前 `default_timezone` 属于 authoring 输入默认值，不改变执行期冻结规则；`.env.example` 已由配置收敛测试守护。 |

## 7. 依赖与风险

### 7.1 项目依赖

| 依赖方 | 依赖内容 | 风险等级 |
|--------|----------|---------|
| Agent Runtime | `policy_json` 增加 `locale.default_locale`；失败收尾渲染器；任务工具默认时区 | 中 |
| Agent Core | 系统提示的回复语言段；失败 facts 渲染 | 中 |
| Agent Worker / IM Gateway | 统一 locale 取数；移除硬编码中文 | 中 |
| Memory | 复用 `language` predicate 与确认流程 | 低 |
| Console Platform | 设置页作用域说明 | 低 |

### 7.2 风险识别

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|---------|
| RISK-01 | 模型不严格遵守系统提示的语言要求 | 默认语言不稳定 | 显式系统提示段 + 验收场景；不以 prompt 作为唯一保障的码/文案仍由平台渲染 |
| RISK-02 | 错误码族映射维护成本 | 新码无描述 | 按 `PLATFORM_*`/`MODEL_*`/`SANDBOX_*`/`TOOL_*` 等族给回退，未知码仍显示原码 |
| RISK-03 | `policy_json` 增加字段影响快照兼容 | 旧 Run 恢复 | 缺失时回落 schema 默认；快照版本按现有规则递增 |
| RISK-04 | 平台时区变更后已建任务不跟随 | 触发时间与部署地不一致 | Draft 卡片显式展示时区；用户可编辑/重建；如后续要求老任务跟随，另开需求做调度器重算 |
| RISK-05 | 移除 IM 硬编码文案影响既有快照测试 | 测试波动 | 同步更新契约测试与人工场景 |
