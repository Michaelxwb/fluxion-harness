# 聊天中的平台限流提示设计

> v0.2 · 2026-11-23 · 待评审 · PRD FEAT-01

## 需求与范围

WebChat 中的 `execute` 因平台 HTTP 出站滑动窗口限流中断时，显示普通助手回复，并明确查询未完成。复用现有助手消息、Run 完成和附件交付通道。并发限流、累计预算、上游自行返回的 HTTP 429、定时任务和 Console 配置沿用各自的现有语义。

## 技术设计

### 1. 在出站与脚本边界确认原因

- 准入 Broker 在受控平台接口被滑动窗口规则拒绝时，在当前调用内登记该次拦截，并在拒绝响应中携带同一尝试标识。标识由宿主生成，作用域限定于本次调用，正文不携带目标 URL、请求头或凭据。继续使用现有出站审计记录拒绝，超限请求在 HTTP 发送前终止。
- IPC 客户端在类型化拒绝异常上保留尝试标识。现有 Python 启动器遇到直接冒泡的该类型窗口限流异常时，通过受限的结构化退出协议回传原因和标识。沙箱执行器须同时核对保留退出状态、结构化记录和本次 Broker 的匹配拒绝，才能在执行结果上附加确认的限流原因。退出码、脚本输出、历史审计或单独一次拒绝均不足以完成判定。调用结束即释放匹配状态。
- Smoke Skill 对该类型窗口限流透传异常，让原测试路径进入提示分支。脚本如果在内部完全吞掉异常再以普通退出码失败，因果关系无法确认，仍走常规脚本失败。脚本捕获限流后成功完成时，保留成功结果。若结果实际为普通异常、超时、取消、累计预算耗尽或依赖故障，则优先保留真实结果。

### 2. 按普通助手回复结束聊天轮次

- Runtime 将已确认的限流写成类型化工具结果，工具事实保留“查询受限”和可交付附件引用。该状态与业务成功、通用脚本失败均有区别。工具完成事件、审计和导出保留状态及原因。
- Runner 在当前已启动批次结算后读取该结果，进入专用的正常回复收尾。已启动调用的结果照常登记，首个确定性失败以及取消等现有终止语义优先。单纯窗口限流时停止派发后续工具，在剩余轮次预算内由模型利用已结算结果生成一次不带工具的回答。保留本轮已输出的正文，把补充回答与本地化提示以增量追加，终态记录完整正文。模型补答不可用时，保留已输出正文并追加提示。中断恢复沿用已持久化的工具结果和既有身份检查，避免重跑已确认的查询。
- 默认文案为「平台查询触发频率限制，请稍后再试」。可随消息交付本轮已注册且确认可用的部分结果，并注明受限部分仍未完成。只展示现有交付链路可验证的结果；成功的 HTTP 尝试、未登记的文件和任意脚本输出均不足以生成部分结果。普通消息的完成状态描述聊天已回复，工具状态继续反映查询受限。

## 验收与回归

人工验收见 [验收场景](chat-egress-rate-limit-notice.scenarios.md) 的 S-01、E-01、B-01 和 B-02。使用本地真实构建的 WebChat、Runtime、PostgreSQL、Redis 与 Smoke 模拟平台；定向用例验证内部契约，手工验收核对浏览器、出站审计与上游请求记录。

后续任务声明相关定向用例。建议在 `tests/sdk/test_egress_ipc.py` 核对拒绝标识和上游收包，在 `tests/agent_core/test_sandboxed_skill_executor.py` 核对因果匹配、冒充和混合错误，在 `tests/agent_runtime/test_skill_tools.py` 与 `tests/agent_core/test_runner.py` 核对工具结果、回合收尾、恢复及无重试，并在 `tests/skills/test_smoke_platform.py` 覆盖 Smoke 异常透传。
