# PRD：聊天中的平台限流提示

> 版本 v0.2 · 2026-11-23 · 评审中

## 1. 文档控制

v0.1 根据本地 Run 核查和用户确认的处理方向起草。

v0.2 按人工复测反馈明确限流提示追加在正常正文后。

## 2. 背景与目标

本地 Smoke 测试 Run `d13a5632-0e2d-4103-9389-b97924800783` 中，前三个 GET 返回 HTTP 200，第四个命中出站滑动窗口限流。该请求在外发前被拦截，Skill 退出码为 1，整个聊天 Run 以 `FAILED / RUN_NO_PROGRESS` 结束。

用户应收到一条可读的普通助手消息，知道哪项查询受限、稍后可以重试，以及本轮有哪些已确认结果可用。

## 3. 用户与场景

**US-01** 作为在聊天中查询平台数据的用户，我希望遇到短期限流时能读到明确的提示，并拿到已可用的部分结果。

## 4. 功能需求

**FEAT-01 · 窗口限流提示**（P0，US-01）

- [ ] `execute` 调用命中平台接口的滑动窗口限流并因此无法完成查询时，聊天保留已输出的正文，并让助手根据可用结果正常作答，最后追加简短提示，例如「平台查询触发频率限制，请稍后再试」。仅因该限流结束的聊天 Run 可正常完成，同时工具结果明确记录查询受限。
- [ ] 已交付且可用的部分结果可以随提示展示，并说明受限部分仍未完成。只有 HTTP 200 审计记录时，不据此生成查询结果。
- [ ] 受限请求不外发，出站审计保留拦截和原因。本轮不因提示立即重试同一个受限查询。
- [ ] 正常查询仍交付结果。鉴权失败、计量依赖故障、累计预算耗尽和一般脚本错误继续按各自的失败语义处理。脚本输出中的限流字样不足以触发提示。

## 6. 范围与边界

首版覆盖聊天 Run 中通过 `execute` 发起的平台 HTTP 调用，以本地 WebChat 和 Smoke 模拟平台验收。并发上限、外部平台自行返回的 HTTP 429、定时任务和改动管理端规则配置均在本需求范围之外。

## 7. 依赖与风险

设计阶段确认出站层到 Runtime 的可信限流事实如何传递，以及 Skill 同轮发生其他错误时如何保留实际失败。验收同时观察聊天消息、Run 状态、出站审计和模拟上游请求次数。
