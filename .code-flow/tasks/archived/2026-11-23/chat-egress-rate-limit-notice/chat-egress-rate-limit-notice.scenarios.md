# 聊天中的平台限流提示验收

使用本地构建的 WebChat、Console 和 Smoke 模拟平台，使用测试账号及测试租户。每个场景开始前等待前一次限流窗口结束，按场景准备独立测试数据。执行后记录 Run ID、聊天结果和对应的出站审计。

## S-01 正常平台查询

- **目标**：确认窗口内有额度时可以正常查询。
- **负责**：功能验收人。
- **前置**：Smoke 测试 Skill 已安装并可执行，目标接口的规则允许本次查询。
- **步骤**
  1. 在 WebChat 请求列出 Smoke 测试目标。
  2. 查看聊天回复和 Console 中的本轮运行记录。
- **期望**：聊天显示查询结果，运行正常完成，相关出站请求在模拟平台有对应记录。
- **实际结果**：待执行。

## E-01 同一轮触发窗口限流

- **目标**：确认限流后仍能看到普通助手提示，超限请求未到达上游。
- **负责**：功能验收人。
- **前置**：给 Smoke 目标接口配置足够长的窗口和较低频率上限，使用测试访问把目标接口消耗到上限。
- **步骤**
  1. 在窗口结束前，在 WebChat 请求同一 Smoke 目标查询。
  2. 查看聊天回复、Console 运行记录和出站审计，并对照 Smoke 上游访问记录。
  3. 等窗口结束后，再发一条消息查询同一目标。
- **期望**：第一次显示普通助手消息，已有正文保留在原处，限流提示追加在正文后。聊天轮次正常完成，审计显示窗口限流拦截，本轮没有再次尝试同一受限查询，限流请求没有到达上游。窗口结束后的新查询正常交付结果。
- **实际结果**：待执行。

## B-01 限流前已有可交付结果

- **目标**：确认用户可以保留已产出的部分结果。
- **负责**：功能验收人。
- **前置**：准备测试 Skill，先产出可登记的结果文件，再调用已达到窗口上限的 Smoke 接口。
- **步骤**
  1. 在 WebChat 请求执行该测试 Skill。
  2. 查看提示和附件，打开附件并核对内容。
- **期望**：助手在正文中说明已获得的结果，末尾提示剩余查询受限，已确认的文件可打开。本轮只展示实际交付的结果。
- **实际结果**：待执行。

## B-02 真正的脚本故障继续报错

- **目标**：确认同轮出现窗口拒绝时，独立脚本故障仍有正确反馈。
- **负责**：功能验收人。
- **前置**：准备测试 Skill，捕获已达窗口上限的 Smoke 请求异常后，触发独立的脚本错误。
- **步骤**
  1. 在 WebChat 请求执行该测试 Skill。
  2. 查看聊天消息、运行结果和出站审计。
- **期望**：聊天展示脚本失败，审计能看到先前发生的限流拦截，失败原因仍指向实际脚本错误。
- **实际结果**：待执行。
