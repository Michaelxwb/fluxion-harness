# PRD：会话上下文保留（token 历史预算、唯一裁剪与“继续”）

> v0.5 · 2026-11-24 · 评审中

## 1. 文档控制

v0.1 基于内网 WebChat 实测（2026-11-23 10:35–11:08 同一会话）与代码走查起草。

v0.2 按评审意见改为**不新增模型配置**：历史预算以平台设置的 token 档位表达，模型定义保持现状。

v0.3 按代码复核结论重构：**装配只读、请求边界只裁一次、保头保尾、摘要只覆盖完整区间、预算覆盖当前回合、“继续”不自动绑定单候选**；同时把 `compaction` 分组从 15 个叶子收缩为 4 个叶子。设置页其余分组的精简另立需求 `settings-page-simplification`，本需求不重复。

v0.4 按评审结论改为**开发阶段直接删除不兼容数据**：不写设置与 Agent 覆盖的数据迁移，不写反向迁移，旧 revision 一并清空。

v0.5 收敛设计与需求：

- **删除 `snip` 与 `micro` 两套固定口径**，不再保留按组数选择/改写内容的层；压缩只剩“摘要（可选）+ 请求边界预算裁剪”；
- 摘要材料只覆盖一个**连续 seq 区间**，摘要替换只替换这个区间，**头部锚点和尾部最近历史不受影响**；
- 旧 `CONTEXT_SUMMARY` 的 coverage 不可信，必须随不兼容数据一起清理，不能让新代码继承旧空洞；
- Worker 与 Runtime 共用严格冻结解析和预算裁剪；Worker 没有持久摘要 coverage，材料按任务历史全部 older 处理；
- 删除 `round_budget_bytes` 后，**整轮工具结果外置预算由 `history_budget_tokens` 派生**，不新增配置叶子；
- 不做兼容性改造：旧键、旧 policy、旧摘要、旧平台设置一律不解析。

## 2. 背景与目标

内网实测：第 1 轮给出需求（重构 daily-duty-report-mssp 接入层），第 2 轮补充 6 条约束，第 3 轮问“为啥失败了”，第 4 轮说“继续”——助手答非所问，前两轮的结论全部丢失。

代码走查定位到两类互相独立的原因：

1. **历史在进入请求前被固定条数/组数砍掉**：取数窗口（`budget × 4` 事件）、装配期工具回合上限、请求期消息条数、`snip` 的固定组数阈值。四者都与内容实际大小无关；一个工具型回合是 7~60 条消息，所以 3~5 轮即失效。摘要层默认关闭、旧工具结果降级默认关闭，真正生效的只有“按条数/组数静默或半静默删除”，模型只能看见一段从中间开始的历史，于是诚实地回答“我没有之前的上下文”。
2. **裸“继续”被任务线索恢复流程截获**：平台把线索清单直接当作助手回复返回，本轮模型根本未被调用。

此外还确认了两个会放大故障的代码事实：

- `snip` 本身默认开启，`max_groups=50`、`keep_head_groups=3`、`keep_tail_groups=20`，也是与内容大小无关的固定上限；
- 摘要的 `coverage_seq` 是单点最大 seq，不是“已完整摘要的区间”。装配侧只要在摘要前截断，就可能把未摘要的记录也宣称覆盖，形成永久空洞。

目标：

- 历史预算以 token 为单位、可在系统设置里配置；与内容大小无关的固定截断全部移除；
- 只有真正超出预算时才裁剪，且裁剪对模型与审计可感知；
- 预算足够时，请求包含会话此前全部轮次；预算不足时，**保头保尾**，首个用户目标固定保留，中间明确省略；
- 摘要只处理从 `covered` 起的连续区间，替换时保留头部和尾部，不产生 coverage 空洞；
- “继续”不再吞掉模型回合，也不再自动替用户选择旧任务；
- `compaction` 设置从 15 项收缩为 4 项；其他设置页精简不在本需求内。

**成功指标**

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 连续 6 轮工具型对话后，第 1 轮事实的可召回率 | 0（实测第 6 轮已不在请求里） | 100%（预算内；预算外由头部锚点或摘要 user_goal 承载） | 集成场景：真实 PostgreSQL + 真实历史装配 + 模型桩断言收到第 1 轮消息 |
| 与内容大小无关的固定**截断/选择**上限数量 | 4（snip、按条数、按回合、micro 固定组数） | 0 | 契约/单测 + 代码走查；`snip`/`micro`/条数/回合全部删除；头部锚点、分页读取和最近往返保护不属于截断/选择上限 |
| 无标记裁剪次数 | 每次预算触发 | 0 | 请求断言 + `CONTEXT_COMPACTED` 审计 |
| 摘要 coverage 空洞数量 | 事件窗口触发时可能 > 0；旧摘要不可信 | 0 | 新摘要 `covers_up_to_seq` = 材料末条；旧摘要清理后无旧 coverage |
| 裸“继续”进入模型回合的比例 | 0 | 100% | 集成场景断言执行段被调用 |
| `compaction` 设置叶子数 | 15 | 4 | schema/Console catalog/设置页契约测试 |

## 3. 用户与场景

**US-01** 作为在 WebChat 里连续多轮提需求的员工，我希望助手始终记得前几轮定下的需求与结论，不要在第 4 轮开始重新问一遍。

**US-02** 作为需要助手做多次工具调用的员工，我希望历史按内容实际大小计算，而不是一次工具调用就吃掉一整轮记忆。

**US-03** 作为管理员，我希望在系统设置里只用一个 token 预算调整历史，不用理解条数、回合数、组数、预览长度等实现细节。

**US-04** 作为排查问题的开发/运维，我要能从 Run 事件里看到本次请求是否发生过裁剪、裁掉了多少、保留起点在哪里。

**US-05** 作为正在让助手干活的用户，我说“继续”时希望助手接着干，而不是弹出一份无关的任务清单，也不是被自动带去另一个旧任务。

**US-06** 作为管理员，我不希望在“上下文压缩”里看到十几个互相牵制的调参项；我只需要预算、摘要开关、摘要模型和工具结果外置阈值。

## 4. 功能需求

**FEAT-01 · 历史预算与压缩配置收缩**（P0，US-03、US-06）

- [ ] 系统设置的上下文压缩分组只保留 4 个叶子：`history_budget_tokens`、`summary.enabled`、`summary.model_ref`、`tool_result.persist_threshold_bytes`。
- [ ] 删除 `snip.*`（4）、`micro.*`（2）、`history_budget_messages`、`max_history_tool_rounds`、`summary.threshold_bytes`、`tool_result.round_budget_bytes`、`tool_result.preview_head_bytes`、`tool_result.preview_tail_bytes`。
- [ ] `history_budget_tokens` 是正整数且有上限；非法值在保存时被字段级拒绝。上限同时受 `HISTORY_BUDGET_TOKENS_MAX` 与部署最小窗口约束。
- [ ] 预算随 Run/Task 快照冻结；new / resume / continuation 与 Agentic Task 使用同一份冻结值，执行期不重读设置。
- [ ] Agent 级覆盖沿用现有的 `runtime_config.budget.compaction` 合并口径；旧键不保留兼容解析。
- [ ] 预算语义是**保守估算 token**：1 token ≈ 1 UTF-8 字节 + 每条消息协议开销，与现有 `conservative_input_estimate` 同口径，不是 `bytes/3`。
- [ ] 工具结果的整轮外置预算由 `history_budget_tokens` 派生，不再单独配置；单条外置阈值仍是 `persist_threshold_bytes`。预览头尾由该阈值按固定比例派生，并受代码常量上限约束。
- [ ] Runtime 与 Worker 共用同一个严格冻结解析；缺键、未知键或旧键都必须显式失败，不回落默认值。

**FEAT-02 · 装配按预算读取，不做裁剪**（P0，US-01、US-02）

- [ ] 历史装配按事件序号分页取值，直到填满预算读取上限或取尽；不存在固定的事件条数、工具回合或消息条数上限。
- [ ] 装配只读：不删消息、不生成省略标记、不推进摘要 coverage；裁剪只在请求边界发生一次。
- [ ] 装配必须同时取到**头部锚点**（未被摘要覆盖时，会话第一个用户目标及其后的首个 assistant 组）和尾部最近历史；不能只按 seq 倒序取尾部。
- [ ] 摘要材料以**连续 seq 区间**表达，从可信摘要的 `covered_seq` 之后开始；材料不包含当前用户消息，不包含 pinned 的生效 Skill 组。
- [ ] 只在组边界切入：assistant 工具声明与其工具结果成对保留，不产生孤儿 `tool` 消息。
- [ ] 受保护前缀（系统提示、记忆注入、摘要前缀、resume hint）与当前用户消息永不因预算被裁。
- [ ] 预算足够时，请求必须包含会话此前全部轮次；“聊到第 N 轮就丢前文”不再存在。

**FEAT-03 · 请求边界唯一裁剪，裁剪可见**（P0，US-04、US-01）

- [ ] 裁剪只在请求构建缝发生一次，输入是完整的 `ContextPlan`；不存在第二个按条数/组数的裁剪点，也不存在 `snip`/`micro` 这类第二套内容选择规则。
- [ ] 保留策略是**保头保尾**：受保护前缀、头部锚点、当前用户消息、最近一次完整工具往返及其后的消息永不裁；从旧到新丢中段，不拆组。
- [ ] 预算同时约束 `older`、`pinned`（当前用户组/生效 Skill 组）与当前回合的 `working`；`prefix` 不计入预算。当前回合中间的旧工具往返可以被省略，但当前用户消息和最近一次完整往返必须保留。
- [ ] 当且仅当有历史记录未进入请求时，请求中出现一条确定的省略标记，写明被省略的条数（或“至少 N 条”）；未发生裁剪时不得出现该标记。
- [ ] 同一时刻落一条压缩审计事件：触发的层、保留起点、丢弃条数、裁剪前后的估算量。
- [ ] 摘要只对从 `covered_seq` 起的**连续材料区间**做材料；`covers_up_to_seq` 只推进到实际材料末条，不覆盖当前用户消息。摘要成功时只替换该材料区间，头部锚点和尾部最近历史继续保留。pinned 组不进入材料；其 seq 由 `protected_event_ids` 保留，不视为 coverage 空洞。
- [ ] 材料覆盖全部未摘要历史时，尾部由摘要承载；只有材料被预算截断、存在独立尾部时，才要求保留原始尾部。
- [ ] 摘要只在历史区/材料超预算或存在缺口时触发；仅当前回合超预算时只裁剪当前回合，不调用摘要模型。
- [ ] 同一材料区间已经摘要过时复用缓存摘要，不重复调用摘要模型。

**FEAT-04 · “继续”交给模型**（P0，US-05）

- [ ] 裸“继续/接着/恢复/续接”及带主题形式，在存在进行中会话时必须进入模型回合；模型能看到该用户消息与按需附加的任务线索。
- [ ] 首次“继续”只提供候选线索作为上下文提示，**不得自动绑定**任何候选；仅当用户明确选择既有候选（编号、key 或唯一标题）时，才按原语义绑定 resume 引用继续。
- [ ] 无候选项时不得用“没有可用的任务线索”之类的平台话术顶替模型回答。
- [ ] 记忆确认续跑（MEMORY_CONFIRMATION）的既有失败语义不变，不因本需求被削弱。
- [ ] 候选标题只作为未确认数据注入，必须定界、转义、截断；不得以 SYSTEM 指令口吻授予执行权限。

**FEAT-05 · 不兼容数据的清理**（P0）

- [ ] 本需求不提供数据迁移，也不提供反向迁移：开发阶段的旧压缩配置、旧 policy 与旧摘要直接删除/失效。
- [ ] **平台设置整份重置**：清空 `control.platform_setting` 的全部版本行（全租户、全 revision；所有分组回到 schema 默认），并清理对应的平台设置幂等回执。这是开发阶段的全量重置，不是只清 `compaction`。
- [ ] `control.agent_definition.runtime_config_json` 删除 `budget.compaction` 整个块；其他 runtime_config 原样保留。
- [ ] **旧 `CONTEXT_SUMMARY` 全部清理**：旧 coverage 是单点最大 seq，可能宣称覆盖未读历史；新代码不解析旧摘要，也不能让它继续作为 `covered_seq`。
- [ ] 上述平台设置重置与旧摘要清理是发布 runbook 的一次性操作；产品代码不新增删除版本行/摘要事件的 API，代码侧只做严格解析与 fail-closed。
- [ ] 旧 `policy_json` 不保留兼容解析；发布前排空在途 Run/Task，旧终态快照只作审计。
- [ ] 旧键残留时由既有 fail-closed 解析直接报错（“平台设置含未知配置键”），不新增检测代码。
- [ ] 配置清单、i18n、Console catalog、Spec Delta 与测试同步更新；Worker 同步删除旧压缩解析。

### 4.2 边缘情况

| 场景 | 预期行为 |
|------|----------|
| 单条消息本身超过预算 | 至少保留当前回合（当前用户消息 + 最近一次完整工具往返）；更早历史省略并写标记；记录超预算告警 |
| 当前回合有数十次工具调用 | 写入侧按派生整轮预算把最大结果外置；请求边界仍保护最近一次完整往返；更早中段省略；不拆组、不产生孤儿 tool |
| 装配/摘要/估算/审计写入失败 | 压缩层退化为“不裁剪”，保留已装配的完整历史，记录 warning 与 metric，Run 不失败；首屏历史读取失败按现有 Run 失败语义显式失败 |
| 摘要已存在 | 摘要前缀按受保护前缀处理，预算只作用于其后的对话区；旧摘要必须先清理 |
| 摘要启用但装配被预算截断 | 材料只取从 `covered` 起的连续区间（≤ 预算），coverage 推进到该区间末尾；摘要替换只替换该区间，头部与尾部保留；剩余缺口继续写标记 |
| 预算小于单条记录 | 仍以当前回合为准，标记说明更早历史不可用，并留下可观测告警 |
| 预算配置非法 | 保存时字段级拒绝；冻结值严格解析失败显式报错，不回落到默认值 |
| 旧摘要残留 | 不得作为 `covered_seq`；发布清理断言 `CONTEXT_SUMMARY` 为空 |
| 摘要事件 payload 损坏 | 视为无摘要（`covered_seq=0`），保留原始历史，记录 warning 与 metric；不得静默跳过历史 |

## 5. 非功能需求

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-PERF-01 | 性能 | 单次历史装配的查询次数与读取量随预算有界；历史事件按 partial index 取数，不先全量读入内存再过滤；装配路径不新增网络调用 |
| NFR-REL-01 | 可用性 | 压缩、估算、标记写入任一步失败都退化为“不裁剪”，不得使 Run 失败；首屏历史读取失败按明确失败处理；冻结配置非法属于配置错误，必须显式失败 |
| NFR-COST-01 | 成本 | 预算、模型输出预算和系统提示/工具目录统一用同一套保守 token 估算核对；发布前必须满足“预算 + 输出 + 系统提示与工具目录 < 部署最小模型窗口” |
| NFR-SEC-01 | 安全 | 任务线索提示只能作为“数据”进入上下文，必须转义/截断并明确未确认、无授权；不得以 SYSTEM 指令口吻授予执行权限 |
| NFR-TEST-01 | 可验证性 | 估算与裁剪是确定性纯逻辑：同输入同输出，可在无模型网络的情况下断言；摘要 coverage 空洞与旧摘要失效有专门回归 |
| NFR-COMPAT-01 | 兼容性 | 本需求不保留旧压缩键、旧 policy、旧摘要或旧平台设置的兼容解析，也不写数据迁移与反向迁移；开发阶段直接删除/失效不兼容数据 |

## 7. 依赖与风险

**依赖**：平台设置 schema、Console 设置目录与词条、Run/Task 快照 `policy_json`、Run 事件审计与 Console 事件详情、WebChat/Runtime 历史装配、`runtime.canonical_event` 历史 partial index、Worker Agentic 执行历史。

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|---------|
| RISK-01 | 预算配得超过部署最小模型窗口 | 上游拒绝请求，用户看到失败 | 预算上限 + 部署最小窗口校验；上游超窗错误保留 status/type 并做一次有界降级重试 |
| RISK-02 | 预算放大带来单次请求成本与时延上升 | 成本/体感 | 默认取保守档；用 token 用量与装配耗时指标观测 |
| RISK-03 | 无 tokenizer，估算与实际偏差 | 低估导致超窗，高估浪费预算 | 复用 `conservative_input_estimate` 的 1 字节/token 上限；超窗时降预算重试一次 |
| RISK-04 | 当前回合本身超预算 | 请求过大 | 写入侧整轮外置预算由 `history_budget_tokens` 派生；请求边界保留最近完整往返，省略中段并标记 |
| RISK-05 | 旧摘要 coverage 有洞 | 历史永久丢失 | 旧 `CONTEXT_SUMMARY` 全部清理；新摘要材料只取连续区间，coverage 由实际材料末条决定 |
| RISK-06 | 旧压缩键残留在库里 | 设置读取与保存按 fail-closed 直接报错 | 发布前重置平台设置并清空 Agent `budget.compaction`；不写迁移代码，残留即报错 |
| RISK-07 | 历史事件分页仍扫描大量非历史行 | 读取量不受预算约束 | 增加 `(conversation_id, seq)` partial index，只索引历史事件类型 |
| RISK-08 | Worker 仍使用旧字段/旧默认 | 编译失败或静默用默认值 | Worker 与 Runtime 共用严格冻结解析；删除旧解析与测试 |
| RISK-09 | 摘要替换误删尾部 | 保尾目标失效 | `with_summary` 只替换材料 seq 区间；专门回归“摘要+截断+尾部保留” |
