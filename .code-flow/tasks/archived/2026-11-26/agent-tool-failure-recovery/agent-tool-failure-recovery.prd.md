## 2. 背景与目标

### 2.1 问题陈述

| 维度 | 内容 |
|------|------|
| **问题描述** | 当前工具调用已经能够把部分异常转换成结构化工具结果，但执行边界异常（例如时间、输出、资源、子进程、网络、上下文或观测边界）仍可能与普通业务失败混在一起，导致执行内核直接导向 `finalize`，宿主随后把 Run 置为失败并把技术错误返回给用户。用户看到的是“会话被接管/断掉”，而不是 Agent 读取失败事实后重新规划、改用替代工具、补充参数、查询状态或解释无法完成的原因。该问题不应只针对 `execute` 或某一个沙箱错误码修补，Skill、MCP、附件、Memory、Task 和其他工具入口必须遵循同一语义。 |
| **当前替代方案** | 将工具失败映射为终止或依赖单个工具的特殊修补；`retryable`、是否允许 Agent 继续、是否允许原操作重试和是否必须宿主收尾之间没有清晰分离。结果是不可重试的副作用操作可能需要阻止重做，但不代表整个 Agent 不能继续；反过来，持久化/租约/模型不可用等宿主故障又不能交给模型假装恢复。 |
| **触发原因** | 用户反馈：除 `execute` 外，基本所有工具执行失败都可能直接返回错误并结束会话，期望失败后由 Agent 自己思考解决路径。当前代码核对显示 `AgentRunner` 在失败状态达到止损条件时直接路由 `finalize`，Runtime 的 `_finish_segment` 再将 `NO_PROGRESS` 转成失败终态。 |

### 2.2 目标与价值

| 维度 | 内容 |
|------|------|
| **核心目标** | 工具执行失败后，优先把脱敏、结构化、可恢复的失败事实交给正常 Agent 回合；Agent 可选择替代方案、修正调用、读取已有结果、请求用户补充或给出诚实结论，只有真正不可继续的情况才由宿主确定性收尾。 |
| **预期价值** | 降低无必要的会话中断和“研发排查式”错误暴露；保持副作用操作不被盲目重试；让 Runtime 与 Worker、同步与异步、Skill 与 MCP 的失败体验一致。 |

### 成功指标

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|----------|
| 可交给 Agent 处理的工具失败比例 | 未统一测量 | 所有已归一化的工具执行失败均进入统一恢复判定 | 共享执行内核契约测试 + 运行指标 |
| 工具失败后无必要 `run.failed` 的比例 | 存在直接失败路径 | 对可继续失败，终态前不发 `run.failed`，而是至少完成一次恢复回合或明确等待 | Runtime/Worker 集成测试与事件断言 |
| 不安全原操作重复执行 | 必须依赖现有门禁 | 为 0 | 副作用工具重试安全测试、审计记录 |
| 宿主故障被模型“吞掉” | 存在风险 | 为 0 | 持久化、租约、模型、取消、截止时间负向测试 |

## 4. 功能需求

### 4.1 功能清单

| 功能ID | 功能名称 | 功能描述 | 优先级 | 来源用户故事 |
|--------|---------|---------|--------|-------------|
| FEAT-01 | 失败控制语义分离 | 将“是否允许 Agent 继续”“是否允许原操作重试”“是否已发送且结果未知”“是否必须宿主停止”拆成独立的结构化事实，不能继续用单一 `retryable` 或 `no_progress` 推断全部行为。 | P0 | US-01, US-02, US-04 |

| FEAT-03 | 副作用与未知结果门禁 | 工具失败不等于原调用可重试。已发送且结果未知的效果型调用必须冻结原调用身份并阻止重复执行；恢复回合只能走状态查询、幂等安全操作或其他明确允许的路径。 | P0 | US-02, US-04 |
| FEAT-04 | 有界恢复与硬停止 | 恢复回合受既有 Run 轮次、工具调用、截止时间和模型预算约束；频率限流在允许范围内等待/退避重试；执行边界异常按“停止是否确认、结果是否未知、证据是否完整、执行权是否仍安全”归类；对相同失败持续重复、总预算耗尽、模型不可用、Run 取消、租约丢失、持久化/事件写入失败等情况确定性收尾。 | P0 | US-01, US-04 |
| FEAT-05 | 用户态收尾与技术态观测 | Agent 能生成最终结论时，以正常助手回复收尾，并可标记存在工具失败/降级；只有宿主硬停止才生成失败终态。技术码、Run ID、脱敏证据和恢复次数进入技术详情、审计和指标，不直接替代用户正文。 | P0 | US-03, US-04 |
| FEAT-06 | Runtime/Worker 一致性 | 交互 Run、定时 Task、同步工具、异步工具和恢复执行使用同一失败控制与事件契约，不能由宿主各自解释同一失败。 | P1 | US-04, US-05 |

#### FEAT-01: 失败控制语义分离

- **验收标准**:
  - [ ] 工具结果至少能表达：Agent 是否可继续、原调用是否可重试、外部请求是否已发送、结果是否确定、是否要求宿主停止。
  - [ ] `retryable=false` 不再单独推出“Run 必须结束”；它只禁止不安全的原操作重做，除非其他事实明确要求停止。
  - [ ] 失败控制事实可进入事件/检查点/恢复视图，实时执行与恢复执行使用同一判定。

#### FEAT-02: 统一恢复回合

- **验收标准**:
  - [ ] 首次可继续的工具失败后，不直接发 `run.failed`，而是把失败结果交给至少一个正常 Agent 回合。
  - [ ] Agent 可以选择替代工具或修正参数；被阻止的原调用有明确工具结果，不会因重试门禁造成宿主异常。
  - [ ] 多工具批次部分成功、部分失败时，成功结果保留，失败结果逐 call 回给 Agent，未执行调用有明确事实。
  - [ ] 工具层异常、错误码、MCP 协议错误、Skill 子进程失败和资源不可用在共享边界归一化，不要求每个工具单独实现续行。

#### FEAT-03: 副作用与未知结果门禁

- **验收标准**:
  - [ ] 发送后结果未知的效果型调用不能自动重做；Agent 可继续，但只能调用安全的状态确认或其他明确允许的工具。
  - [ ] 失败回合中变更参数、变更工具入口或换宿主不能绕过原操作身份和安全门禁。
  - [ ] 审计能关联原调用、恢复回合、阻止原因和最终结论。

#### FEAT-04: 有界恢复与硬停止

- **验收标准**:
  - [ ] 恢复回合消耗同一 Run 的预算和截止时间，不创建无限重试环。
  - [ ] `LOCAL_RATE_LIMITED`、平台 429 和带 `Retry-After` 的限流结果可在剩余 Run 预算内等待/退避后重试；总预算耗尽与停止确认失败仍然硬停止。
  - [ ] 相同失败反复出现且没有有效进展时，系统停止继续调用并确定性收尾。
  - [ ] 模型不可用、Run 明确取消、截止时间、租约丢失、事件/检查点持久化失败、身份/租户/快照不一致等宿主或安全故障不交给模型处理，不伪装为普通工具失败。
  - [ ] 异步工具/后台 Task 使用 `ToolOperation` 与 `RunContinuation` 的生命周期；取消 operation 后不再提交该 operation 的新调用，不引入 MSSClaw 的 `longtask:<id>` 会话模型。
  - [ ] 时间、输出、资源、子进程终止、网络响应或观测缺失等执行边界异常不按错误码逐一分叉；统一根据停止确认、发送/结果事实和证据完整性选择 `CONTINUE`、`WAIT` 或 `STOP`。

#### FEAT-05: 用户态收尾与技术态观测

- **验收标准**:
  - [ ] Agent 能基于失败事实生成结论时，用户收到正常助手回复，不被原始异常文本覆盖。
  - [ ] 回复明确区分已完成内容、失败内容、未知内容和下一步；不能把失败查询写成空结果或成功。
  - [ ] 运行事件和指标能区分恢复后完成、恢复后仍失败、硬停止和等待；技术详情保留错误码、脱敏证据和 Run 关联。

### 4.2 边缘情况

| 场景 | 预期行为 |
|------|----------|
| 工具参数校验失败 | 结构化结果回给 Agent；Agent 可修正参数，原错误不直接终止 Run。 |
| 资源不存在或无权限 | 回给 Agent；Agent 可换资源、请求用户补充或解释不可用；不伪造空结果。身份、租户或快照不一致时升级为安全硬停止。 |
| 频率限流 | 在剩余 Run 预算内按 Retry-After/退避等待并重试；等待预算耗尽后把限流事实交给 Agent，不把普通限流直接转换为 `run.failed`。 |
| MCP 会话失效/协议错误 | 按 MCP 安全规则重建会话与业务重试分离；结果回给 Agent，效果型未知操作不重做。 |
| 同一调用在一轮中被多次失败 | 保留每个 call 的结果；达到恢复止损条件后停止继续派发并收尾。 |
| 工具已发送但结果未知 | 标记未知并冻结原调用；只允许安全查询/替代路径。 |
| 工具结果持久化或事件写入失败 | 视为宿主硬故障，确定性失败并保留可恢复所需事实；不能继续调用模型掩盖事实缺失。 |
| Agent 在失败后直接输出解释 | 以正常助手回复完成，标记为降级完成；不额外追加技术失败文案覆盖用户答案。 |
| 模型服务不可用或 Run 被取消 | 按现有模型/取消终态收尾，不当作工具失败交给模型。 |

## 5. 非功能需求

| 指标ID | 类型 | 要求 |
|--------|------|------|
| NFR-REL-01 | 可靠性 | 工具失败不得丢失已执行事实、成功结果、失败结果或未知结果；恢复回合不能造成未经允许的重复副作用。 |
| NFR-OBS-01 | 可观测性 | 恢复、止损、硬停止和降级完成必须有结构化事件、审计关联和指标；日志脱敏且有界。 |
| NFR-COMPAT-01 | 一致性 | Runtime 与 Worker、实时与恢复使用同一共享失败判定和事件字段；不得新增按宿主复制的特殊续行分支。 |
| NFR-PERF-01 | 性能 | 失败回合复用同一 Run 预算与上下文，不引入无界等待或高频网络重试。 |

## 6. 范围与边界

| 类别 | 内容 |
|------|------|
| **范围（In Scope）** | 共享 Agent 执行内核的失败控制语义、工具结果/事件/检查点字段、Runtime/Worker 接线、恢复回合、重复调用安全门禁、执行边界异常的统一归类、用户态收尾、审计与指标、相关 Spec/测试/人工场景。 |
| **非范围（Out of Scope）** | 不改变具体 Skill 业务逻辑；不自动修复外部平台故障；不把所有宿主异常吞成工具错误；不绕过授权、租约、取消、deadline、模型预算或持久化要求；不新增独立重试服务；不复用 MSSClaw 的 `longtask:<id>` 会话机制；不把原始堆栈直接展示给用户。 |
| **前置假设** | 当前统一 ToolResult/ToolEvent、prepared fact、checkpoint、ToolOperation、RunContinuation 和 Runtime finalization 继续作为事实载体；失败回合必须遵守现有副作用与恢复契约。 |

### 7.2 风险识别

| 风险ID | 描述 | 影响 | 缓解方案 |
|--------|------|------|---------|
| RISK-01 | 将可继续与可重试混为一谈，导致副作用重做 | 数据重复或外部动作重复 | 在 typed outcome 中分离控制语义；专门覆盖 sent/unknown 场景 |
| RISK-02 | Agent 失败后反复调用导致 Run 卡住 | 延迟、成本、容量耗尽 | 复用总预算并增加失败恢复止损；相同失败和无进展有界终止；普通频率限流只在剩余预算内等待/退避 |
| RISK-03 | 宿主持久化失败被伪装为普通工具失败 | 恢复事实缺失、审计不完整 | 只有工具边界异常可进入恢复回合；事件/检查点/租约故障硬停止 |
| RISK-04 | Runtime 与 Worker 语义分叉 | 同一错误在不同入口体验不同 | 共享核心状态机与契约测试，宿主只提供端口 |

## 附录：术语表

| 术语 | 定义 |
|------|------|
| 恢复回合 | 工具结果已回到模型上下文后，Agent 再进行的一次正常模型决策回合。 |
| 原操作重试 | 对同一外部副作用调用再次执行；受 `retry_safety`、发送阶段和结果确定性约束。 |
| 结果未知 | 请求可能已经到达外部系统，但当前执行者无法确认业务结果。 |
| 硬停止 | 必须由宿主确定性结束 Run 的状态，例如取消、deadline、租约或持久化事实不可用。 |
| 降级完成 | Agent 已基于失败事实给出诚实结论，Run 正常回复但带有可观测的失败/降级信息。 |
