## 单项结论

### 工具预算

- 30 次对“资产 + 天气”两步任务足够，基线 4 次工具调用完成。
- 3 次会在完成资产查询后、天气查询前停止，说明预算是真实硬约束。
- 停止文案保留“已取得 1 个工具结果”，续行“继续”只补天气，不重复资产查询。
- 工具预算 3 过低，不建议作为默认值；30 次与当前基线匹配。

### 失败阈值

- 同一提示词、同一 Skill、同一错误码下，阈值 3 在第 3 次失败后停止，阈值 2 在第 2 次失败后停止；两者都进入 `RUN_NO_PROGRESS`。
- 本次 A/B 说明阈值语义生效，且计数按同一工具/错误/失败层累计。
- 阈值 2 对“可重试但永远失败”的调用能更早止损；是否影响正常业务的续行，仍需真实业务失败样本。

### 历史预算

- 256/1024/65536 都正确复用了早期事实；256 丢弃 25 条、1024 丢弃 19 条，65536 无压缩。
- 本样本把事实放在会话头部，压缩仍保留了它；不能据此认为 256 适合所有长对话。
- 256 的模型延迟和总耗时反而更高（2.785s vs 0.719s），但样本小，不能归因于预算本身。
- 默认 65536 仍是最稳妥选择；本次没有发现需要下调的证据。

### 摘要开关

- 摘要层实际触发：`summary.fired=true`，处理 20 组，节省 203 字节。
- 256 + 摘要：3 次模型调用、5.947s；256 关闭：2 次模型调用、2.785s；答案均正确。
- 摘要增加了一次模型调用和延迟，在这个短事实样本上没有带来可测的正确性收益。
- 只测了一个长对话，且导出没有 token 计数；不能据此决定默认开启摘要。

## 默认值建议

本次证据支持继续使用：

```text
max_turns=20
max_tool_calls=30
history_budget_tokens=65536
max_identical_failures=2
summary_enabled=false
```

不建议根据本次有限对照提高/降低默认值。要完成更强的 B-02，还需：

1. 用真实业务失败样本复验阈值 2/3 对正常任务续行的影响；
2. 用事实位于会话中部的长对话比较历史预算候选值；
3. 在可用摘要模型和容量下记录 token 用量，并覆盖多个长对话样本。
