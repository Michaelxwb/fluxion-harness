# Agent 对话续行与运行设置生效 · 前端设计

## 1. 文档控制

v0.8，对应 PRD FEAT-03 至 FEAT-06。Console 设置负责人负责执行预算和阈值说明，WebChat 验收负责人负责提问、跨 Run 续行及通用产物展示。企微客户端使用既有消息和文件能力，投递和回复路由由后端设计约束。

## 2. 需求与验收

- 管理员能理解“连续同类失败停止阈值”的含义和生效时间。保存后能用新 Run 及授权执行导出核验。
- WebChat 用户能看到当前问题、回复并接续原对话。刷新后仍能恢复待输入状态和问题。
- 企微用户在原会话收到自然语言问题，直接回复即可。用户界面以真实客户端为验收入口。
- 普通结果用正文显示。超出正文容量或需要文件时，在原会话展示产物或授权下载入口，以及说明内容、范围和送达状态的最终回复。

## 3. 前端技术设计

| 入口 | 复用组件与数据流 | 交互 |
|---|---|---|
| 系统设置 | React 设置页 `SettingsPage`、`SettingsGroupPanel`、`SettingsFieldRow`。通过既有 `usePlatformSettings` / `settingsApi` 读取后端目录、校验和保存。 | 阈值标签和说明使用 i18n，示意“同类失败累计达到此次数时停止”。范围取目录定义。保存时保留原有加载、失败、版本冲突、重置与成功反馈。说明影响新 Run，已挂起 Run 恢复采用创建时的值。 |
| 执行详情 / 导出 | 从现有授权执行详情入口下载。导出从运行快照读取所需字段。 | 历史快照缺项时以未记录呈现。管理员可以对比设置页当前值与导出中的当次有效值。 |
| WebChat | 复用现有流式消息、活动 Run 和提交入口。使用后端现有消息快照及等待状态。 | 异步接收、刷新、掉线重连均可读到当前问题。`WAITING_INPUT` 不是“只能停止”：输入框可编辑、Enter 可提交，提交走同一会话消息并 resume 原 Run；停止保留为次要动作。重复事件按同一 `seq`/`run_id` 合并到同一条提问。回答提交后按服务端状态显示继续执行、错误或等待。错误时保留可修改的回答。 |
| 企微 | 使用现有机器人在原会话发送文本；用户发送常规文本答复。 | 问题说明缺失项和能回复的值，例如“请回复客户名或客户 ID”。继续沿用客户端已有的消息展示。 |
| WebChat 与企微的产物交付 | WebChat 复用会话消息、历史和附件卡片。企微复用现有文本、图片、文件与授权下载展示。 | 附件和最终说明使用现有会话展示，刷新后仍可读取。产物按现有媒体类型和渠道能力展示。用户可在自然语言中指定格式，Agent 可在同一 Run 选定合适类型。 |

前端从设置目录和现有接口取得有效范围和状态，保持 API 调用经过现有 services。界面改动复用原有排版、表单提示、错误反馈和国际化规范。

## 4. 依赖与验收

- S-03 通过真实企微客户端验证问题和答复闭环。S-07、S-09、B-03 验证 WebChat 刷新、短对话及达限后续行。S-08 验证设置保存、版本和导出值。S-10、S-11、E-04、E-05 验证普通正文、超限产物和说明、刷新与失败反馈。
- 若 WebChat 既有行为通过验收，改动集中在设置文案和约束联动。企微断点由消息链路的证据定位。
- `frontend/harness-frontend`、`i18n/harness-i18n` 和 `ui/harness-ui` 约束现有组件与服务层复用。权限按现有设置和运行详情授权。
