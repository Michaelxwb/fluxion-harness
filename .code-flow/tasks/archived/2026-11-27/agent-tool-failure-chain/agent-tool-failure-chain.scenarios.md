# Agent 对话续行与运行设置生效 · 人工验收

在真实构建产物、隔离测试环境和已登录的客户端执行。由验收负责人记录版本、入口、实际用户结果及辅助证据。每项结果初始为待执行。

## S-01 一次可纠正失败后继续查询

- **负责** · Runtime 验收
- **前置** · 测试 Agent 可通过另一组合法参数或工具完成同一查询。
- **步骤**
  1. 在 WebChat 发起查询，用测试夹具使第一种调用在派发前被拒绝。
  2. 等待 Agent 用已有信息尝试合法路径。
- **期望** · Agent 继续原请求，返回真实结果或说明仍缺的条件。后续独立调用能执行。

## S-02 大结果截断后交付可用结果

- **负责** · Runtime 与 Skill 验收
- **前置** · 测试资产查询为只读，默认结果会截断，缩小范围可以取得可核实结果。
- **步骤**
  1. 请求资产明细，观察默认查询返回不完整结果。
  2. 让 Agent 按客户、关键词或分页缩小范围，查看最终回复和可用文件。
- **期望** · 原截断结果如实记录。Agent 给出核实后的结果或部分交付，并说明范围和缺口。

## S-03 企微收到具体问题并回复续跑

- **负责** · 企微渠道验收
- **前置** · 测试企微账号已绑定 Agent，准备一个确需客户标识的资产查询和可核实结果。
- **步骤**
  1. 在真实企微客户端只发“帮我拉一下资产 IP 明细”。
  2. 在原聊天中查看机器人回复，记录具体问题与显示顺序。
  3. 直接回复一个有效客户名或客户 ID，查看后续结果。
  4. 用授权执行详情核对答复和最终结果属于同一运行。另用可控的回复句柄失效条件复验已有投递路径。
- **期望** · 用户收到一条明确写出所需信息和回复方式的问题。有效回答让原任务继续并使用补充参数。只见等待状态、问题仅在后台、问题重复显示或答复另起任务均判失败。

## S-04 长对话复用当前输入

- **负责** · Runtime 验收
- **前置** · 对话长到会触发历史省略。当前请求内有客户、平台和所需范围。
- **步骤**
  1. 在长对话中给出包含完整条件的新查询。
  2. 观察 Agent 的后续问题、结果及对哪些信息缺失的说明。
- **期望** · Agent 使用已给条件继续，准确描述历史缺口。若需要更早的必要事实，只询问缺失项。

## S-05 同一工具成功后重新计数

- **负责** · Runtime 验收
- **前置** · 有一个可加载 Skill 与两个可用于制造拒绝的测试 Skill，停止阈值设为 2。
- **步骤**
  1. 用测试 Agent 顺序尝试不可用 Skill、可用 Skill、另一个不可用 Skill。
  2. 观察第二次拒绝后执行是否还可继续，查看最终解释。
- **期望** · 中间的有效加载打断失败连续性，原任务还有机会继续。

## S-06 自建草稿试跑和发布后执行

- **负责** · Skill 验收
- **前置** · 测试用户可创建草稿并走既有审批，有已授权的工作区。
- **步骤**
  1. 新建小型 Skill 草稿，运行简单命令验证草稿行为，再修订并试跑。
  2. 发布并让新对话调用默认入口，核对参数和结果。
  3. 在独立授权工作区执行一条测试命令。若有存量调试调用，打开其历史详情。
- **期望** · 草稿试跑有可见结果且测试数据隔离。发布后按默认入口执行，工作区命令能运行，旧详情能打开。

## S-07 WebChat 刷新后继续回答

- **负责** · WebChat 验收
- **前置** · 测试 Agent 会发起必填参数澄清。
- **步骤**
  1. 发起查询并等到问题显示，刷新页面后重新打开该会话。
  2. 在会话中提交有效答案并查看结果。
- **期望** · 刷新后仍能看到问题，答复后原任务继续且问题不会重复显示。

## S-08 设置对新 Run 生效

- **负责** · Console 与 Runtime 验收
- **前置** · 隔离租户、管理员权限和可稳定制造同类失败的测试 Agent。
- **步骤**
  1. 按设置页说明保存一个可区别于默认值的阈值，发起测试并让 Run 在达到阈值前等待用户输入。
  2. 再保存另一个阈值，恢复旧 Run，并开启新会话运行相同测试。
  3. 核对两次实际停止时机及授权执行导出的阈值、历史预算和摘要状态。
- **期望** · 表单范围和文字与实际语义相符。旧 Run 沿用原冻结值，新 Run 使用新值，导出可区分二者。测试结束后还原隔离租户设置。

## S-09 工具结果密集的短对话仍记得目标

- **负责** · 对话续行验收
- **前置** · 同一会话内首个请求会执行多次工具，有可核实的客户、平台、目标和未处理范围。
- **步骤**
  1. 发出含客户、平台和目标的请求，等首个回复呈现一部分结果。
  2. 在原会话只发“继续”或补充一个过滤条件。
- **期望** · 新执行沿用客户、平台和目标，接着处理剩余工作。补充条件生效，用户不用重复已有信息。

## S-10 企微按结果大小交付正文或产物

- **负责** · Skill 与企微渠道验收
- **前置** · 测试 MSSP 客户清单超过单条消息的可读范围，已知授权范围和匹配总数。
- **步骤**
  1. 在企微先查询一条客户记录，再单独发一次超出正文容量的客户清单请求。
  2. 查看第一条查询的文字回复。打开第二条查询收到的产物，核对记录数与筛选范围。
  3. 核对第二条查询的最终说明是否与收到的产物一致。
- **期望** · 单条查询直接收到完整文字。超限查询收到产物和简短说明，产物适合查看明细并覆盖预期范围，无需为附件再发一次请求。

## S-11 WebChat 按用途交付不同类型的产物

- **负责** · Workspace 与附件验收
- **前置** · 准备超出单条消息容量的可公开测试全文，以及一组可独立核对内容的异构测试文件。测试 Agent 能在授权工作区读取和生成产物，可模拟原始输出预览被截断。
- **步骤**
  1. 在 WebChat 请求获得测试全文，明确要求 TXT。打开收到的文件并与原文对照，再核对说明中的内容和范围。
  2. 发起另一条测试请求，说明要一次性下载整组异构文件并保留原格式，不指定最终产物类型。打开 Agent 选定的产物并核对成员及内容。
  3. 刷新会话，查看已发内容和产物入口。
- **期望** · 第一条请求交付可打开的 TXT 并简短说明。第二条请求无需用户再选格式，Agent 交付适合一次性下载的产物，例如归档包。两条请求均可对照实际来源。预览截断时仍能打开和核对完整产物。刷新后说明和产物保持可见。

## E-01 未核实写入与安全核实

- **负责** · Runtime 与 Worker 验收
- **前置** · 使用可对账的测试目标，能在已接受写入后模拟结果丢失；另备只读查询及独立目标。
- **步骤**
  1. 触发一次结果未知的写入，观察 Agent 反馈。
  2. 让测试 Agent 重复操作，尝试改超时、输出选项或换入口。
  3. 核实原目标状态，并尝试可证明独立的操作。
- **期望** · 目标只收到一次原写入，重复尝试被拦。安全核实和独立操作可继续，用户可以理解待核实事项。

## E-02 旧调试参数的反馈

- **负责** · Runtime 验收
- **前置** · 测试工具能模拟旧提示产生的带调试参数调用。
- **步骤**
  1. 触发旧调用并观察返回。
  2. 用该 Skill 的正常默认入口完成同一测试。
- **期望** · 反馈说明调试参数不可用且如何纠正，合法入口能完成。

## E-03 Skill 对当前 Run 不可用

- **负责** · Runtime 验收
- **前置** · 测试账号有一个可用 Skill，另一个目标 Skill 在该 Run 不生效。
- **步骤**
  1. 发起依赖不可用 Skill 的请求，查看回复和可用替代项。
  2. 在有替代路径时继续请求。
- **期望** · 用户能理解哪个 Skill 当前不可用和如何处理，替代路径仍可执行。

## E-04 平台归属或分页不完整时如实交付

- **负责** · 数据来源与附件验收
- **前置** · 准备无已验证映射的跨平台客户标识，再准备一个已选对平台但故意缺页或有重复记录的样本。
- **步骤**
  1. 请求指定平台的客户资产明细，观察 Agent 如何处理不同平台的客户标识。
  2. 使用第二个样本再发一次查询，查看产物及缺口说明。
- **期望** · 用户只收到已核实平台的结果或一个明确的澄清问题。缺页或重复记录导致完整性无法确认时，可交付已核实明细并明确未取全，表格内容可与来源对照。

## E-05 产物首次未送达

- **负责** · 企微渠道与附件验收
- **前置** · 可控企微环境能确认首次文件发送未发出，并提供同一文件可交付的恢复路径。另备发送结果未知变体。
- **步骤**
  1. 发一次超限查询。触发产物首次发送失败并查看最终说明。
  2. 恢复通道，查看用户收到的文件，并用授权执行详情核对生成与投递记录。
  3. 复验发送结果未知变体，查看会话和后续交付状态。
- **期望** · 用户能区分实际送达、未送达和待核实。通过既有重试收到文件时，内容与原产物一致。

## B-01 升级时保留安全边界

- **负责** · 发布验收
- **前置** · 隔离环境准备一个已知派发前失败而等待的旧 Run，以及一个结果确实未核实的旧写入案例。
- **步骤**
  1. 按发布流程在切换前清点两类执行，核实或处置无法确认的写入。
  2. 切换后用同会话的合法查询复验，并核对未核实操作的处置记录。
- **期望** · 已知失败没有造成持续误锁。未核实写入没有被重复执行，处置有证据。

## B-02 默认值单项对照

- **负责** · 产品与运维验收
- **前置** · 固定模型修订、Skill 版本、授权、输入及可复现的对话材料。
- **步骤**
  1. 用短对话、带早期必要信息的长对话、可恢复失败三组输入记录基线和实际设置。
  2. 加入曾触及模型轮次、工具调用预算及内网改善场景。每次调整模型轮次、工具调用数、历史预算、摘要或失败阈值的一项后重复测试，再验证选定组合。
  3. 记录实际生效值、停止类型、用量、任务完成、正文或产物交付结果、重复追问、已确认信息复用、延迟和 token。
- **期望** · 有可复查的单项对照与默认值决定。结果能说明体验变化来自哪项设置，并区分无明显收益的候选值。

## B-03 达到预算后说“继续”

- **负责** · 对话续行验收
- **前置** · 分别准备可稳定触及模型轮次和工具调用预算的只读任务，达到限制时已有部分可核实结果。
- **步骤**
  1. 发出请求，等前一次执行结束，查看已完成部分和缺口。
  2. 在原会话只发“继续”，观察下一次执行。
- **期望** · 新执行沿用原目标与确认参数，依据已有结果推进未完成部分。用户看得出前后进度，已完成步骤不会因为续行被当成未知或凭空补齐。
