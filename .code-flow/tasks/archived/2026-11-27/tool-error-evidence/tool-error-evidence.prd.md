# 工具错误事实透传与 Run 失败说明

2026-11-27 · v0.1 · 待复核

## 背景与目标

定时技能预检失败时，用户需要知道任务是否建成、谁能处理、何时可以再试。Agent 需要能区分业务输入、平台配置和执行结果待核对。管理员需要能从同一 Run 还原这些判断的依据。

当前工作区中可复核的断点：

| 位置 | 事实与后果 |
|---|---|
| Worker 的 schedule_drafts.py，调用契约校验 | 缺失和无效契约使用同一码，reason 分别为 CONTRACT_MISSING 和 CONTRACT_INVALID，repair 均为 REIMPORT_SKILL。仅凭 code 不能区分两者。 |
| Runtime 的 task_client.py 与 task_tools.py | 非成功响应仅取 code，工具包装又将 code 填入 message。即使补回 data，直接套用 TaskToolError 的现有默认值仍可能把平台配置错误标记为可重试。 |
| agent-core 的 tools/result.py 与 failures.py | 工具错误能携带 detail，但当前序列化只在结果已知且 retryable 为真时写出该标记。调度错误缺少对应用户提示，重试保护会命中普通工具错误提示。 |
| Runtime 的 finalization/facts.py 与 render.py | 无进展时取最后失败，审计缺失的重试信息按假值处理，再尝试用快照补正。展示层据此解释停机，并把 evidence_preview 标作平台返回。 |

| US-02 | 用户能看懂受影响的操作、已确认的结果和自己接下来能做什么。 |
| US-03 | 有权限的管理员能直接从 Run 详情和导出核对业务失败、保护动作与终止原因。 |

| ID / 优先级 | 交付要求与可观察结果 |
|---|---|
| FEAT-01 / P0 | 经真实 Worker HTTP 客户端和工具适配进入下一轮 role=tool 消息的错误应携带稳定 code、安全 message、获准的 detail、修复责任方及有证据的重试许可。显式禁止与未知可区分。补全 detail 本身不得放开原样重试。服务不可达、非 JSON、畸形响应应保留已知边界事实并安全降级。 |
| FEAT-02 / P1 | zh-CN 和 en-US 均覆盖调度错误及重试保护。具体码和 reason 优先于宽泛前缀；TOOL_RETRY_UNSAFE 提示先核对先前结果。CI 枚举工具可产生的已知码，缺少可信专属提示或明确适用的码族时失败；运行时遇到未知码保留安全通用提示并记录缺失指标。 |
| FEAT-03 / P1 | 按同一操作和调用证据关联原始业务失败及后续保护事件，分别保留工具、调用身份与顺序。其他并行调用失败、先前已恢复的错误不能抢占根因。无可靠关联时标记根因未确定。Run 停止说明取自实际 TerminationReason。审计可还原 retryable、retry_disposition、agent_disposition；恢复和重放应得到一致解释，历史缺项显示未知。 |
| FEAT-04 / P2 | 主消息以用户语言说明结果、影响和下一步。修复责任区分 USER、ADMIN、NONE；证据不足时保留未知。平台配置由管理员处理，用户输入只追问缺失业务值。WebChat 默认折叠诊断；管理员 Run 详情及导出保留 Run ID、工具、码、字段、reason、repair 与有来源的脱敏摘要。只有确实来自平台的消息可标为平台返回，只有持久化成功才可声称已记录。 |

## 场景验收

1. 草稿预检返回缺失契约、payload.skill_id、REIMPORT_SKILL。检查模型实际接收的工具消息含 detail.repair；触发无进展收尾后，中文主消息说明平台配置和管理员重新导入，技术详情含错误码和当前 Run ID。英文验收相同语义。
2. 同一码改为 CONTRACT_INVALID，应说明配置无效。移除 detail 并只返回码时，应说明具体原因无法确定；两个场景均不得虚构已发布版本的脚本信息或自动切换执行方式。
3. 在原始失败后插入同操作的重试保护，再以 NO_PROGRESS 结束。三项事实可独立核对；用户消息不得出现“失败不可重试，已停止”。换为无关联保护或旧审计记录时不得推定因果。
4. 原调用结果未知时提示核对；只有预检确在写入前被拒、且本次相关操作无其他写入时，才可向用户确认本次未创建、已有任务未变。用户可补正的业务字段应直接追问。
5. 在响应的未知键、允许字段的值以及 msg 中放入敏感内容或超长嵌套对象。模型上下文、技术详情和导出均不得泄露原值；保留安全码及可验证的诊断字段。

契约缺失场景的预期主消息（已确认无相关写入）：

> 这次定时任务没有创建，已有任务不受影响。这个技能缺少定时执行所需的平台配置，你无需修改任务内容。管理员重新导入技能后，你可以再让我创建。

## 约束、范围与风险

- NFR-01：公开投影按错误契约校验字段、值类型、枚举、长度、集合大小与嵌套深度；field、reason、repair、allowed_values、entry 等按需开放。未知正文不能直接进入模型、审计或用户界面。Run 查询及导出沿用租户和角色权限。
- 范围包括 Worker→Runtime 工具错误、共用提示、Run 审计/收尾及现有展示出口。复用已有 agent-tool-failure-chain 的执行与恢复判定。本需求不新增重试策略、调度执行方式或管理员通知流程。
- 复核项：本期将 REIMPORT_SKILL 唯一解释为重新导入；发布、替代执行和自动转派需要各自的产品契约。运行结果未确认时保留不确定性。
- 规范依据：api/harness-api RULE-005 对应 FEAT-01；i18n/harness-i18n RULE-i18n-001 对应 FEAT-02、04；arch/harness-arch RULE-003、005、006 对应 FEAT-01、03、05；persistence/harness-data RULE-data-001 对应审计归属和持久化。
