# 工具错误事实人工验收

在真实构建、浏览器和隔离服务执行，记录构建号、语言、Run ID、实际结果。以下场景均待执行。

## S-01 用户遇到技能配置问题

负责：WebChat 验收。前置：准备缺少定时调用契约的技能和一条已有定时任务，确认本次尚未提交其他变更。

1. 在 WebChat 请求为该技能创建定时任务。
2. 阅读助手回复，打开任务中心，比对已有任务和新增记录。
3. 刷新后再次查看，确认页面没有技术详情块；另以英文会话重试。

期望：主消息只说明本次创建失败、平台配置需管理员重新导入、用户可在修复后再试。两种语言含义一致；已有任务未变。技术码和 Run ID 只在 Console 运行记录/导出中，WebChat 不返回技术详情。

## S-02 管理员核对证据

负责：Console 验收。前置：有权查看 S-01 的运行及其导出，另备一个契约无效的技能。

1. 对无效契约的技能发起相同请求。
2. 在运行详情分别打开两次调用，再导出记录并比对。

期望：同一错误码下能区分 CONTRACT_MISSING 与 CONTRACT_INVALID；工具、字段、REIMPORT_SKILL 和各自 Run ID 一致。只有经验证的平台消息标为平台返回。

## E-01 保护事件发生在业务失败之后

负责：Runtime 与 Console 验收。前置：准备带可重放对话的测试租户，包含同操作失败、重复请求受保护、运行无进展，以及同时发生的独立调用。

1. 运行测试对话，观察回复和运行时间线。
2. 在设置好恢复点的相同对话中恢复运行，再核对详情与导出。

期望：业务原因、保护动作、Run 停止原因分别可辨。独立失败不成为根因；恢复前后含义一致。只有先前执行结果未知时提示先核对该结果。

## E-02 只有错误码或结果待核对

负责：WebChat 与 Runtime 验收。前置：测试夹具分别提供只有错误码的预检拒绝、请求发出后结果未确认的样本。

1. 分别请求创建任务，从首次流式回复观察到会话结束。
2. 查看运行的调用记录和任务中心。

期望：前者提示具体原因未确定；后者明确结果待核对。不会出现猜测脚本、自动改用另一种执行方式或断言一定未创建。核对记录中实际执行的工具。

## B-01 可纠正的业务值

负责：对话验收。前置：可调度的技能声明了必填业务参数。

1. 请求创建任务时遗漏该值，观察追问。
2. 补充该值，按正常草稿确认流程查看结果。

期望：用户只需提供缺少的业务值，可继续原目标；正常确认流程可完成，无重复任务。

## B-02 诊断可见性和旧记录

负责：Console 与安全验收。前置：有含无害敏感标记样本的测试错误、一条早期 Run 记录和另一租户的账户。

1. 在本租户查看并导出样本，搜索夹具中预置的敏感标记。
2. 打开早期记录；切换至另一租户，尝试访问样本 Run 和导出。

期望：任何用户可见输出均不含标记；旧记录缺失项保持未知。其他租户无法查看或导出本租户记录。

## N-01 正常成功

负责：WebChat 验收。前置：可用的只读技能。

1. 请求查询一个正常业务结果，例如未来两天天气。
2. 观察流式回复、最终正文和运行记录。

期望：Run 完成，正文是模型正常总结，没有错误块或技术详情；运行记录中工具调用为成功。

## C-01 错误信息给到模型后自行修正成功

负责：WebChat 与 Console 验收。前置：`uat-self-correct` 技能已导入并绑定；第一次传入未知客户会返回可重试错误，错误正文列出可用客户编号。

1. 只提出业务目标，不告诉模型正确参数：
   `请用 uat-self-correct 查询客户 ACME 的资产概况。请直接调用该技能，不要先问我；最后报告你实际使用的客户编号和资产列表。`
2. 观察第一次工具错误、模型是否自行修正、第二次调用和最终结果。

期望：第一次调用 `customer=ACME` 返回 `UAT_CUSTOMER_UNKNOWN`，错误中给出可用客户 1001；模型没有收到用户提示的正确值，仍依据工具错误自行改为 1001 并成功。最终 Run 完成；WebChat 不展示技术详情，Console 运行记录保留两次调用事实。
