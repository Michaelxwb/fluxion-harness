# 架构基线 V1.13

## 1. 适用范围

本规范约束 Fluxion Framework Core、Platform API、Agent Runtime、Worker、Channel Gateway、Skill SDK 和 Integration。业务项目可以扩展能力，但不得反向修改 Core 语义。

## 2. 分层

```text
presentation/control-plane
    ↓
application/usecase
    ↓
domain/contracts
    ↓
ports/SPI
    ↓
adapters
    ↓
external infrastructure
```

禁止：

- Domain import FastAPI/SQLAlchemy/Redis SDK；
- Agent Runtime 直接 import 项目 integrations；
- Skill import Runtime 内部模块；
- Console 直接依赖数据库；
- ProjectIntegration 在启动时动态修改 Domain class；
- 以 JSONB 万能字段绕过领域对象。

## 3. 应用角色与进程边界

| 角色 | 入口 | 持久状态 | 横向扩展 | 主要依赖 |
|---|---|---|---|---|
| platform-api | Console HTTP | 无本地 SoT | 是 | PostgreSQL/SecretProvider |
| agent-runtime | Internal Chat | 无本地 SoT | 是 | PG/Redis/LLM/Capability |
| worker | Execution claim | 无本地 SoT | 是 | PG/Capability |
| channel-gateway | WeCom WS | 连接态仅临时 | V1 单副本（多副本前 Gate：RULE-CHAN-08） | agent-runtime 内部 REST（CH-DATA-01..04 / CH-INT-02） |
| console | Browser | 无 | CDN/静态 | platform-api |
| maintenance | 同镜像不同 entrypoint（`maintenance`，副本=1） | 无本地 SoT | 否（单副本定时任务） | 独立连接池/开关；Worker 只留 WORK-LIB-06 投递调度 |

Gateway 的 WebSocket connection 属于连接状态，不是业务事实；bot→agent 配置的事实源是 PostgreSQL 的 `channel_account`，Gateway **不直连业务库**，由 agent-runtime 经 `CH-DATA-01` 以短时 `SecretLease` 下发（含 account scope 限制）。实例重启后按 ChannelAccount 重建连接。

若未来 Gateway 需要多副本，必须先满足 RULE-CHAN-08 的多副本 Gate（Redis 协调 Bot 连接归属、错实例投递经内部转发、Redis 不可用时退化为单接管），在此之前不得按“水平扩 Gateway”做容量假设。

CH-DATA 走 agent-runtime 承载 + 可用性合同（ADR-060）：CH-DATA-01..04/CH-INT-02 为运行面（只读、幂等、可安全重试），与 platform-api 管理面进程与依赖分离，管理面停机不影响它们；agent-runtime 故障时 IM 入站与投递许可不可用，但已创建 Execution 仍由 Worker 推进，投递行保留并在恢复后由 WORK-LIB-06 继续调度。

## 4. Definition Plane 与 Execution Plane

Definition Plane：

- AgentDefinition；
- ServiceDefinition/Draft/Release；
- CapabilityDefinition/Implementation；
- SkillDefinition/Artifact；
- ModelConfig；
- ProjectPlatform；
- User/Grant/ChannelAccount。

Execution Plane：

- Conversation/Message；
- Execution/Step/AsyncTaskRun；
- Delivery；
- runtime checkpoint/trace。

定义对象变化不得原地修改历史 Execution Snapshot。

## 5. Resolve Once / Dynamic Security

业务逻辑配置可按执行开始时冻结，但安全动态状态不能被快照永久绕过：

- User Agent grant；
- Credential 当前有效性；
- Capability emergency disable；
- Platform/Agent enabled；
- Secret current availability。

Worker 恢复执行时必须重校验必要动态安全状态。

## 6. 外部基础设施

Fluxion 应用部署不得内置生产 PG/Redis/ObjectStore/SecretProvider/OTel Backend。开发环境可使用独立的外部依赖实例，但也应保持连接配置同生产形态。

## 7. 依赖方向 Gate

CI 应至少检查：

```text
framework/domain      !-> integrations/*
agent-runtime         !-> integrations/*
skill package         !-> fluxion internal runtime modules
console               !-> DB
capability provider   !-> console
```

## 8. 配置生效

- Agent/Model/Capability/ProjectPlatform：保存后对新请求生效，revision/audit；
- Skill：通过新 Artifact 生效，不覆盖旧 Artifact；
- Service：仅 Publish 后对正式执行生效；
- ChannelAccount：保存后 Gateway 进行连接重建/路由切换；
- AgentAccessGrant：即时生效；
- User Credential：更新后新 Capability invoke 使用新值。

## 9. 术语表（一义一名，P2-6）

本表是术语的唯一裁决处；文档出现同名不同义时以本表为准并回写正文。

| 术语 | 唯一含义 | 不要再用的近义词 |
|---|---|---|
| User / PlatformUser | 产品侧唯一用户身份（`platform_user`），Console 与 IM 共用 | Customer、Account、Member（`auth_account` 已删除） |
| Grant | `agent_access_grant` 的一条授权记录（user × agent），由单条 grant/revoke 操作变更 | Permission、Role、Binding |
| Role | `platform_user.role ∈ {END_USER, BUILDER, ADMIN}`，唯一权限承载字段 | Group、Level |
| Execution | `service_execution`，**唯一 durable 执行根**（Worker 推进） | Job、Task、Process |
| Turn / Chat turn | 一次用户消息触发的对话处理，**不 durable**（`message.processing_status` 调度） | Run、Session（`conversation_run` 已删除） |
| Run | **已废止**：原 `conversation_run` | （不要使用） |
| Step | `execution_step`，Execution 内的一个编排步骤 | Stage、Node、Action |
| Stage | 进度事件里的业务阶段（`task_progress_event.stage`），仅用于展示 | Step（不要与 Step 混用） |
| Capability | 统一业务能力契约（`capability_definition`） | Tool、API、Function |
| Implementation | Capability 的可替换实现（`capability_implementation`） | Adapter（Adapter 是实现内部的传输层） |
| Skill | 离线开发的 Python SOP 代码资产（`skill_definition` / `skill_artifact`） | Plugin、Script |
| Service | 面向最终用户的业务服务定义（`service_definition`）+ Release | App、Workflow |
| Snapshot | 执行冻结的业务投影（`execution_snapshot.snapshot_json`） | Config copy、Payload |
| Delivery | 一次对外投递尝试（`channel_delivery`） | Notification、Message |
| Artifact | 可交付/大结果元数据（`artifact`），对外身份 `artifact_id` | File、Object（`object_ref` 是内部引用） |
| Route | 投递路由（`channel_delivery_route`） | Channel、Endpoint |

---

> **代码根（P2-4 定死）**：唯一代码根是仓库根的 **`framework/`（Core）+ `adapters/`（基础设施实现）+ `apps/`（运行角色入口）**。文档中出现的 `src/fluxion/`、`packages/` 均为历史示意，**不作为目录约束**；新增模块按 `framework/<domain>/` 落位，跨层只能经 Port/SPI。
