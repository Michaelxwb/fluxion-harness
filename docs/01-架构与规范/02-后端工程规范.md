# 后端工程规范 V1.9.1

> **适用范围**：本文档是**后端工程风格与共享样板**的唯一落点（错误族、事务、日志、测试分层的通用段落，模块文档只写差异行）。
> **不重复契约**：错误码以《10-错误码与错误分类基线》为唯一注册表；表结构以模块 `design-full §3.3` + 《08》为准；接口以模块 `§3.4` + 《09》为准——本文件不维护第二份清单。

## 1. Python 与工程结构

Python 3.12+。推荐：

```text
framework/                 # Core：领域 + 应用 + Port 定义（不 import 基础设施）
├── domain/                # 领域对象与规则
├── execution/ capability/ agent_core/ workspace/ channel/ web/
│                          # 各域应用服务与公共 Web 基础
├── contracts/             # SPI 契约（Port 定义、错误码引用）
└── integration/           # 装配期 Registry / Loader / Seed 契约
adapters/                  # 基础设施实现（PostgreSQL/Redis/Secret/ObjectStore/Sandbox）
apps/                      # 运行角色入口（platform_api / agent_runtime / worker / channel_gateway）
sdk/                       # skill-sdk（Skill 离线开发）
integrations/<project>/    # 项目 Integration（manifest + providers + seed）
```

Domain 使用 Pydantic/dataclass 等纯模型；数据库 ORM 模型不得直接作为 API DTO。

## 2. Use Case

每个写用例显式：

- actor/context；
- input DTO；
- transaction boundary；
- domain validation；
- repository；
- audit event；
- result/error。

禁止 Controller 中拼装复杂业务逻辑。

## 3. Repository

- Async SQLAlchemy 2；
- 默认过滤逻辑删除；
- 不返回未提交的 ORM 到上层；
- 列表必须分页；
- 不允许隐藏 N+1；
- 关键查询必须有索引说明；
- published Artifact/Release Repository 不提供 update 方法。

## 4. 错误

错误至少包含：

```text
code
message (安全的人类可读)
details (可选，非敏感)
request_id
```

错误族示例：

- `VALIDATION_ERROR`
- `NOT_FOUND`
- `CONFLICT`
- `FORBIDDEN`
- `AGENT_ACCESS_DENIED`
- `CHANNEL_IDENTITY_UNBOUND`
- `CAPABILITY_DISABLED`
- `CAPABILITY_TIMEOUT`
- `CAPABILITY_PAGINATION_LIMIT`
- `SKILL_MANIFEST_INVALID`
- `SKILL_SDK_INCOMPATIBLE`
- `SERVICE_CONFIGURATION_INVALID`
- `EXECUTION_CANCELLED`

不得把 traceback/Secret/SQL 暴露到外部。

## 5. 超时/重试

- HTTP/Provider 必须显式 deadline；
- retry 有界、带 backoff/jitter；
- 非幂等写默认不自动 retry，除非 Provider 有幂等键或明确安全语义；
- Worker retry 与 Provider retry 分层，禁止叠加造成指数放大；
- Capability Data Retrieval 总时长受 `max_duration_seconds` 约束。

## 6. 并发与事务

- Service Publish：事务内 validate snapshot + insert release + switch pointer；
- BindCode consume：行锁/条件 update 防双消费；
- Execution claim：SKIP LOCKED/lease 等并发安全机制；
- ChannelAccount bot_id unique；
- Grant/Credential 使用数据库唯一约束兜底。

## 7. 日志

结构化日志字段至少：

```text
timestamp level service request_id trace_id
user_id agent_id service_id execution_id step_id
capability_key skill_id error_code latency_ms
```

敏感字段必须脱敏。Credential、Secret、authorization header、完整用户密码永不记录。

## 8. 测试分层

- unit：领域规则/转换/结束策略；
- repository integration：真实 PostgreSQL；
- adapter integration：真实/可控 Provider；
- process integration：API/Runtime/Worker/Gateway；
- E2E：跨进程用户旅程；
- architecture：依赖边界和禁止 import；
- contract：Capability/Skill manifest/API schema。

## 9. 时间

内部 UTC/带时区 datetime；DB `TIMESTAMPTZ`。API ISO8601。不得使用 naive datetime 作为持久事实。

## 10. Feature Flag

架构主语义（如 Agent 是否发布、一个 Bot 是否多 Agent）不得隐藏在 flag 中。Flag 只用于可逆实现切换，不用于维持两套长期领域模型。
