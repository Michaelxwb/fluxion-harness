# 前端工程规范 V1.9.1

## 1. 技术基线

React 18 + TypeScript + Vite + Semi Design。数据访问统一通过 API client/query layer，页面不直接拼接 fetch 和错误处理。

## 2. 标准列表页

页面不重复大标题/说明。左侧导航 + breadcrumb 表达当前位置。

```text
[+ 主操作]                             [筛选] [搜索] [刷新]
┌────────────────────────────────────────────────────────┐
│ Table                                                  │
└────────────────────────────────────────────────────────┘
                                    每页 20 ▼  < 1 2 3 >
```

要求：

- 主操作左上；
- 筛选/搜索右上；
- 行操作最后一列；
- Pagination + Page Size 右下；
- 每页条数是页面级状态，不进入全局 Settings；
- 所有时间 `YYYY-MM-DD HH:mm:ss`；
- loading/empty/error 三态完整。

## 3. 新增/编辑/详情

- 简单对象：新增/编辑 Modal；
- 复杂 Service：独立编辑页；
- 普通详情：右侧 Drawer，只读；
- Skill 详情所有 Tab 只读；
- Agent 资源绑定属于 Agent 详情/配置，不塞进创建 Modal；
- Secret 编辑只显示“已配置/未配置”，永不回显原值。

## 4. 字段中文

业务页面所有字段使用中文显示；技术 key/schema/path 可保留英文输入，但必须有中文说明和示例。

## 5. 菜单

Builder：

- 概览；
- 服务；
- 智能体；
- 能力；
- Skill；
- 知识库（规划）；
- 模型；
- 项目平台；
- 执行记录。

Admin 增加“用户”，并显示正式发布/授权操作。

不提供：Channel、认证配置、ProjectIntegration、System Settings、Async Task 独立菜单。

## 6. 表单校验

前端校验用于体验，后端仍是权威。Schema/JSON 编辑必须有格式校验、示例和错误行定位。分页策略配置必须根据 pagination type 动态显示字段。

## 7. 交互反馈

- 保存成功 toast；
- 发布/删除/解绑/作废等危险操作确认；
- 长操作显示明确 progress/status；
- Test 操作展示输入、结果、耗时、error code；
- 不使用仅颜色表达状态，状态需文字。

## 8. 路由与状态

URL 应能表达列表/详情/复杂编辑页；Modal/Drawer 可由 search param/state 表达。刷新不得丢失核心编辑对象 ID。

## 9. 访问控制

V1 主要做菜单和按钮层控制。UI 隐藏不是安全边界；后端敏感写仍校验 Admin/Builder 身份。
