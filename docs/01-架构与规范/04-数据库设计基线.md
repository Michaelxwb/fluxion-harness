# 数据库设计基线 V1.13

## 1. 数据库定位

PostgreSQL 是 Fluxion Framework 权威业务状态（SoT）。Redis 不是 SoT；Object Store 保存 Artifact 大对象；Secret Provider 保存密钥。数据库设计必须从领域对象和交互契约反推，不允许“先建万能表再让产品适配”。

## 2. 公共字段

除第三方组件自管理表（如 LangGraph Checkpointer）外，**所有** Framework 自建表统一包含四个字段，不设例外：

```sql
id            UUID/TEXT PRIMARY KEY,
is_deleted    BOOLEAN NOT NULL DEFAULT FALSE,
create_time   TIMESTAMPTZ NOT NULL DEFAULT now(),
update_time   TIMESTAMPTZ NOT NULL DEFAULT now()
```

不可变表（`service_release`、`execution_snapshot`、`task_progress_event`、`artifact`、`skill_artifact`、`skill_artifact_capability`、`message`、`audit_log`）同样包含 `update_time`，但其业务内容**禁止 UPDATE**：`update_time` 仅由迁移触及；`skill_artifact` 的 validation_status/validation_report 禁止 UPDATE，复核结论只追加 `skill_artifact_validation_event`（append-only），schema 必须明确不可变语义。

## 3. 软删除

- Repository 默认 `is_deleted=false`；
- 业务唯一索引使用 partial unique index；
- 仍被 published release/execution 引用的资源禁止物理删除；
- 对审计有意义的数据优先 disable/revoke，不做删除；
- BindCode/Execution/Audit 采用状态生命周期，不通过软删表达完成状态。

## 4. ID

ID 不承载业务含义。外部稳定 key 独立字段，例如 `agent.key`、`capability.key`。禁止通过自增 ID 向外暴露资源总量。

## 5. JSONB

允许：

- JSON Schema；
- immutable snapshot；
- Implementation typed config；
- provider raw metadata（明确非查询核心）。

不允许：

- 用户-Agent 关系塞入 JSON 数组；
- Credential 明文；
- 用 JSONB 替代一对多表；
- 不受 Schema 约束的“万能 config”。

JSON config 必须有 `type/discriminator + Pydantic/schema validation`。

## 6. 索引

每张表设计时明确：

- PK；
- 唯一约束；
- 高频列表过滤；
- FK；
- Execution 状态 claim；
- Conversation time order；
- external identity lookup；
- bot route lookup。

禁止为所有字段盲目建索引。

## 7. 时间

DB 统一 `TIMESTAMPTZ`；业务 API 保留 offset；Console 转用户时区展示。过期/lease 字段必须使用 DB/服务端可信时间，不信任客户端时间。

## 8. Secret

DB 只保存：

```text
secret_ref
credential_version/metadata（非敏感）
verified_at
status
```

SecretProvider 写失败时数据库不得写“已配置”假状态。

## 9. 迁移

Alembic expand-contract：

1. additive column/table/index；
2. 双读/双写（如需）；
3. backfill；
4. switch；
5. 观察；
6. drop old。

涉及唯一约束或 NOT NULL 时，先清理数据再收紧。

### 9.1 V1.13.1 破坏性变更迁移附录

- `invocation_policy` 回填映射：`write/destructive/HIGH → EXECUTION_ONLY`（fail-closed），其余按原直调谓词回填；
- `request_timeout_ms → request_timeout_seconds` 改名双读（读旧毫秒/新秒，写新秒，观察后删旧列）；
- `service_definition.created_by` 先 nullable 上线 + 按发布审计回填，再收紧 NOT NULL（不可变）；
- 新增 2 张表：`skill_import_preview`、`channel_command_receipt`（additive 建表 + 索引，无双写）。

## 10. 事务边界

必须事务化：

- Service Publish；
- BindCode consume + channel_binding upsert（channel_identity 只读解析）；
- AgentAccessGrant create/revoke；
- UserProjectCredential ref switch；
- Execution state transition；
- Worker claim/lease；
- Skill import metadata commit（ObjectStore 先成功，DB 再提交；失败清理 orphan）；
- **Skill 预览暂存与提交**：preview 只写 `skill_import_preview`（不产生正式记录、不切 current），commit 锁 preview 与目标 Skill、校验 checksum 与 token 归属后原子落库并切 current；
- **提案签发与确认**：提案即建 `execution_snapshot`（source=FORMAL/TEST），`proposal.snapshot_id` 与 `execution.snapshot_id` 同 id 复用，不拷贝大 JSONB；签发（冻结 `ExecutionProjection` + snapshot + digest + confirmation_ref）为单事务；用户确认时“校验 confirmation_ref/digest 归属 → 创建 `service_execution` + root step + command 幂等行 → 标记提案 CONSUMED”必须在同一事务内，保证重复确认只创建一个 Execution；
- **TEST 草稿快照创建**：`execution_snapshot(source=TEST)` + root + steps 单事务，且 `service_release_id` 为空、`draft_revision`/`test_mode` 非空；
- **人工决策**：写 `execution_command`（PENDING，含 `requested_action`/`accepted_at`/`human_decision_at`）与审计单事务，且锁内校验 `human_deadline`；**不在 API 层推进 Step、不改已持有租约**；
- **重试派生**：创建新 Execution（`parent_execution_id`/`root_execution_id` 沿用、成功步骤结果复制、`execution_command(RETRY)` 同事务写 APPLIED/`result_execution_id`），禁止 Worker 二次应用 RETRY；
- **投递许可与结果回写**：`channel_delivery` 的 attempt 领取（`SENDING` + `attempt_token` + `lease_epoch`）与结果回写（`DELIVERED`/`NOT_SENT`/`UNKNOWN`）各自单事务，同一 epoch 不得二次许可；
- **Memory 受控写入**：校验 `MemoryPolicy`（key 白名单/值上限/条数上限）与来源证据后写入 `user_memory`，禁止写入业务权威事实。
