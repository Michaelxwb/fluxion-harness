# 接口设计基线 V1.12

> 本基线与《09-接口所有权与详细设计索引》及各模块 design-full 同步；接口的 Owner 与详细契约以 09+模块文档为准。

## 1. 命名空间

- Console/control plane：`/api/v1`
- Runtime internal：`/internal/v1`
- Skill development gateway：`/dev/v1`
- Channel adapter internal：`/internal/v1/channels/...`
- 运维观测：`/health/*`、`/metrics`（OPS-API-01..03，模块 15）

普通 JSON 使用统一 Envelope（SSE 除外）。Secret 字段读取永不回显。

**全局鉴权**：除 `POST /api/v1/auth/login` 外，所有 `/api/v1/*` 必须登录会话；Admin-only / Builder+Admin 按 ADR-021；`/internal/*` 仅 service-to-service token（详见 02-模块设计/README 全局 RULE）。

## 2. Agent API

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/v1/agents` | 列表，分页/搜索/状态/模型 |
| POST | `/api/v1/agents` | 新建基础信息 |
| GET | `/api/v1/agents/{id}` | 详情 |
| PUT | `/api/v1/agents/{id}` | 编辑基础信息，revision+1 |
| PUT | `/api/v1/agents/{id}/capabilities` | 替换/更新直接能力集合 |
| PUT | `/api/v1/agents/{id}/skills` | 绑定 Skill 集合 |
| PUT | `/api/v1/agents/{id}/services` | 可调用子 Service 集合 |
| GET | `/api/v1/agents/{id}/users` | 反向查看授权用户 |
| PUT | `/api/v1/agents/{id}/users` | Admin 授权集合/增量按实现定 |
| GET/PUT | `/api/v1/agents/{id}/channel/wecom` | 当前 Bot 配置（**Owner：Channel Gateway，CH-API-01/02**） |
| GET | `/api/v1/agents/{id}/effective-capabilities` | Agent 有效能力分析（AGENT-API-08） |

**不存在** `/agents/{id}/publish`。

WeCom Secret PUT 可以接受一次性 secret，GET 只返回 `secret_configured=true`。

## 5. Capability API

```text
GET/POST /api/v1/capabilities
GET/PUT /api/v1/capabilities/{id}
POST /api/v1/capabilities/{id}/test
GET /api/v1/capabilities/{id}/contract
```

Create/Update DTO 必须是 discriminated union：

```text
implementation.type = PLATFORM_SERVICE | HTTP | MCP | SANDBOX
```

### Platform Service DTO 重点

```json
{
  "project_platform_id": "pp_mss",
  "service_name": "customer-service-mgr",
  "operation": "list_customer",
  "auth_mode": "USER_PLATFORM",
  "execution_policy": {...},
  "data_retrieval_policy": {...}
}
```

只有该类型允许 `project_platform_id`。

### 分页 Policy

API 必须校验：

- type 对应字段；
- `items_path` 必填；
- max_pages/max_items/max_duration > 0；
- PAGE start/page_size 合法；
- Cursor 有 next_cursor_path；
- short_page_terminates 是显式布尔值，不由后端默猜；默认值 = true（短页即终止），Capability 定义可显式覆盖。

## 9. Execution API

```text
GET /api/v1/executions
GET /api/v1/executions/{id}
POST /api/v1/executions/{id}/cancel
POST /api/v1/executions/{id}/retry
POST /api/v1/executions/{id}/resume   # 人工审批：WAITING_HUMAN 时 decision=RESUME/CANCEL（EXE-API-05）
```

cancel/retry/resume 均 Admin-only。

详情必须包含：

- execution summary；
- steps/timeline；
- async task detail；
- delivery；
- artifact/result refs；
- error；
- timestamps。

列表无需“timeline”独立 endpoint 按钮语义，页面详情内部加载步骤即可；后端可按性能提供 `/steps` 子接口，但产品入口仍为详情。

## 10. Channel Gateway Internal Contract

外部适配器收到消息后构造可信 envelope，不允许正文提交 user_id/agent_id 替代服务端解析。

```json
{
  "channel_type": "WECOM",
  "channel_account_id": "...",
  "external_user_id": "wotvU***i4GA",
  "external_message_id": "...",
  "text": "...",
  "received_at": "...",
  "metadata": {}
}
```

Gateway：

1. account → agent；
2. identity → platform user；
3. grant check；
4. 构造 TrustedExecutionContext；
5. 调 Agent Runtime。

IM 命令（/bind、/skills、/new、/stop）由 Gateway 统一解析并转发（RULE-CHAN-06）；/bind 在正常 Agent 路由前截获执行，其余命令转发至对应模块（Skill 列表/会话创建/Execution 取消）。

后台主动投递：`POST /internal/v1/channels/deliver`（CH-INT-01，仅 Worker 调用；投递重试唯一 owner 是 Worker）。

## 12. Skill Dev Capability Gateway

```text
GET  /dev/v1/capabilities
GET  /dev/v1/capabilities/{key}/contract
POST /dev/v1/capabilities/{key}/invoke
```

目标是为本地 SDK 提供真实联调，不是第二套 Capability Runtime。

要求：

- 复用生产 Capability Resolver/Executor；
- 使用开发身份/token；
- 测试 user context 由服务端授权映射，不能任意冒充；
- 返回与生产 `ctx.capability.call` 一致的逻辑错误语义；
- 默认只在 dev/test 环境启用。

## 13. 列表 API 规范

统一输入：

```text
page=1
page_size=20
search=
sort=
filters...
```

page_size 有平台最大值（例如 100，具体可配置）但 Console 用户可在当前列表页选择常用条数。

统一返回：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0
}
```

这里是 **Fluxion Console API 自己的分页**，与 Capability 调用外部平台的 Data Retrieval Policy 是两个概念，不可混淆。

---

## 14. 错误与幂等

写 API 可通过 request_id/idempotency key 保护关键操作：

- Service publish；
- Skill import；
- BindCode consume；
- Execution create/cancel。

Publish 重复请求不能产生两个逻辑相同但未知状态的 Release。

---

## 15. API 评审 Gate

每个新增接口必须回答：

1. 对应哪个页面/Runtime 用例？
2. DTO 是否有 Domain 对象？
3. 数据最终落哪张表/外部系统？
4. 谁有权调用？
5. 是否包含 Secret？
6. 是否可重试/幂等？
7. 异常码是什么？
8. 对应哪个测试场景？
