# 接口设计基线 V1.13

> 本基线与《09-接口所有权与详细设计索引》及各模块 design-full 同步；接口的 Owner 与详细契约以 09+模块文档为准。

## 1. 命名空间

- Console/control plane：`/api/v1`
- Runtime internal：`/internal/v1`
- Skill development gateway：`/dev/v1`
- Channel adapter internal：`/internal/v1/channels/...`
- 运维观测：`/health/*`、`/metrics`（OPS-API-01..03，模块 15）

普通 JSON 使用统一 Envelope，**显式例外**：SSE（`/internal/v1/chat`）与 `GET /metrics`（Prometheus exposition，`text/plain; version=0.0.4`，裸文本不套 Envelope）。Secret 字段读取永不回显。

**全局鉴权**：除 `POST /api/v1/auth/login`、`POST /api/v1/auth/logout` 外，所有 `/api/v1/*` 必须登录会话；`/health/*`、`/metrics` 豁免（部署网段限制，仅运维网段可达）；Admin-only / Builder+Admin 按 ADR-021 与 ADR-046；`/internal/*` 仅 service-to-service token（JWT，`audience` + `scope`，由模块 09 `AUTH-LIB-02` 签发与校验）。

**Console 登录**：登录契约 Owner=模块09 AUTH-LIB-0x，校验规则：role∈{ADMIN,BUILDER}映射platform_user.id，END_USER不可登录，会话过期/锁定行为见09；本基线只冻结其对外契约与身份归属：`POST /api/v1/auth/login` 返回 `{token, username, role}`（`role ∈ {ADMIN, BUILDER}`），Bearer 有效期 12h，`ADMIN/BUILDER` 与 `platform_user.role` 一一对应，`END_USER` 不可登录 Console；所有“仅 Admin”判定的主语、`granted_by` 与 `audit_log.actor_user_id` 均取该登录用户对应的唯一 `platform_user.id`（详见模块 09）。**身份与角色不在登录响应里缓存消费**：客户端一律以 `GET /api/v1/auth/me`（`AUTH-API-01`，ADR-067/D14）作为“我是谁/我是什么角色”的唯一事实源；登录响应只表示会话已建立。

## 3. Model API

```text
GET/POST /api/v1/models
GET/PUT /api/v1/models/{id}
POST /api/v1/models/{id}/test
```

V1 protocol 固定 OpenAI-compatible；编辑立即对新请求生效。

字段单位与可选字段（ADR-044）：`request_timeout_seconds`（秒，默认 60，1..600，**不使用毫秒**）、`extra_headers`（仅非敏感 Header，禁止承载凭据）。读投影按 ADR-058 裁决#4 三态重写：列表安全只读（不含 `base_url/api_key/extra_headers`，仅 `key/name/protocol/model_name/enabled/revision/api_key_configured`）；详情 Builder 可见 `base_url/default_parameters/request_timeout_seconds`（可写，新增/编辑表单必填项）；仅 `api_key/extra_headers` Admin-only（非 Admin 出现含 `null/{}` 显式清空同样拒绝）。

## 5. Capability API

```text
GET/POST /api/v1/capabilities
GET/PUT /api/v1/capabilities/{id}
POST /api/v1/capabilities/{id}/test
GET /api/v1/capabilities/{id}/contract
```

Contract 元数据（字段级合同见模块 07）：

```text
side_effect              = none | read | write | destructive
risk_level               = LOW | MEDIUM | HIGH
invocation_policy        = DIRECT | EXECUTION_ONLY   # 直调结论（ADR-057；凭据来源见 implementation.auth_mode）
```

`write`/`destructive`、`HIGH`、`invocation_policy=EXECUTION_ONLY` 的 Capability **不得被 Agent 直调**；调用方只比较 CAP-API-06 的派生字段 `direct_invocation`（ADR-057）。

Create/Update DTO 必须是 discriminated union，**字段以模块 07 的 `capability-implementation-schema` 为准**（本基线不重复定义）：

```text
implementation.type = PLATFORM_SERVICE | HTTP | MCP | SANDBOX
```

### Platform Service DTO 重点

```json
{
  "project_platform_id": "pp_mss",
  "service_key": "customer-service-mgr",
  "auth_mode": "USER_PLATFORM",
  "request_mapping": {...},
  "response_mapping": {...},
  "execution_policy": {"deadline_ms": 30000, "max_retries": 0, "backoff_ms": 0},
  "data_retrieval_policy": {...}
}
```

只有该类型允许 `project_platform_id`。超时与重试**只属于 `execution_policy`**，不放 `config`。

### 分页 Policy

API 必须校验：

- type 对应字段；
- `items_path` 必填；
- max_pages/max_items/max_duration > 0；
- PAGE start/page_size 合法；
- Cursor 有 next_cursor_path；
- short_page_terminates 是显式布尔值，不由后端默猜；默认值 = true（短页即终止），Capability 定义可显式覆盖。

## 9. Execution API

```text
GET /api/v1/executions
GET /api/v1/executions/{id}
POST /api/v1/executions/{id}/cancel
POST /api/v1/executions/{id}/retry
POST /api/v1/executions/{id}/resume   # 人工审批：WAITING_HUMAN 时 decision=RESUME/CANCEL（EXE-API-05）
GET /api/v1/executions/{id}/artifacts/{artifact_id}/download   # 受权字节流下载（EXE-API-06）
POST /api/v1/executions/{id}/redeliver # 重新投递：仅 delivery_status ∈ {FAILED, UNKNOWN}，不重跑业务步骤（EXE-API-07，ADR-054）
```

列表/详情 Builder+Admin（Builder 可见范围见 ADR-052）；cancel/retry/resume/redeliver 均 Admin-only（END_USER 经 `/internal/v1/commands` 的 STOP/RESUME/CANCEL 走同一 Application，见模块 10 `CH-INT-02`）。

兼容期：老数据缺 `invocation_policy` 缺省 `EXECUTION_ONLY`（fail-closed）；缺 `current_step_name` 缺省回退 `current_step`（仅技术标识展示）。

详情必须包含：

- execution summary（含脱敏 `resource_scope_summary` 与 `delivery_status`，见 ADR-048）；
- steps/timeline；
- async task detail；
- delivery；
- artifact/result refs；
- error；
- timestamps。

下载接口返回**受权字节流**（校验租户 + 执行归属），不返回 ObjectStore 的 `object_ref` 或公开签名 URL；END_USER 经 IM `/result` 重取原生文件，链接/取件过期语义见模块 05。

列表无需“timeline”独立 endpoint 按钮语义，页面详情内部加载步骤即可；后端可按性能提供 `/steps` 子接口，但产品入口仍为详情。

## 10. Channel Gateway Internal Contract

外部适配器收到消息后构造可信 envelope，不允许正文提交 user_id/agent_id 替代服务端解析。

```json
{
  "channel_type": "WECOM",
  "channel_account_id": "...",
  "external_user_id": "wotvU***i4GA",
  "external_message_id": "...",
  "text": "...",
  "received_at": "...",
  "metadata": {}
}
```

Gateway：

1. account → agent；
2. identity → platform user；
3. grant check；
4. 构造 TrustedExecutionContext；
5. 调 Agent Runtime。

IM 命令由 Gateway 统一解析并转发（RULE-CHAN-06）：`/bind` 在正常 Agent 路由前截获并由本模块执行；其余经 `CH-INT-02`（`POST /internal/v1/commands`，Owner=模块 10）转发给 agent-runtime 的领域 Application，动作集合为 `SKILLS / NEW / STOP / RESUME / CANCEL / MEMORY_LIST / MEMORY_CLEAR / RESULT / CONFIRM`（Playbook 的 `/bind /skills /new /stop` 是用户可见子集）；`/memory remember` 不走命令，由普通消息经 Agent 的受控 Memory 工具写入（ADR-037）。禁止调用 Console 端点。

后台主动投递：`POST /internal/v1/channels/deliver`（CH-INT-01，仅 Worker 调用；投递重试唯一 owner 是 Worker）。请求只带 `{delivery_id, attempt_token}`，路由与内容由 Worker 预建的 `channel_delivery` 行决定，**不接受请求临时指定 route/user**；单次调用只发一次，结果（`DELIVERED`/`NOT_SENT`/`UNKNOWN`）回写 PG。

Gateway 运行面数据（Bot 配置与短时 SecretLease、入站解析、发送许可、附件取流）经 agent-runtime 承载的 `CH-DATA-01..04` 获取，**不直连业务库、不经过 platform-api**（Gate H）。

## 12. Skill Dev Capability Gateway

```text
GET  /dev/v1/capabilities
GET  /dev/v1/capabilities/{key}/contract
POST /dev/v1/capabilities/{key}/invoke
```

目标是为本地 SDK 提供真实联调，不是第二套 Capability Runtime。

要求：

- 复用生产 Capability Resolver/Executor；
- 使用 **Developer Token**（由模块 09 `AUTH-LIB-03` 签发与校验：dev tenant + scope + TTL + test-user allowlist）；Mock 本地模式不需要 token；
- 测试 user context 由服务端授权映射，不能任意冒充（越界返回 `TEST_USER_NOT_ALLOWED`，失效返回 `DEV_TOKEN_INVALID`）；
- 返回与生产 `ctx.capability.call` **一致的数据形态**（列表能力返回数组，映射返回对象）与逻辑错误语义；
- 默认只在 dev/test 环境启用（生产不注册该 Provider）。

## 13. 列表 API 规范

统一输入：

```text
page=1
page_size=20
search=
sort=
filters...
```

page_size 有平台最大值（例如 100，具体可配置）但 Console 用户可在当前列表页选择常用条数。

统一返回：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0
}
```

这里是 **Fluxion Console API 自己的分页**，与 Capability 调用外部平台的 Data Retrieval Policy 是两个概念，不可混淆。

## 14. 错误与幂等

写 API 可通过 request_id/idempotency key 保护关键操作：

- Service publish；
- Skill import（preview 与 commit 两阶段，commit 以 `preview_token` 幂等）；
- BindCode consume；
- Execution create/cancel；
- **提案确认**（同 `proposal_id` + 真实确认消息只创建一个 Execution）；
- **人工决策**（同 `idempotency_key` 返回原结果，含已超时/终态；相反决策 `HUMAN_DECISION_CONFLICT`）；
- **重试派生**（同父执行不得产生两个子执行）；
- **投递许可**（同 `attempt_token`/`lease_epoch` 不得二次发送）。

Publish 重复请求不能产生两个逻辑相同但未知状态的 Release。

**错误码**：错误码的注册表与错误分类（可重试性判定）见《10-错误码与错误分类基线》；模块接口表中出现的错误码必须能在该注册表中查到，未登记的按“新增错误码”流程补录。

## 15. API 评审 Gate

每个新增接口必须回答：

1. 对应哪个页面/Runtime 用例？
2. DTO 是否有 Domain 对象？
3. 数据最终落哪张表/外部系统？
4. 谁有权调用？
5. 是否包含 Secret？
6. 是否可重试/幂等？
7. 异常码是什么？
8. 对应哪个测试场景？
