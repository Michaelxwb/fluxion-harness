# 数据库表所有权与字段索引（V1.13）

> 本文由各模块 `design-full` 的 §3.3 汇总。**字段完整定义、索引和约束一律以对应模块文档为准**；本文与模块不一致时以模块为准，并视为本文需要重生成。
> 本轮按 Owner 文档重生成：补齐 4 张缺失表（`execution_proposal`/`skill_import_preview`/`conversation_run`/`channel_command_receipt`），修正与 Owner 冲突的唯一键（`execution_snapshot`、`async_task_run`）与字段名（`execution_source`、`request_timeout_seconds`）。
> Knowledge 当前规划中，不建立生产表。

## 0. 一致性校验

- 模块 §3.3 定义的物理表集合必须与本文「2. 表所有权」完全一致（无差集，无幽灵表）。
- 唯一键/约束必须与 Owner 模块 §3.3 的“约束与索引”逐字一致；发现不一致时先修模块再重生成本文。
- `tests/architecture/` 的文档一致性测试应覆盖该比对（见 `04-追溯与验收/03-设计验收Gate.md` 的 Gate G14）。

## 1. 公共规则

- PostgreSQL 是 Framework 业务 SoT；Redis 不是 SoT。
- Framework 自建可变表：`id UUID` + `is_deleted` + `create_time` + `update_time`；不可变表无业务 UPDATE。
- 所有表 tenant scoped；Secret 明文不入表。
- 一个领域事实只允许一个 owner 表；禁止为了页面/Runtime 创建 shadow table。
