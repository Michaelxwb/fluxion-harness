# 错误码与错误分类基线（V1.13）

> 本文件是错误码的**唯一注册表**（第三轮 Review 修复，T-35）。模块接口表与处理逻辑中出现的错误码必须能在下文查到；未登记的先补录再使用。
> 命名约定：`RESOURCE_ACTION`（UPPER_SNAKE），HTTP 状态习惯 `404` 资源缺失 / `409` 冲突或前置缺失 / `422` 校验失败 / `403` 越权 / `401` 未认证 / `410` 已清理 / `500` 兜底。
> 错误码常量与所属契约同模块定义（`contracts/`），全局唯一，不得重复。

## 1. 错误分类（可重试性判定的唯一依据）

外部调用（HTTP/RPC/MCP/DB/LLM/ObjectStore/Auth）失败必须归类到下列之一，Worker 的重试与转人工判定只依赖该分类（RULE-WORK-04）：

| 分类 | 含义 | 处置 |
|---|---|---|
| `RETRYABLE_TECHNICAL` | 连接/超时/5xx/限流等临时故障 | 有界指数退避重试，达上限按 failure_policy 收敛 |
| `AUTH_EXPIRED` | 凭据有效但 Session 过期 | 触发 AuthProvider 刷新后**重试一次**；刷新失败升级为 `CREDENTIAL_INVALID` |
| `CREDENTIAL_INVALID` | 长期凭据失效或被撤销 | 立即拒绝，不自动恢复，通知用户重新配置（ADR-036） |
| `BUSINESS_REJECTED` | 业务系统明确拒绝（权限/前置条件不满足） | 不重试，按 failure_policy 终止或转人工 |
| `SEMANTIC_INVALID` | 输入/语义校验失败 | 不重试，终止并给出 field_errors |
| `USER_ACTION_REQUIRED` | 需要人工决策/补全 | 直接进入人工检查点（WAITING_HUMAN） |
| `FATAL` | 不可恢复的平台缺陷/数据不一致 | 终止并告警，不重试 |

**禁止**：`while True` 无界重试；把 `BUSINESS_REJECTED` 当技术故障重试；把 `AUTH_EXPIRED` 当长期凭据失效拒绝。
