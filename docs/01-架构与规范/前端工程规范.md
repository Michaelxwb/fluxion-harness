# 前端工程规范

> **适用范围**：Console Web 前端。  
> **唯一通用 UI 组件库**：Semi Design。

## 1. 技术栈

```text
React 18
TypeScript
Vite
React Router
Semi Design
Axios（统一 Service 层封装）
```

禁止同时引入 Ant Design、MUI、Element 等第二套通用组件库。

## 2. 页面分层

```text
Page
→ Hook / State
→ Service
→ API

Page
→ Shared Components
→ Semi Design
```

展示组件不直接调用 API。

组件中禁止出现裸 `fetch/axios`；所有远程调用进入 `services/` 或等价 API Client。

## 3. 标准列表页

所有普通 CRUD/资源列表页默认必须使用统一 `StandardListPage`。

固定排版：

```text
页面标题

┌────────────────────────────────────────────────────────────┐
│ [新增/主要操作]                     [过滤][筛选][搜索][刷新] │
├────────────────────────────────────────────────────────────┤
│                         Table                              │
├────────────────────────────────────────────────────────────┤
│                                  Pagination（右下角）       │
└────────────────────────────────────────────────────────────┘
```

规则：

- 主按钮固定左上；
- 过滤、筛选、搜索固定右上；
- 行操作固定 Table 最后一列；
- Pagination 固定列表底部右侧；
- Semi Table 自带分页关闭，由统一 Footer 控制；
- 空态、加载、错误态统一处理。

## 4. 详情与编辑

默认模式：

```text
详情
→ 只读 Drawer

新增
→ Modal / 独立 Form

编辑
→ Modal / 独立 Page / Form
```

详情 Drawer 不承担隐式编辑。

Service/Agent 的草稿编辑与发布按钮只能出现在明确的编辑/发布流程中。

## 5. API Envelope

前端统一解析：

```ts
interface ApiEnvelope<T> {
  code: string;
  message: string;
  data: T;
  request_id: string;
  timestamp: string;
}
```

业务页面不得自行猜测其他错误结构。

## 6. UI 四态

任何异步视图至少处理：

```text
loading
empty
error
success
```

Error 应提供明确提示；可重试场景提供重试入口。

## 7. 样式

优先使用 Semi Design Token 与统一 CSS 变量。

禁止在大量页面散落重复魔法值。

公共页面间距、Toolbar、Table、Drawer、Modal、Pagination 统一封装。

## 8. 可访问性

- 所有 Icon-only Button 必须有 `aria-label`；
- 表单错误应关联字段；
- Modal/Drawer 打开后焦点可进入、关闭后回到触发点；
- 不只用颜色表达状态。
