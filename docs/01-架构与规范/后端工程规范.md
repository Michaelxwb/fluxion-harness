# 后端工程规范

> **适用范围**：`platform-api`、`agent-runtime`、`worker`、`channel-gateway` 以及 Framework Core。Python 与 TypeScript 实现可以不同，但日志字段、错误码和普通 JSON Response Contract 必须一致。

## 1. 统一响应

所有普通 JSON REST API 使用统一响应体：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "request_id": "01...",
  "timestamp": "2026-09-10T15:00:00+00:00"
}
```

规则：

- 业务成功统一 `code=OK`；
- 错误仍使用同样 Envelope；
- HTTP Status 与错误语义一致；
- `request_id` 同时写入 `X-Request-ID`；
- Feature Router 禁止手写另一套 `{error: ...}`；
- SSE、WebSocket、文件流属于协议例外，不强制包 JSON Envelope，但错误码命名必须复用统一 taxonomy。

## 2. 统一异常

领域/应用层抛出统一 `AppError` 派生异常：

```text
code
message
http_status
details（按需）
```

全局异常管线统一处理：

```text
RequestValidationError
HTTPException
AppError
Unknown Exception
```

Unknown Exception 对外不能泄露内部堆栈、SQL、Credential 或路径。

## 3. 统一日志

所有后端运行角色生产环境输出结构化 JSON 到 stdout。

Python 使用统一 logging/bootstrap；Node.js/TypeScript Channel Gateway 使用等价 JSON logger。两种语言必须保持公共字段一致，不能因为语言不同形成第二套日志格式。

公共字段至少包括：

```text
timestamp
level
logger
message
service
request_id
event
trace_id（可获取时）
```

HTTP access log 还应包括：

```text
method
path
status
latency_ms
client_ip
```

Worker/Execution 日志还应包括：

```text
execution_id
step_id
worker_id
attempt
capability
```

## 4. 敏感信息

禁止日志明文：

```text
Authorization
Cookie
Access Token
Refresh Token
Password
Credential
Secret
External Session
完整敏感业务 Payload
```

Sandbox Tool 日志默认只记录：

```text
workspace_id
capability
execution_id / conversation_id
duration_ms
exit_code
bytes_read / bytes_written
```

不记录完整文件内容和 stdout/stderr。

## 5. Request ID 与 Trace

入口请求：

```text
已有 X-Request-ID
→ 校验后复用

无 X-Request-ID
→ 服务端生成
```

内部 HTTP 调用透传：

```text
X-Request-ID
traceparent
```

异步 Execution 通过：

```text
trace_id
execution_id
```

关联在线请求与后台任务。

## 6. 分层与依赖

推荐：

```text
Router / Handler
→ Application Service
→ Repository / Runtime SPI
→ Adapter
```

禁止：

```text
Router 直接写 SQL
Domain Import FastAPI
Domain Import SQLAlchemy ORM
Framework Core Import integrations/*
```

## 7. 配置

所有进程使用同一 Settings 约定：

```text
环境变量
→ Settings
→ 强类型配置对象
```

Secret 只保存引用，明文从 Secret Provider 读取。

## 8. 代码质量

至少执行：

```text
ruff
mypy
pytest
architecture tests
```

任何跨边界的重要约束必须尽量用自动化测试，而不是只写在文档里。


## 9. 跨语言统一约束

`channel-gateway` 使用 Node.js/TypeScript，但普通内部 JSON API 仍遵循：

```text
code
message
data
request_id
timestamp
```

结构化日志仍遵循：

```text
timestamp
level
service
event
request_id
trace_id（可用时）
```

允许字段类型/Logger SDK 不同，不允许字段语义不同。

WebSocket/Channel 原生协议不套 JSON API Envelope，但内部异常必须映射到统一 `error_code` taxonomy，并在日志中携带 `request_id/trace_id/channel/account_id/message_id` 等可关联字段。
