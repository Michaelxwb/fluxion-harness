# 架构基线

> **状态**：与《通用智能服务执行框架 V1.6 总体设计说明书》+《05-变更记录/V1.6-to-V1.7-整改对齐说明》（V1.7 D01-D08）对齐  
> **适用范围**：Framework Core、四个运行角色、Project Integration  
> **目的**：把总体设计中的关键边界转成编码期必须遵守的简明规则。

## 1. 运行主链

```text
Channel
  ↓
Channel Gateway
  ↓
Agent Runtime（无状态，可运行多个 Agent Definition）
  ├── 普通问答 / 短时只读 Capability
  └── ExecutionService.create()
          ↓
      PostgreSQL
          ↓
        Worker
          ├── Agent Step
          ├── Capability Step
          └── System Step（Wait / Human / Delivery）
```

`platform-api` 是旁路 Control Plane，不是每次终端用户请求的同步必经节点。

## 2. 四个生产运行角色

| 运行角色 | 主要职责 | 默认扩缩方式 | 是否保存业务权威状态 |
|---|---|---|---|
| `platform-api` | Console、控制面 API、发布、授权、查询 | 通常 1 副本；有 HA 需求再扩 | 否 |
| `agent-runtime` | 实时 Agent、Conversation turn、Memory、短时 Capability | HPA/KEDA | 否 |
| `worker` | ServiceExecution 可靠执行、Wait/Retry/Recovery | HPA/KEDA | 否 |
| `channel-gateway` | Channel Adapter、连接、消息归一化、主动投递 | 按连接/投递负载扩 | 连接可有状态，业务无状态 |

PostgreSQL、Redis、Object Store、Secret Provider、OTel Collector 均为外部基础设施。

## 3. Framework 与 Integration 边界

```text
framework/**
  = 通用领域、Contract、Runtime、Worker、扩展 SPI

adapters/**
  = 通用协议/基础设施实现，例如 HTTP、PostgreSQL、Redis、Sandbox

integrations/**
  = 项目专属 Service / Agent / Capability / Auth / Knowledge

apps/**
  = 可部署进程的装配入口
```

硬约束：

```text
Framework Core
❌ 不依赖 integrations/*

Framework Core
❌ 不出现项目专属领域模型

Integration
✅ 依赖 Framework Contract/SPI
✅ 可以依赖项目 SDK / API
```

## 4. Agent 与 Runtime

`Agent Definition` 是管理员/Builder 创建的配置对象。

`Agent Runtime` 是共享计算池。

```text
Agent A ─┐
Agent B ─┼──→ Agent Runtime Pool
Agent C ─┘
```

禁止：

```text
Agent A → 固定 Pod A
User A  → 固定 Runtime
```

## 5. Chat 与 Execution

只有下列操作允许实时路径直接执行：

```text
短时
+
无副作用
+
风险可接受
```

其余动作进入：

```text
Agent Proposal
→ ExecutionService
→ ServiceExecution
→ Worker
```

`ExecutionService` 是共享 Application Service，不是独立微服务。

## 6. Capability、Knowledge、Auth、Channel

四类扩展点保持分离：

```text
Capability
→ 能做什么

Knowledge
→ Agent 可以查询什么知识

Auth
→ 如何获得外部系统调用身份

Channel
→ 用户消息从哪里来、结果发到哪里
```

不要把四类都收敛成万能 Resource/Plugin。

## 7. Workspace 与 Sandbox

OpenClaw 风格的 `read_file/write_file/edit_file/glob/grep/shell` 统一作为 Sandbox-backed Capability：

```text
Capability Runtime
→ SandboxCapabilityProvider
→ SandboxExecutor
→ Workspace
```

`Workspace` 归 Conversation/Execution，不归 User Pod。

Agent Runtime 禁止直接执行 Host Shell 或访问任意 Host 文件路径。

## 8. 状态事实源

| 数据 | 权威位置 |
|---|---|
| 用户、绑定、授权 | PostgreSQL |
| Agent/Service Published 配置 | PostgreSQL/Object Store |
| Conversation/Memory | PostgreSQL |
| Execution/Step/Command | PostgreSQL |
| Artifact | Object Store + PostgreSQL metadata |
| Credential | Secret Provider |
| Worker wake-up/cache | Redis，可丢失、可恢复 |
| LangGraph checkpoint | PostgreSQL Checkpointer 表 |

Redis 不能成为业务唯一事实源。

## 9. 版本与生效

只对 `Service` 和需要独立发布的关键 `Agent` 提供：

```text
草稿
→ 已发布
```

其他运行配置：

```text
校验
→ 保存
→ 直接生效
```

内部使用 `revision/audit/checksum` 留痕，不建设通用版本中心。

## 10. 架构 Gate

编码期至少保持：

```text
Core Purity
Stateless Runtime
Worker Crash Recovery
Redis Down
Control Plane Down
Execution Snapshot
Capability Contract Reuse
AuthProvider Replaceability
External Knowledge Provider
Workspace / Sandbox Boundary
统一 Response / Logging
前端 Semi Design / StandardListPage
```

## 11. 数据库公共字段

所有 Framework 自建表统一继承：

```text
is_deleted
create_time
update_time
```

任何新表缺失其中任一字段都必须由 Architecture Gate 阻止合并。
