# 模块分档与文档拆分验收 — V1.11

## 1. 目标

本次整改不是“给原文件贴 Full/Lite 标签”，而是把文档目录本身变成架构边界：后端每个一级模块独立目录，前端每个产品模块独立 `design-frontend.md`。

## 2. 后端 Gate

- 后端模块目录数：19；
- Full：18；Lite：1；
- 每个模块目录只存在一个主设计事实源 `design-full.md` 或 `design-lite.md`；
- DB Owner 只能在一个模块主设计中出现；
- Interface Owner 只能在一个模块主设计中出现；
- Full 文档继续保留逐表字段/约束/索引/ER 和逐接口请求/响应/错误码/处理逻辑。

## 3. 前端 Gate

- 前端产品模块：11；
- 每个模块独立 `design-frontend.md`；
- 每个模块必须写路由、角色、组件、字段、UI 四态、API 映射、风险；
- 公共 Shell/StandardList 独立模块，不在各页面复制实现；
- 交互事实继续由 V0.8/`90-Console交互规格.md` 控制。

## 4. 禁止回退

以下情况判定文档结构回退：

1. 再次把全部 Console 页面合回一篇大文档；
2. 为“平均使用模板”把复杂模块降级成 Lite；
3. 同一 DB 表在多个模块重复定义；
4. 同一 API Contract 在多个模块重复定义；
5. 为每个表/每个 API 创建独立设计文件造成碎片化；
6. Knowledge 未冻结时伪造 CRUD/API/DB。
