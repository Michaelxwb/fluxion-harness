## 其他需要统一的边界

1. **Console 登录前置条件**：FE-00 假设有角色上下文，WEB-LIB-03 假设有 session/token，但 docs 没有冻结登录/当前身份/失效恢复的合同。若由外部 SSO 或已有仓库能力提供，应明确依赖文档和 Owner；不据此强行要求自建账号系统。
2. **Service 紧急停用**：总设要求停用实时绕过 Draft，模块有 enabled 字段，但唯一更新入口主要是“保存 Draft”。应明确该字段是否即时更新定义、安全检查在哪一层执行。不能把前端声明的 Release 回滚后置扩大解释为紧急停用也后置。
3. **跨语言 Gateway**：当前已声明 Node/TypeScript，Python 示例注明伪代码，因此不把 Python 示例本身当技术栈错误。仍需明确 Python Control Plane 拥有的服务如何供 Node Gateway 调用、DB migration Owner 与运行进程职责；“业务 SoT 在 platform-api”应改成准确的 PG/领域 Owner 表述。
4. **Gateway 扩容**：已有多 Bot 单进程设计，但尚未冻结多 Gateway 的 Bot 连接归属、请求到错实例时的投递转发和 Redis 不可用时的冲突处理。若 V1 先单副本，应明确阶段边界和扩容前 Gate。
5. **Resource Governance**：新增环境变量已给默认值，但 per-capability 并发是单进程还是整个 Worker 集群、资源 class 来源和槽位释放流程仍未明确；总设 P1 的资源分组/priority 被模块提升为 P0，也应同步排期口径。

这些是待细化/确认的外部边界，不作为已证实的代码故障，也不与上面的 25 项重复计数。

## 建议修订次序与验收

1. 先闭合 Execution 主合同：Proposal/确认、Draft 测试来源、快照投影、五类 Step、完整状态机（R01–R08）。这些决定后端存储、接口和前端编辑器。
