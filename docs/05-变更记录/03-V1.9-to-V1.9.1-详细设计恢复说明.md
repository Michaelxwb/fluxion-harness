# V1.9 → V1.9.1 详细设计恢复说明

## 1. 背景

V1.9 完成了最新领域决策收敛，但在整理过程中将大量原 V1.7 `design-full` 模块文档压缩成概念摘要，造成以下信息丢失：

- 功能清单与 RULE；
- 正常/异常场景；
- 方案选型与被否决方案；
- DB 字段/唯一约束/索引；
- API 路径与输入语义；
- 生命周期/状态机；
- DFX；
- 部署/回滚；
- 风险依赖；
- 需求追溯与 Compliance Matrix。

这会重新产生“开发人员根据摘要自行猜接口/DB”的问题，与本轮交互驱动设计的目的相反。

V1.9.1 不改变 V1.9 已评审的核心方向，而是恢复详细设计深度，并把最新交互结论系统性落入每个模块。

## 2. 保持不变的 V1.9 结论

- ProjectPlatform / ProjectIntegration 拆分；
- AgentAccessGrant；
- ChannelIdentity / ChannelAccount / Grant 三关系；
- 一个 bot_id 一个 Agent；
- Skill 离线 Python + SDK；
- Skill manifest 依赖单事实源；
- Skill Artifact immutable；
- Capability 自动分页；
- Service 必须主 Agent；
- 只有 Service 发布；
- Knowledge 后置；
- Execution 统一 Async Task；
- Console 最新页面规范。

## 3. V1.9.1 恢复的详细度

每个核心模块统一恢复 `design-full`：

## 4. 新增/强化细节

### Capability

完整定义 Data Retrieval Policy、分页结束优先级、空列表兜底、max_pages/max_items/max_duration、重复页、大结果 Artifact。

### Skill

明确离线目录、manifest、Runtime load、SDK host、immutable Artifact、manifest dependency、禁止 Console binding。

### Skill SDK

详细 Mock/Dev Gateway/Production 三模式、Public API、CLI、semver、transport transparency、安全边界。

### Channel

详细 Bot connection、bot→Agent、identity→User、grant、/bind、主动推送、多 Gateway 风险和双 Bot 身份稳定性验证。

### User/Auth

详细 `user × project_platform` 唯一 Credential、SecretProvider、verify、缺失失败语义。

### Service/Execution

详细主 Agent、Draft/Release、Worker 状态、AsyncTaskRun、cancel、snapshot/dynamic security。

### Frontend

逐页面固定列表字段、新增字段、编辑字段、详情字段、Tab、按钮、权限、页面 API 映射。

## 5. 文档基线规则

V1.9.1 之后不得再次把 design-full 模块压缩成摘要作为“最终设计”。如需要快速阅读，可新增 overview/summary，但详细模块文档必须保留作为事实基线。
