# V1.13.1：第四轮「设计合理性」裁决修复

> 依据：`04-追溯与验收/10-设计合理性Review-2026-09-12.md`（60 条发现：7 项需裁决的取舍 + 15 项次优 + 14 处交互稿分歧，另有 3 路独立批判新增的 Q-01..Q-11 / Y-01..Y-10 / Z-01..Z-15）。
> 本轮回答的问题不是"有没有承接"（前三轮已闭合），而是"**承接的东西本身是否合理、是否最优**"。用户裁决「修复所有问题」。

## 一、需要裁决的取舍（已按建议落地）

| 编号 | 裁决 | 结果 |
|---|---|---|
| D1 | Capability 判定收敛 | 新增单一结论字段 `invocation_policy ∈ {DIRECT, EXECUTION_ONLY}`；**删除** `execution_characteristic`/`authorization_requirement`/`error_semantics`；凭据来源唯一由 `implementation.auth_mode` 表达；直调谓词唯一事实源（ADR-057） |
| D2 | 模型/平台字段级授权 | 新增/编辑对 Builder 开放；`api_key`、`auth_type`/`auth_schema` 仅 Admin 可写，越权 `FIELD_ADMIN_ONLY`(403) 原子拒绝（ADR-058） |
| D3 | Gateway 数据通路 | 保持 agent-runtime 承载，但补「运行面 vs 管理面」可用性合同与备选触发条件（ADR-060） |
| D4 | 两个「重试」拆开 | 「重新执行」(EXE-API-04) 与「重新投递」(新增 EXE-API-07) 分离；END_USER 自助重试与来源会话查看显式后置（ADR-054） |
| D5 | `resource_scope` 收敛 | 最小 typed 形态 `{type, refs[], attributes?}`；删除 Service 级 Scope Schema、`schema_hash`、Registry 推导（ADR-050） |
| D6 | Builder 执行可见范围 | 新增 `service_definition.created_by`；Builder 只看自己创建的 Service ∪ 被授权 Agent 的执行，越界视为不存在（ADR-052） |
| D7 | 后置项 | 写入模块 05 §2.4 与 ADR-054 |

## 二、机制层次优项（全部修复）

- **B1/Q-03**：新增 `CORE-LIB-08 LeaseQueue` 唯一租约原语（claim/renew/release/assert_owner），`service_execution` 与 `conversation_run` 共用；消除两套 epoch/续租实现。
- **B2/Q-05**：新增 `current_step_name`（业务可读阶段名），`current_step`（step_key）降为技术标识（ADR-051）；`EXE-API-01` 增 `error_code` 筛选以支撑概览卡跳转。
- **B3/Q-06/Y-06**：新增《01-架构与规范/11-数据保留与清理策略》（14 类数据的保留期/清理者/引用义务 + 维护任务职责）；新增 `INFRA-LIB-06 delete_object`、`INFRA-LIB-07 delete_secret`。
- **B4**：`browser`/`external-scan`/`large-report` 槽位改集群级 PG 信号量（协调表 `worker_slot_lease`），其余保持进程内计数（ADR-056）。
- **B5/Q-01**：随 D1/D5 删除冗余抽象（`error_semantics`、Scope Registry/`schema_hash`）。
- **B6**：产物访问判定以 `artifact` 表 FK 为准，`artifact_ids` 仅记录复制来源（ADR-053）。
- **B7**：`audit_log.details` 结构定死为 `changed_fields[{field,before,after}]`（Secret 掩码 `***`）。
- **B8**：`MemoryPolicy` 给出 typed schema（`enabled`/`allowed_keys`/`max_value_bytes`/`max_items`/`write_mode`），空 `allowed_keys` = fail-closed。
- **B9**：`extra_headers` 改 Header 名 allowlist（拒绝凭据类名 + 值上限 1024）。
- **B10**：`PLATFORM_SERVICE` config 补寻址字段 `service_key` + `path` + `method`（对齐交互稿三控件）。
- **B11/Q-09**：步骤 schema 新增 `human_policy ∈ {never, on_uncertainty, always}`，与 `failure_policy` 正交（ADR-055）。
- **B12/B13/B14**：前端与原型侧补齐（步骤字段、测试用户、概览两张卡）。
- **B15**：三处「留给实现者」定死——`result_mode` 默认分路径冻结（Skill 固定 INLINE）、`skill_artifact` 复核改为**追加 `skill_artifact_validation_event`**（不再 UPDATE）、Agent 授权集合替换语义。

## 三、独立批判新增项

- **Q-02**：租约默认值自洽（TTL 900000 / 心跳 300000）+ 启动自检不满足即**拒绝启动**；失联语义改为可验收三行为（提交边界 fencing 拒绝 / best-effort cancel / `operation_id` 幂等兜底），删除不可实现的"立即中断同步外部调用"。
- **Q-04**：`confirmation_digest` 去掉 `rendered_summary`、改用 `template_hash`（ADR-049）。
- **Q-07**：`reconcile_deadline` 由 ASYNC 提交事务写入（默认 86400），消除"NOT NULL 无写入者"。
- **Q-08**：新增 `CH-LIB-02 enqueue_delivery(tx, …)`（显式接收调用方事务）。
- **Q-10**：提案状态收敛为 `PENDING/CONFIRMED` + `superseded_at`（ADR-049）。
- **Y-01/Y-02/Y-04/Y-07**：元数据重复与"零消费方"问题——`authorization_requirement` 随 D1 删除；RULE-WORK-04 增加**副作用合取条件**（`NONE` + `write/destructive` 禁止自动重试）与 `CREDENTIAL_INVALID` 处置；SYNC 步骤补 `effect:{operation_id}`；`error_semantics` 键空间对齐错误分类基线（7 类）。
- **Y-05**：`ProviderKind` 增加 V1 可注册白名单（`AUTH`/`CAPABILITY`），其余 kind `PROVIDER_KIND_NOT_ENABLED` fail-fast，消除"两套 Secret 解析来源"。
- **Y-08/Y-09/Y-10**：Provider 补 `display_name`；模型列表字段投影矛盾修正；Developer token 补 TTL/kid。
- **Z-01/Z-02/Z-04/Z-06/Z-07/Z-08/Z-09/Z-10/Z-11/Z-12/Z-13/Z-14/Z-15**：前端与交互契约——取代声明扩为**正反两向 16 条**、停用按爆炸半径分级确认、授权差异确认、`StandardListQuery`、审计小节、概览两张卡、动作门控与禁用原因、角色三条守卫（ADR-059）、知识库菜单措辞、trace 搜索、`human_policy` 取代原型「人工介入」。

## 四之二、执行中追加的六处裁决

1. **`invocation_policy` 命名消歧**（与 implementation 的 `execution_policy` 故意不同名）。
2. **上游就地修订**：D1 删除的三字段是总设/Playbook 明文要求，按总设 §6.4 规则修订两份母本，ADR-041 标注为被 ADR-057 取代。
3. **`worker_slot_lease` 作为模块 06「无独立业务表」的显式例外**（协调表 ≠ 业务事实表）。
4. **模型字段可见性统一**：`base_url`/`default_parameters`/`request_timeout_seconds` 对 Builder 详情与表单均可见可写（非凭据；`base_url` 受 SSRF allowlist 约束），仅 `api_key`/`extra_headers` Admin-only；`RISK-07-03` 随之闭合。
5. **能力测试权限以 API 合同为准**：`CAP-API-05` = Builder + Admin（与"模型连通性测试仅 Admin"分开判断）。
6. **恢复用户列表「角色」列与筛选**（冻结交互稿 + `USR-API-01` 都支持，V1.13 误删）。
