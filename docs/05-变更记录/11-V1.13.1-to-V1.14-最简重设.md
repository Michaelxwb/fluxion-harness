# V1.13.1 → V1.14 最简重设说明

设计阶段以最优最简为准，对前期 Review 发现的 5 处次优（N-1~N-5）与 1 处载体残留（C-5）推翻重设。正确性契约不变，只做减法；总纲见 ADR-061。

## 重设清单

| 编号 | 旧方案 | 新方案 | 落点 |
|---|---|---|---|
| N-1 | `worker_slot_lease` 槽位行表（slot_no 分配 + 过期回收 + 抢占重试 + FOR UPDATE 串行化） | 单行计数器 `worker_slot_counter(resource_class PK, used, slot_limit)`：原子 `UPDATE ... used=used+1 WHERE used<slot_limit` 抢占，终态递减释放，崩溃泄漏只少用、由 maintenance 对账修复 | ADR-056 修订、模块 06 §2.5/§3.3/S-WORK-13、`08` 表索引、模块 README |
| N-2 | 维护 GC 由 worker 镜像内独立调度循环承载 | 独立 `maintenance` 运行角色（同镜像不同 entrypoint，副本=1，独立连接池/开关 `MAINTENANCE_ENABLED`）；Worker 只留投递调度 | `01-架构基线` 角色表、`11-数据保留与清理策略` §1 |
| N-3 | 提案签发与执行创建各写一份快照（双份大 JSONB） | 单快照行复用：`service_execution.snapshot_id = proposal.snapshot_id` | `04-数据库设计基线` §10、模块 05 EXE-LIB-01、`08` 快照行注释 |
| N-4 | `CORE-LIB-08` 通用 `claim(table, filter: ClaimFilter)` 大一统 | 通用 claim 删除；领取 SQL 归各域（06 WORK-LIB-01、03 RT-LIB-03），共享只剩 `renew`/`release`/`assert_owner` + epoch 语义 | 模块 01（特性/规则/签名/场景 S-CORE-07）、模块 03/06/11 调用处、`09` 索引 |
| N-5 | `audit_log.details.changed_fields` 全字段存值（含 MB 级 draft/snapshot 原文） | 大小分流：大字段（点名大列或单值 >4KB）只存 `{field, before_hash, after_hash, diff_ref?}` | 模块 15（表结构 + 写入约束）、`90` §15.4、FE-11 §3.4 |
| C-5 | V0.8 HTML 原型与各页设计并列存放，易被误作事实源 | 移入 `docs/03-前端设计/archive/`，11 页引用同步为归档路径 + 冲突口径注释 | `03-前端设计/README` 事实源优先级与取代声明 |

## 迁移说明

- 迁移链压缩为单基线 `0001`（旧 0001~0003 已删除）：`migrations/versions/0001_initial_schema.py` 由模型元数据全量生成（44 表 + 索引 + 计数器种子行），`downgrade base` ↔ `upgrade head` 已在本地库验证往返。
- 新建 `worker_slot_counter` + 预置 3 行（browser 2 / external-scan 2 / large-report 1），旧表下线。本地 `isf` 库已 DROP SCHEMA 重建并 `upgrade head`（44 表 + alembic_version，`alembic_version=0001`）。
- 其余重设均为纯文档结构收敛，无存量数据迁移；`changed_fields` 历史行读取默认 `[]` 不变。
