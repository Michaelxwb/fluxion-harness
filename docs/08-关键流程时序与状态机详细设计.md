# 08 关键流程、时序与状态机详细设计

## 1. `/bind` 首次绑定时序

```mermaid
sequenceDiagram
    participant A as Admin
    participant CP as Console Platform
    participant DB as control DB
    participant U as User
    participant WC as WeCom
    participant IG as IM Gateway

    A->>CP: 生成绑定码
    CP->>DB: insert bind_code(code_hash, ttl)
    CP-->>A: 明文绑定码（仅本次展示）

    U->>WC: /bind ABC123
    WC->>IG: bot message
    IG->>CP: POST /internal/channel/bind
    CP->>DB: SELECT bind_code FOR UPDATE
    CP->>DB: upsert channel_identity
    CP->>DB: bind_code -> USED
    CP-->>IG: platform_user_id
    IG-->>WC: 已完成身份绑定
    WC-->>U: 已完成身份绑定
```

关键规则：

- `/bind` 只建立 ChannelIdentity → PlatformUser；
- 不绑定 Agent；
- 不创建 AgentAccessGrant；
- `bot_id -> logical agent_id` 由 BotAccount 决定；不绑定 Runtime Pod。

## 6. `/stop` 取消时序

```mermaid
sequenceDiagram
    participant U as User
    participant IG as IM Gateway
    participant RP as Receiving Runtime Pod
    participant EP as Executing Runtime Pod
    participant RD as Redis
    participant PG as PostgreSQL

    U->>IG: /stop
    IG->>RP: POST /v1/runs/cancel-active(agent_id, platform_user_id)
    alt no active run
        RP-->>IG: 404 NO_ACTIVE_RUN
        IG-->>U: 当前没有正在执行的任务
    else WAITING_INPUT (无执行者)
        RP->>PG: CAS status=CANCELLED
        RP->>PG: write CANCEL CanonicalEvent
        RP-->>IG: run.completed(status=CANCELLED)
        IG-->>U: 当前任务已停止
    else CREATED / RUNNING
        RP->>PG: cancel_requested=true
        RP->>RD: run:cancel:{run_id}=1
        RP-->>IG: status="CANCELLING"
        IG-->>U: 正在停止当前任务…
        Note over EP: 模型调用前 / 工具调用前 / 心跳处检查 cancel
        EP->>PG: CAS status=CANCELLED
        EP->>PG: write CANCEL CanonicalEvent
        EP-->>IG: run.completed(status=CANCELLED)
        IG-->>U: 当前任务已停止
    end
```

**图说明**：

- Gateway 调用 `POST /v1/runs/cancel-active`（`agent_id + platform_user_id`）；无活跃 Run 返回 `404 NO_ACTIVE_RUN`；
- `WAITING_INPUT` 没有执行者，接收 Pod 直接 CAS 置 `CANCELLED`；
- `CREATED/RUNNING` 接收 Pod 只写 `cancel_requested=true` 与 Redis hint `run:cancel:{run_id}=1`，返回 `status="CANCELLING"`；执行 Pod 协作停止后 CAS 写终态、写 CANCEL CanonicalEvent 并发 `run.completed(status=CANCELLED)`；
- 用户侧为受理语义：“正在停止当前任务…”。

外部系统已经完成的不可逆写操作不自动回滚。

## 7. Skill 按用户范围验证/放开时序

```mermaid
sequenceDiagram
    participant B as Builder
    participant CP as Console Platform
    participant FS as NFS Artifact Store
    participant DB as control DB
    participant U as Selected User
    participant AR as Agent Runtime

    B->>CP: import skill.zip
    CP->>CP: validate + checksum
    CP->>FS: write immutable skill.zip
    FS-->>CP: storage_key
    CP->>DB: insert skill_artifact
    CP->>DB: skill.user_scope=SELECTED
    CP->>DB: insert skill_user_grant(user)

    U->>AR: next run
    AR->>CP: resolve-definition(agent_id, user_id)
    CP->>DB: AgentAccessGrant + AgentSkillBinding + user_scope/grant
    CP-->>AR: includes effective new artifact
    AR->>AR: snapshot pins new checksum

    B->>CP: verification passed, set user_scope=ALL
    CP->>DB: update Skill.user_scope
```

**图说明**：

- `SELECTED` 用于指定测试用户/小范围业务用户，不再使用 PRIVATE 作为产品语义；
- 非指定用户在 `user_scope=SELECTED` 时看不到该 Skill；
- 改为 `ALL` 后，也只有拥有目标 AgentAccessGrant 且该 Agent 已绑定 Skill 的用户可用；
- 当前已开始 Run 不受 user_scope/grant 修改影响；新的 Run/Task 重新解析当前权限。

## 15. 定时任务创建与触发时序

```mermaid
sequenceDiagram
    participant U as User
    participant IG as IM Gateway
    participant AR as Agent Runtime
    participant AW as Agent Worker
    participant CP as Console Platform
    participant DB as Task DB

    U->>IG: 每周一 9 点帮 A 客户做策略检查
    IG->>AR: POST /v1/runs
    AR->>AR: resolve intent policy_check
    AR->>AR: extract schedule Monday 09:00 + timezone(IANA)
    AR->>AW: POST /internal/schedules
    AW->>DB: insert TaskSchedule(timezone IANA)
    AW-->>AR: schedule_id
    AR-->>U: 定时任务已创建

    Note over AW,DB: 到达 next_fire_at
    AW->>DB: claim due schedule
    AW->>CP: resolve-definition(agent,user)
    CP-->>AW: current Agent and Skill definition
    AW->>DB: create TaskExecution plus snapshot
    alt ONCE
        AW->>DB: schedule.status=COMPLETED, completed_at=now()
    else recurring
        AW->>DB: update next_fire_at
    end
    AW->>AW: execute task
```

**图说明**：

- Schedule 保存的是稳定业务意图模板与触发规则，提取与入库必须包含 `timezone`（IANA 名称）；
- `ONCE` 触发创建唯一 TaskExecution 后，Schedule 置 `status=COMPLETED`、`completed_at=now()`，不写 `next_fire_at`；
- 错过触发按 `SKIP` 处理（V1 唯一策略），不补发，记录审计事件并累加 `scheduled_misfire_total`；
- 不永久 pin 旧 Artifact；
- 每次真正触发时重新校验授权，并为该次 Task 生成 Snapshot；
- 定时触发不依赖某个 Agent Runtime Pod 在线。

## 16. 批量并行 Fan-out / Fan-in 时序

```mermaid
sequenceDiagram
    participant AW as Agent Worker
    participant DB as Task DB
    participant W1 as Worker Pod A
    participant W2 as Worker Pod B
    participant W3 as Worker Pod C
    participant IG as IM Gateway

    AW->>DB: create Parent Task customers A B C
    AW->>DB: create Child A (key=parent:{parent_id}:A)
    AW->>DB: create Child B (key=parent:{parent_id}:B)
    AW->>DB: create Child C (key=parent:{parent_id}:C)

    par parallel claims
      W1->>DB: claim Child A
      W2->>DB: claim Child B
      W3->>DB: claim Child C
    end

    W1->>DB: Child A COMPLETED
    W2->>DB: Child B COMPLETED
    W3->>DB: Child C FAILED
    W3->>DB: atomic sibling terminal check + CAS Parent
    AW->>DB: persist aggregated result (aggregate_mode=BEST_EFFORT)
    AW->>IG: final delivery only (delivery_key)
```

**图说明**：

- Child 幂等键为 `parent:{parent_id}:{item_key}`，唯一约束 `(parent_id, item_key)`；Parent reclaim 后已有 Child 则继续等待/聚合，不重复创建；
- Child 进入终态时原子检查兄弟终态计数，满足 `aggregate_mode` 后 CAS 完成/唤醒 Parent，不依赖 Redis wake-up 时序；
- 示例中 Child C FAILED 使用 `aggregate_mode=BEST_EFFORT`：Parent 仍 `COMPLETED`，结果中标注成功/失败数量；若为 `ALL` 则 Parent `FAILED`；
- Parent/Child 全部继承同一个 `intent_key`；
- 并行度由 Worker 配置限制，例如 `max_concurrency=10`；
- 这是一个 Agent 意图的多个执行实例，不是 Multi-Agent；
- 默认只推送 fan-in 后的最终结果，投递使用 `delivery_key=task:{task_id}:final` 去重。

## 17. Worker Lease / Crash Recovery 时序

```mermaid
sequenceDiagram
    participant A as Worker A
    participant DB as Task DB
    participant B as Worker B

    A->>DB: claim task lease_until T1
    A->>DB: heartbeat extend lease
    Note over A: Pod crash
    Note over DB: lease expires
    B->>DB: claim expired task
    B->>DB: read persisted external_task_id and state
    B->>DB: continue or safe retry
```

**图说明**：

- Task 不永久属于 Worker A；
- Reclaim 条件为 `status='RUNNING' AND lease_until < now() AND cancel_requested = false`，命中后置回 `QUEUED` 并保留 `attempts`；
- 对有副作用的外部创建操作必须先持久化 `idempotency_key/external_task_id`；
- Reclaim 后继续查询已有外部任务，不能重复创建；已有 Child 的 Parent 继续等待/聚合，不重复 fan-out；
- 终态投递使用 `delivery_key` 幂等：Gateway Redis `delivery:dedupe:{delivery_key}` SET NX EX 7d 去重，重复请求返回 200。

## 18. Task 状态机

```mermaid
stateDiagram-v2
    [*] --> QUEUED
    QUEUED --> RUNNING: claim
    RUNNING --> WAITING: 外部等待/重试等待，释放 lease
    WAITING --> RUNNING: due claim
    RUNNING --> QUEUED: retry/reclaim
    RUNNING --> COMPLETED
    RUNNING --> FAILED: attempts exhausted
    QUEUED --> FAILED: deadline
    WAITING --> FAILED: deadline
    RUNNING --> FAILED: deadline
    QUEUED --> CANCELLED: CAS
    WAITING --> CANCELLED: CAS
    RUNNING --> CANCELLED: 协作停止
    COMPLETED --> [*]
    FAILED --> [*]
    CANCELLED --> [*]
```

**说明**：

- 终态为 `COMPLETED / FAILED / CANCELLED`；
- `deadline` 由 Scheduler 每 30s CAS 将过期非终态 Task 置为 `FAILED(TASK_DEADLINE_EXCEEDED)`；
- 进入 `WAITING` 时释放 lease；claim/reclaim 始终排除 `cancel_requested=true`。

## 20. ProjectPlatform / PlatformAdapter 调用时序

```mermaid
sequenceDiagram
    participant SK as Skill
    participant PC as PlatformClient
    participant EB as Egress Boundary
    participant PP as ProjectPlatform Resolver
    participant REG as PlatformAdapterRegistry
    participant CR as CredentialResolver
    participant SP as PostgreSQL(密钥列)
    participant SM as PlatformSessionManager
    participant RD as Redis
    participant AD as PlatformAdapter
    participant BP as Business Platform

    SK->>PC: ctx.platform.call(platform_key, request)
    PC->>EB: PlatformRequest
    EB->>PP: resolve platform_key
    PP-->>EB: adapter_key + adapter_config + credential_mode
    EB->>REG: get(adapter_key)
    REG-->>EB: Adapter
    EB->>CR: resolve actor credential
    CR->>SP: get Secret by SecretRef
    SP-->>CR: SecretValue + credential_version
    CR-->>EB: credential_ref + SecretValue + credential_version
    EB->>SM: acquire session(platform, actor, credential_ref, credential_version)
    SM->>RD: get session cache
    alt cache miss or invalid
        SM->>AD: authenticate(platform, credential_ref, SecretValue, credential_version)
        AD->>BP: platform-specific login/sign
        BP-->>AD: session/token/cookie
        AD-->>SM: PlatformSession
        SM->>RD: set session TTL
    end
    SM-->>EB: PlatformSession
    EB->>AD: prepare_request(request, session, credential_ref, SecretValue, credential_version)
    AD-->>EB: PreparedRequest
    EB->>BP: execute
    BP-->>EB: response
    EB-->>SK: normalized result
```

**图说明**：

- Skill 不感知 AK/SK、Cookie、Session、签名规则；
- ProjectPlatform 只选择 Adapter 并提供非敏感配置；
- `PlatformSessionManager.authenticate` 与 `Adapter.prepare_request` 使用同一份 `credential_ref + SecretValue + credential_version`（见 12 §8）；
- Session 缓存在 Redis，可丢失重建；
- Runtime/Worker 任意 Pod 都能复用同一外置 Session；
- 新平台若复用已有 Adapter，只新增 ProjectPlatform 配置，不增加认证代码。

## 21. Agent 多 IM 通道路由

```mermaid
flowchart LR
    B1[WeCom bot_id A] --> A[AgentDefinition]
    B2[WeCom bot_id B] --> A
    B3[Future Channel Account] --> A
    A --> RS[agent-runtime Service]
    RS --> P1[Runtime Pod A]
    RS --> P2[Runtime Pod B]
    RS --> PN[Runtime Pod N]
```

**图说明**：

- 一个 Agent 可以配置多条通道账号；
- 每个 bot_id 只能解析到一个 Agent；
- 通道账号与 Runtime Pod 无固定绑定；
- 同一个 Agent 不同通道来的请求也可以落到不同 Runtime Pod。
