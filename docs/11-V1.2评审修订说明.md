# 11 V1.2 评审修订说明

## 1. 本轮新增需求

本轮确认了此前被推迟但现在已经有明确用户场景的能力：

1. 用户通过 Agent 创建长任务；
2. 用户可离开，后台继续执行；
3. 用户通过 Agent 创建定时任务；
4. 一个业务意图可以对多个目标并行执行；
5. 后台默认只投递最终结果；
6. Agent 必须知道何时同步、何时异步，但不能让 LLM 自由猜测。

因此 V1.1 的“三 Image + Worker 后置”决策正式调整为 V1.2 的“四 Image + Worker 当前纳入”。

## 2. 核心决策

| 决策 | V1.2 结论 |
|---|---|
| 用户任务是否有多个意图 | 否。一个 Prompt 先解析成一个 Business Intent |
| 同步/异步是谁决定 | ExecutionRouter 根据 Skill Runtime Profile / Trigger / 确定性 Planner |
| 是否允许 LLM 输出 use_async 直接驱动 | 禁止 |
| 异步标记放哪里 | `SKILL.md` 可选 `execution`，导入后固化到 `skill_artifact.execution_mode` |
| 是否恢复复杂 skill.yaml | 否 |
| 定时任务是什么 | Trigger Policy，不是第二个业务 Intent |
| Scheduled Skill 是否都进 Worker | 是 |
| 并行多个客户是否 Multi-Agent | 否，Parent/Child Task fan-out/fan-in |
| Worker 是否绑定 Agent/用户 | 否，通用无状态 Worker Pool |
| Background/Cron 是否采纳 learn-agent | 是 |
| Multi-Agent/Worktree 是否采纳 | 否 |
| 默认后台消息策略 | FINAL_ONLY |
| Task 权威队列 | PostgreSQL |
| Redis 角色 | wake-up/cancel/cache hint，非权威 |
| Worker Crash 恢复 | lease/heartbeat/reclaim |
| 定时版本策略 | Schedule 不 pin；每次 fire 创建 Task Snapshot |

## 3. 文档变化

- `00`：更新 learn-agent 采纳矩阵、四 Image、意图/执行/触发模型；
- `01`：加入 Async Execution Plane 与 Worker 部署；
- `02`：增加 `task` schema、Schedule/Task/Event/DeliveryRoute 表和 ER 关系；
- `03`：增加后台任务/定时任务 Console 页面；
- `04`：增加 ExecutionRouter、BackgroundTaskClient、任务 Tool；
- `05`：增加 Worker -> IM Gateway Final Delivery；
- `06`：SKILL.md 新增最小 `execution` 元数据、TaskContext；
- `07`：增加 Task/Schedule/Delivery Internal API；
- `08`：增加即时异步、Cron、Fan-out/Fan-in、Lease Recovery 时序；
- `09`：增加 Worker/Scheduler 可靠性、DFX 与专项验收；
- `10`：新增 Agent Worker 专项详细设计。

## 4. 与 V1.1 保持不变的关键结论

```text
bot_id -> logical AgentDefinition
bot_id != Runtime Pod
Agent Runtime is stateless
Worker is also generic/stateless
Skill = SKILL.md + scripts/resources
No complex skill.yaml
MCP -> ToolRegistry
Canonical History != LLM Request Context
Egress Boundary remains logical, not a separate Image
Only IM is exposed to normal users
```
