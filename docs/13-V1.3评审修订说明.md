# 13 V1.3 评审修订说明

## 1. 本轮问题

本轮确认：

1. 真实项目平台认证并不统一，旧项目已经存在按平台实现 Session Adapter 的实践；
2. 用固定 `Bearer / OAuth2 / API Key` 枚举抽象会丢失平台特有登录、签名、Cookie、CSRF、Session 生命周期；
3. 一个 Agent 需要支持多个 IM 通道；
4. Console 不需要承担中间件/Pod 健康状态监控；
5. 交互稿字段需全中文并保持列表/详情一致；
6. 列表顶部不再展示重复 Tab 文案/描述。

## 2. V1.3 决策

| 主题 | V1.3 |
|---|---|
| 项目平台认证 | `ProjectPlatform + PlatformAdapter + CredentialRef + PlatformSession` |
| Adapter 代码 | 共享 Python package，受控注册 |
| Console 是否上传 Adapter 代码 | 否 |
| 新增平台是否必写代码 | 否；能复用 Adapter 就只配置 |
| 什么时候写新代码 | 出现新的登录/签名/Session 协议 |
| 平台配置表单 | Adapter `platform_config_schema` 动态生成 |
| 凭据表单 | Adapter `credential_schema` 动态生成 |
| Session 存储 | Redis 可重建缓存 |
| Session 是否业务权威 | 否 |
| Secret 存储 | Secret Provider |
| Agent -> IM | 1:N |
| bot_id -> Agent | N:1 中每条 bot_id 唯一归属一个 Agent |
| bot_id -> Pod | 禁止 |
| 系统设置菜单 | 删除 |
| 中间件/Pod 监控 | 外部运维体系 |
| 列表顶部说明 | 删除 |
| 字段语言 | 中文，保留 Agent/Skill/MCP/bot_id 等领域名词 |

## 5. 用户范围与能力授权模型补充修订

V1.3 后续评审确认，原 `PUBLIC/PRIVATE + 灰度用户` 容易误解为 Console 可见性或“全平台公开”，因此统一修正为：

```text
user_scope = ALL | SELECTED
```

关系固定为：

```text
User -> Agent         AgentAccessGrant
Agent -> Skill        AgentSkillBinding
Agent -> MCP          AgentMcpBinding
User -> Skill         SkillUserGrant（SELECTED）
User -> MCP           McpUserGrant（SELECTED）
```

运行时使用交集，不建设三元授权。完整判定（含 Agent.enabled、Skill/MCP.enabled、is_deleted=false）见 00 §0.9 / 02 §5.10。

产品文案同步调整：

```text
可见范围 -> 用户范围
公开       -> 全部授权用户
私有       -> 指定用户
灰度用户   -> 指定用户
```

“灰度”仍可作为 SELECTED 的使用场景描述，但不再作为核心领域字段或 Tab 名称。

Runtime 必须在 Skill Catalog/MCP ToolRegistry 构建前完成用户范围过滤，未授权能力不得进入 LLM 上下文。

## 7. Console 字段统一与歧义修复

本轮对交互稿与详细设计做全字段复核，固定以下口径：

- Agent：`instructions` 统一显示为“系统 Prompt”；新增/编辑都真实保存模型、启用状态、系统 Prompt；
- 所有关联数量从真实 Binding/Grant/Credential 关系聚合，不在多个对象上重复维护手工 count；
- Skill：统一“当前版本 / 使用 Agent 数 / 指定用户数 / 启用状态”；
- MCP：拆分“启用状态 / 连接状态”，`last_discovered_at` 显示为“最近工具发现时间”，Tool 使用“操作类型”；
- Model：拆分平台“标识”和 OpenAI “模型 ID”，URL 统一为“Base URL”，当前仅 OPENAI 协议；
- User：列表数量字段统一为 Agent 授权数、已配置用户凭据数、IM 身份数、用户记忆数；`external_user_id` 统一“外部用户 ID”；
- ProjectPlatform：接入寻址用 `resolver_type + resolver_config_json`；Adapter 选择与配置用 `adapter_key + adapter_config_json`（Console 按 `platform_config_schema` 动态生成表单）；
- Task/Schedule：使用“任务状态 / 调度状态 / 投递状态”，开始时间和完成时间分列；
- Schedule 历史按 `task_execution.schedule_id` 真实关联；
- Audit：字段统一为“审计类型 / 操作目标 / 动作 / 执行结果 / Trace ID”。


## 8. 数据库/API/Artifact 存储复审修订

- Model 不增加 `is_default`；
- Artifact Store V1 = NFS-backed RWX PVC；
- DB/API 统一保存 `storage_key`；
- Runtime/Worker = NFS + local emptyDir SkillArtifactCache；
- MCP Tool Catalog 最近成功快照持久化到 PostgreSQL；
- ChannelIdentity 增加 `last_active_at`；
- Shared Credential 收敛为每平台 0..1；
- Run/Task Snapshot 增加 schema version；
- Schedule/Task 使用稳定 `skill_id`；
- Schedule 删除只用 `is_deleted`，ONCE 完成使用 `COMPLETED`；
- TaskType V1 仅 SKILL/BATCH；
- Agent relation API 使用单关系 POST/DELETE；
- 增加 MCP tools/discover-tools、Skill 新版本 Artifact、Shared Credential、Audit、Memory 清空全部 API；
- Egress 使用 `execution_ref=RUN|TASK`；
- ProjectPlatform 修改 Adapter 时使旧 CredentialRef/Session 失效。
