# 17 V1.4 评审修订说明

本文档记录 V1.4 全量设计评审发现的问题、决策与修复结论。V1.3 及更早的决策记录见 11/13，本文只覆盖本轮变更。

## 1. 评审范围

- 全量通读 `00` ~ `16` 与两份上游基线（V2.0 总体设计说明书、V7 用户场景与 Playbook 旅程设计）；
- 交叉核验字段词典（15）、授权模型（14）、跨模块接口（07）、数据库设计（02）、Worker（10）、Gateway（05）、Runtime（04）、Console（03）、Adapter/Session（12）；
- 与仓库实现抽查对照（`migrations/`、`config/api-messages.yaml`、`packages/`、`apps/`）。

## 2. 决策记录（D1–D8）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 会话并发 | 同一 conversation 同时最多一个非终态 Run；RUNNING 期间新消息返回 `RUN_BUSY`；WAITING_INPUT 期间新消息自动 resume；`run_record` 增加 `lease_owner/lease_until/heartbeat_at`，终态写入 CAS，Reaper 回收 `RUN_ABANDONED` |
| D2 | resume 归属 | Runtime 在 `POST /v1/runs` 内判定并自动 resume；Gateway 无状态，不查询/缓存 active run |
| D3 | `/stop` 语义 | 受理语义：`POST /v1/runs/cancel-active`；WAITING_INPUT 直接 CAS 置 CANCELLED；CREATED/RUNNING 写 `cancel_requested` + Redis hint，由执行 Pod 协作终止 |
| D4 | Task deadline | `deadline_at` NOT NULL（默认创建时间 + 24h）；过期由 Scheduler sweep 置 `FAILED(TASK_DEADLINE_EXCEEDED)`；终态仍按 `delivery_mode` 投递 |
| D5 | Final Delivery | at-least-once + 幂等去重：`delivery_key = task:{id}:final`，Gateway Redis 去重，Worker 指数退避最多 5 次 |
| D6 | `ctx.http` | 保留 `ctx.http.get/post/request`，与平台调用共用 Egress Boundary（allowlist、审计、5 MiB 上限、禁止未授权跳转） |
| D7 | 授权模型收敛 | 绑定无 `enabled` 开关；grant 无到期时间（撤销 = 软删除）；公式统一补 `is_deleted=false` 与资源/Agent `enabled` |
| D8 | V1 范围收敛 | 无用户侧 Artifact 下载；Schedule 仅 SKIP（无 FIRE_ONCE）；Prompt 模板代码内置（Snapshot 记录 `prompt_template_version`） |

## 3. 主要修复

### 3.1 授权判定

- 公式在 `00`、`02 §5.10`、`03`、`07`、`13`、`14` 统一为同一版本；
- 删除 `agent_skill_binding.enabled` / `agent_mcp_binding.enabled` 死列；
- 删除 `skill_user_grant.expires_at` / `mcp_user_grant.expires_at`；
- 明确撤销语义为软删除，判定必须带 `is_deleted = false`。

### 3.2 Run 与取消

- `run_record` 增加执行租约字段与并发 partial unique 约束；
- 所有终态写入改为 CAS，禁止 lease 失效的执行者覆盖终态；
- `/stop` 全链路（05/07/08/02）改为 cancel-active + 协作取消；
- Gateway SSE 流未收到终态而断开时提示重发，Run 由 Reaper 回收。

### 3.3 Task 与 Worker

- claim/reclaim 条件补 `not_before`、`cancel_requested`；WAITING 释放 lease；
- QUEUED/WAITING 取消走 CAS 直接终态；
- deadline sweep、misfire SKIP、fan-out 幂等键 `parent:{parent_id}:{item_key}`、fan-in 原子 CAS；
- Final Delivery 增加 `delivery_key/delivery_status/delivery_attempts/delivered_at` 与去重协议；
- 移除 `AgentStepExecutor`/AGENT_STEP 命名，`task_type` 仅 `SKILL/BATCH`。

### 3.4 契约与命名

- Gateway resolve 响应补 `bound`，删除 `conversation_hint`；`external_conversation_id` 统一；
- 新增 `POST /v1/runs/cancel-active`、`GET /v1/runs/{run_id}`；
- PlatformAdapter SPI 以 `12 §3.1` 为唯一版本（`name/session_mode`，无独立 `refresh`）；
- `resolver_config_json/adapter_config_json` 为 DB 列名，`resolver_config/adapter_config` 为 API/UI 名（规则写入 15）；
- egress `target_type` 统一 `PLATFORM_SERVICE/HTTP/MCP`；
- Session 失效改为 Redis Set 索引按成员删除，禁止 SCAN/通配符删除。

### 3.5 范围与文档

- 清理全部 "V1.2 当前状态" 版本残留、"灰度"、`ObjectStore`、重复标题编号；
- 两份基线刷新：四核心 Image、Worker 交付、Skill 包格式、user_scope、Console 菜单、Artifact Store、Internal API 指向 doc 07；
- 错误码 `RUN_BUSY`、`NO_ACTIVE_RUN` 收敛到 `config/api-messages.yaml`。

## 4. 交互稿对齐

`MSS智能服务交付平台-V1.4-交互稿.html` 已按本轮口径更新：版本标识 V1.4；MCP 工具明细不再提供单 Tool 启停与启用状态列（工具数按发现总数）；Task 快照改为 execution snapshot 并展示 `mcp_catalog_revision/hash`、`prompt_template_version`；Artifact 措辞改为 Artifact Store；后台任务列表与详情新增任务截止时间、失败原因；定时任务筛选补「已完成」；用户页凭据计数统一为「已配置用户凭据数」；平台编辑在更换 `adapter_key` 时提示凭据失效与 Session 清理。运行审计「执行结果」列对应的 `result_status` 已写入 07 §10.11 与 15。
