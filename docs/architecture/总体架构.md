# Fluxion 总体架构

## 1. 逻辑分层

```text
┌──────────────────────── Control Plane ────────────────────────┐
│ Console Web / Console API                                     │
│ Agent Studio / Resource / User / Policy / Publish / Audit     │
└───────────────────────────┬───────────────────────────────────┘
                            │
                            v
┌──────────────────── Shared State / Registry ──────────────────┐
│ PostgreSQL(prod) / SQLite(dev)                                │
│ Resource / Binding / User / Session / Approval / Audit        │
│ SecretProvider / SemanticStore / OTel backend                 │
└───────────────────────────┬───────────────────────────────────┘
                            │ resolve
              ┌─────────────┼─────────────┐
              v             v             v
        Runtime A       Runtime B      Runtime N
              └──────── Shared RuntimePool ────────┘
                            │
                      ExecutionSnapshot
                            │
                         AgentLoop
       ┌──────────┬─────────┼─────────┬──────────┐
       v          v         v         v          v
     Model       Tool      MCP      Skill    Workflow Adapter
                                              │
                                              v
                                      Durable Workflow Engine
                                      （当前业务实现 DBOS）
```

## 2. 核心实体

### AgentDefinition

产品逻辑 Agent。当前代码已经存在该 typed model，应保留；但 `capabilities: CapabilityBinding[]` 应收敛为 `capability_allowlist/references` 语义。

### RuntimeProfile

纯运行机制配置。不得重新承担 persona、用户能力 ownership 或 Pod identity。

### RuntimeInstance / RuntimePool

实际计算节点与共享计算池。RuntimeInstance 允许持有 connection pool、MCP HTTP pool、bounded cache 等性能状态，但这些都不能成为事实源。

### ExecutionSnapshot

每次执行的版本化投影。建议最终包含/可追溯：

- AgentDefinition exact version；
- RuntimeProfile exact version；
- Model resolution；
- Skill/MCP/Plugin exact versions；
- Policy exact versions；
- User Binding/Grant version set；
- EffectiveCapability digest/refs；
- trace_id/execution_id。

### PlatformUser

统一身份主体。ChannelIdentity 只负责映射。

## 3. 执行链

`Channel/API → Identity → AgentDefinition → Context/Capability Resolve → Snapshot → AgentLoop → Model/Tool/MCP/Workflow → Shared Stores/Trace`

一次 Execution 中所有影响行为的版本必须固定。Credential 明文不进入 Snapshot；Snapshot 只保存 CredentialRef/版本或可审计元数据。

## 4. 开源边界

开源仓库包含 Runtime Kernel、Console、Registry、Skill/MCP/Plugin Runtime、基础 Tool/Sandbox、CLI/SDK、Web Chat、Channel Adapter Contract、Workflow Adapter、共享 Contract。

企业业务 SOP、HR/CRM/ERP 业务逻辑、业务 Policy、企业 Connector 不进入 Kernel。

WorkflowEngine Contract 属于开源层；当前 DBOS production adapter 可作为可选 integration，但 DBOS 不应成为 Kernel 领域模型。

## 5. 当前代码与目标的关系

当前代码的 Snapshot/Registry/SQL Memory/MCP Binding/Workflow Adapter 等可继续演进，不需要重写 Runtime Core。当前首要整改是 Capability 用户维度、durable scheduler/operational state 和真实 multi-pod Gate。
