# 08 用户旅程与体验设计

> **定位**：用户旅程是功能正当性的来源与验收视角。每个功能必须能回答"它服务哪条旅程的哪一步"（UJ-\*）；REQ-\* 由旅程推导，Journey E2E 是旅程的自动化验收。新增功能立项时，Task 的 Source 必须引用其服务的旅程步骤；不服务任何旅程且非支撑能力的功能不予立项。

## 1. 体验原则（易懂易用铁律）

1. **对话优先**：普通用户的核心界面是**对话**（IM 通道 / Web Chat），不是网页表单。用户能力优先以 **tool** 形式供给 Agent，让用户用自然语言完成任务；Web 页面是辅助视图与合规兜底，不是旅程依赖。
2. **术语隐藏**：普通用户面 denylist（`RuntimeProfile`/`Registry`/`Resource`/`Binding`/`Plugin`/`Workflow` 底层态）出现次数 = 0；用户只面向 Agent 与能力。Builder/Admin 可见底层术语（denylist 不覆盖其视图）；**普通用户不接触 Console 控制台**。
3. **路径要短**：高频操作一句话或 ≤3 步完成；常用页面 ≤2 次点击可达；支持深链（`/agents/:id`、`/tasks/:id`）与浏览器前进/后退。
4. **四态完备**：loading / empty / error / success 缺一不可；错误必须可重试、不丢失已收内容（流式中断保留已收帧）。
5. **高风险有确认**：发布、回滚、删除 Memory、审批等操作须明确确认与影响说明。
6. **审批不疲劳**：审批按风险分级触发（P15）；低风险自动放行，不为安全而堆人工确认。
7. **无障碍**：全部可交互元素键盘可达，焦点可见、弹层焦点管理（NFR-A11Y-01）。
8. **产品语言**：绑定后一切以产品信息呈现（displayName/icon/description），不暴露 raw `agent_id`；未绑定用户仅可见绑定流程。
9. **中文优先**：用户可见文案中文优先，代码标识符保留英文（仓库语言约定）。

## 2. Persona

| Persona | 是谁 | 目标 | 入口 | 对应 Journey 套件 |
|---------|------|------|------|-------------------|
| 普通用户 | PlatformUser（渠道绑定后） | 用 Agent 把事办成，管好自己的数据与隐私 | **IM 通道（WeCom/Mattermost/飞书…）与 Web Chat**；不接触 Console | Workspace task journey |
| Builder | 业务构建者 | 构建、测试、发布 Agent 与流程 | Console Build（Agents/Studio/Capabilities/Workflows/Eval） | Build journey |
| Admin | 平台管理员 | 授权、治理、运营、平台配置 | Console Admin（Users/Governance/Operations/Platform） | Admin journey |

> **治理视角**：普通用户的对话内容、任务、Memory 等信息由 Admin 经 User 360 / Governance / Operations 按租户权限查看（审计与合规），对用户旅程无侵入。

## 3. 主旅程

### 3.1 普通用户（UJ-U）

> **核心模型**：一次绑定 → 多个机器人（每个 Agent = 独立人设 + 专业技能）→ 对话中完成一切。
> - **绑定是身份层的，一次即可**（每渠道一次：Web Chat `/bind` 输码；IM 通道首次交互引导）；绑定后即成 PlatformUser，跨 Agent 复用同一身份；
> - **换 Agent 对话不需要再绑定**：用户与 Agent 是 **M:N 授权关系**（Chat Access 按 user+agent 签发），新 Agent 可用时只是出现在目录/IM bot 列表中，签发是 Admin/租户策略侧动作，对用户零操作；
> - 用户级差异（版本/参数/enable/CredentialRef）在 Binding/Grant 层（REQ-CAP-004）；底层共享同一 RuntimePool。

| 步骤 | 用户动作 | 系统行为 | 功能/页面 | 体验要求 | 验收锚点 |
|------|---------|---------|----------|---------|---------|
| UJ-U-01 | 绑定：Web Chat `/bind` 输码，或 IM 通道首次对话引导绑定 | ChannelIdentity → PlatformUser 映射，签发访问 | bind 流程 / IM 首次交互 | 未绑定仅绑定流程可见，其余能力不开放 | phase4 B-01；closure TASK-005 |
| UJ-U-02 | 选择机器人（Agent） | Web 目录页浏览，或 IM 中切换/被指派机器人；每个 Agent = 独立人设 + 专业技能（capability allowlist） | X402 Home、X403 Agents 或 IM bot 列表 | 产品模型展示（无底层术语）；同一身份跨机器人连续 | phase4 S-02/S-03 |
| UJ-U-03 | 对话（核心动作） | 自然语言对话/发起任务；ContextResolver/Snapshot 固定版本 → 流式回复 | Chat / IM 通道 | 流式渲染；中断可重试、已收内容保留 | phase4 S-08/E-04；closure S-10 |

## 4. 功能 ↔ 旅程追溯矩阵

> 「直答」= 功能本身就是某步骤的用户可见能力；「支撑」= 不直接面对用户，但为旅程提供正确性/可靠性底座。支撑能力同样必须挂靠步骤（说明它守护哪一步的体验）。

| 功能/模块 | 服务的步骤 | 类型 |
|-----------|-----------|------|
| `/bind` 流程 + ChannelAuthenticator | UJ-U-01 | 直答 + 支撑（身份可信） |
| Channel Adapter（IM 通道接入，每通道一个 bot 形态） | UJ-U-01/UJ-U-02/UJ-U-03 | 直答 + 支撑 |
| Agent 目录/产品 API（`GET /api/v1/agents/{id}`） | UJ-U-02/UJ-U-03 | 直答 |
| Chat 流式对话 | UJ-U-03 | 直答 |
| ContextResolver + Snapshot V2（digest/manifest） | UJ-U-03/UJ-U-04 | 支撑（一致性底座） |
| **用户自助 builtin tools（profile/memory/preference 读写）** | UJ-U-04/UJ-U-06 | 直答（对话即界面） |
| 任务列表/workflow_run 投影 + History | UJ-U-04（tool）/UJ-U-05（页面） | 直答 |
| HumanTask/审批 signal + Approvals 页/IM 卡片 | UJ-U-04（对话）/UJ-U-05（页面） | 直答 |
| Personal Memory pipeline + learning control | UJ-U-06 | 直答 |
| UserPreference/Settings | UJ-U-04（tool）/UJ-U-05（页面） | 直答 |
| Typed CapabilityPicker + Studio round-trip | UJ-B-02 | 直答 |
| EvalSet/EvalExecutor/ReleaseGateService | UJ-B-05/UJ-B-06 | 直答 |
| Workflow Studio V2 + durable 引擎（DBOS） | UJ-B-08 → UJ-U-04 | 直答 + 支撑 |
| Chat Access 签发（agent 制） | UJ-A-02 | 直答 |
| User 360 | UJ-A-06 | 直答 |
| ArtifactStore/SecretProvider/OTel/durable_task/A2A | 支撑全域 | 支撑 |

## 5. 旅程验收

- **Journey E2E**：三组套件（Workspace task / Build / Admin）成功率 ≥95%，失败项可定位（phase4 TASK-016 / B-03）。
- **术语门禁**：普通用户核心页 denylist 术语 = 0（B-02）。
- **反模式清单**（评审否决项）：让普通用户接触底层资源术语；把三维权限压成一个 checkbox；审批不分级造成疲劳；页面缺四态；错误不可重试；操作无确认即生效。

## 6. 旅程演进规则

- 新增/变更旅程步骤走 code-flow 对齐（步骤变更 → 受影响功能与 Task 重新对齐 Source 引用）。
- 删除步骤前必须核对追溯矩阵：无直答功能悬挂、无 E2E 断言失效。
- Journey 套件是活文档：步骤表与 E2E 用例一一对应，改步骤必改用例。
