# 03 架构原则

1. **ARCH-01 无状态计算**：RuntimeInstance 不拥有 durable business truth。
2. **ARCH-02 逻辑与物理解耦**：AgentDefinition ≠ RuntimeInstance。
3. **ARCH-03 状态外置**：Session/Memory/Credential/Binding/Profile/Approval/Schedule/Workflow/Published Config 外置。
4. **ARCH-04 Definition/Binding 分离**：共享定义不承载用户私有差异。
5. **ARCH-05 Agent 非用户资源 Owner**：AgentDefinition 只表达 Allowlist/Reference/Baseline。
6. **ARCH-06 Tool/MCP 三重交集**：`UserGrant ∩ AgentAllowlist ∩ TenantPolicy`，禁止 `user_tools = agent_tools` 作为最终语义。
7. **ARCH-07 Execution 不可变**：一次执行中的资源、能力和策略版本不漂移。
8. **ARCH-08 Cache 非事实源**：本地 Cache 可直接清空并从共享 Store 重建。
9. **ARCH-09 Typed Spec SoT**：Runtime 禁止绕过 typed model 散乱读取 raw spec。
10. **ARCH-10 Durable Workflow 外置**：AgentLoop 不实现 workflow durability。
11. **ARCH-11 安全默认拒绝**：scope/grant/policy/credential 缺失或解析失败时 fail-closed。
12. **ARCH-12 Core Contract 扩展**：Model/Tool/MCP/Skill/Workflow/Channel/Store/Sandbox 等通过稳定 Contract。
13. **ARCH-13 信任边界显式化**：trusted in-process 与 untrusted isolated extension 分开。
14. **ARCH-14 Console/Runtime 分离**：Console 是控制面，不是 Runtime 已发布配置的在线依赖。
15. **ARCH-15 用户事实统一**：渠道身份最终落到 PlatformUser。
16. **ARCH-16 可追溯执行**：关键路径可关联 exact snapshot/version。
17. **ARCH-17 架构必须被 Gate 证明**：单元测试不能替代 multi-pod、tenant isolation、credential isolation 等真实边界测试。
