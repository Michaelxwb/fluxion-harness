## 2. P0 架构整改

### P0-1 Tool UserGrant ✅ 已收口

当前执行侧 `user_tools = agent_tools` 已移除；`_effective_tool_policy`（`services/runtime_tool_ops.py`）恢复真实 User Tool Grant（`capability_grants` kind=tool ∪ 用户 MCP binding 派生工具 id），与 agent allowlist / tenant policy 取交集。

### P0-2 Agent Capability 命名/职责 ✅ 已收口

`AgentDefinition.capabilities` 已改用 `AgentCapabilityReference`（Allowlist/Reference 语义）。

### P0-3 Multi-Pod Gate

现有 snapshot digest/双实例测试升级为真实部署 Gate。Phase 6 已落地 `backend/tests/integration/test_k8s_gate.py`（门控 `FLUXION_K8S_TEST=1`），待真实集群跑通验证。

### P0-4 Scheduler

RuntimeScheduler 本地 `_tasks` 限定 test/dev；生产任务事实外置。

### P0-5 Operational durable stores

Production profile 禁止 InMemory Trace/Approval/Eval 作为唯一实现；启动时 fail-fast 或显式 production adapter。

## 3. P1 收口

- Snapshot pin User Binding/Grant/Policy exact version；
- 授权解析收敛为单一 EffectiveCapability Resolver（当前三条路径分裂：`EffectiveCapabilityResolver` / `_effective_skill_selectors` / `ContextResolver._resolve_capability_versions`，违反 REQ-CAP-006）；
- Skill 扩展补 Tenant Policy 闸门（REQ-CAP-005「受 Tenant Policy 约束」缺 Gate/Task 落点）；

- Personal Memory retrieval/learning 接入 AgentLoop；
- Tool 与 Plugin 概念拆分；
- Model policy/resource ownership 收口；
- Semantic Validation/Risk/Approval 形成统一 pipeline。
