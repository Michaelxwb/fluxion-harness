# 当前代码偏差与迁移

## 1. 不重写的正确基础

保留并演进：

- AgentDefinition typed model；
- RuntimeProfile 收缩为 mechanics；
- ResourceResolver / ExecutionSnapshot；
- SQLSessionMemoryStore；
- PersonalMemory taxonomy/gate shape；
- PlatformUser/Profile/Preference/User360；
- RegistryMCPRuntime 的 user binding + CredentialResolver；
- WorkflowEngine Protocol / Adapter；
- Plugin Contracts / typed hooks；
- A2A minimal contract；
- typed Spec SoT；
- SQLite/PostgreSQL Store abstraction。

## 2. P0 架构整改

### P0-1 Tool UserGrant

当前执行侧 `user_tools = agent_tools`，用户 Tool 维度消失。恢复 User Tool Binding/Grant，并由统一 EffectiveCapabilityResolver 计算。

### P0-2 Agent Capability 命名/职责

`AgentDefinition.capabilities: CapabilityBinding[]` 改为 Allowlist/Reference 语义。迁移期不保留双模型；开发阶段直接更新 fixture/API/UI。

### P0-3 Multi-Pod Gate

现有 snapshot digest/双实例测试升级为真实部署 Gate。

### P0-4 Scheduler

RuntimeScheduler 本地 `_tasks` 限定 test/dev；生产任务事实外置。

### P0-5 Operational durable stores

Production profile 禁止 InMemory Trace/Approval/Eval 作为唯一实现；启动时 fail-fast 或显式 production adapter。

## 3. P1 收口

- Snapshot pin User Binding/Grant/Policy exact version；
- Personal Memory retrieval/learning 接入 AgentLoop；
- Tool 与 Plugin 概念拆分；
- Model policy/resource ownership 收口；
- Semantic Validation/Risk/Approval 形成统一 pipeline。

## 4. 后续功能

只有 P0 Architecture Gate 全绿后，再继续扩大 Workflow DSL、完整 Memory、企业 Channel、Eval UI、更多 Plugin 等功能范围。
