# 配置平台出站请求限制

在 Console「系统设置 → 出站请求管控」启用管控并新增规则：选择已配置的平台，选择请求方法，填写接口相对路径，再填写每分钟次数或并发上限。两项均留空时该规则不产生限制。初始状态关闭、没有规则，没有预置业务限额。

例如平台 Base URL 为 `https://assets.example/gateway/v1`，路径填写 `/assets/{id}`，会匹配 `https://assets.example/gateway/v1/assets/123`。完整地址是只读预览。管理员不填写域名或内部接口标识；接口身份由平台、请求方法和相对路径生成。修改平台 Base URL 后，后续受控执行自动使用新地址，接口计数身份保持不变。

平台必须存在于当前租户、已启用且配置有效 HTTP Base URL。没有已解析 Base URL 的服务发现平台暂不支持该规则，不能通过手填地址绕过。相互重叠、无法唯一识别的平台路径会被拒绝。

启用选择在新 Run/Task 创建时冻结，重试和恢复保留该选择以及执行累计预算。受控执行启动从 Console 读取当前公共规则投影并发布到共享 Redis；每次实际发送使用已发布的当前规则，路由和准入绑定同一版本。保存设置不等于同步发布 Redis，也不终止已经发出的请求。首次新增或扩大连续滑动窗口时，为避免历史未完整导致超放，会等待一个完整窗口；窗口及并发超限拒绝当前调用，不自动睡眠重跑。

Runtime/Worker 镜像和 `scripts/dev.sh` 默认使用 `config/egress-runtime.json`。这个文件只提供宿主生命周期和保护域参数，默认接口列表为空、公共规则关闭；业务规则来自 Console。已有显式 `EGRESS_CONTROL_FILE` 配置仍由部署方负责。没有规则且没有执行累计预算时，不构造计量 Redis 连接。

共享保护域按租户隔离。首次使用时以 PostgreSQL 的租户执行历史证明未初始化后创建 Redis guard。有历史执行但 guard 丢失、Redis 故障或计数状态不确定时阻止受控请求，不自动重建或清空历史。Redis 切换和数据丢失不是无损恢复承诺，需要按既有故障恢复流程处理。旧的非租户保护域执行不自动迁移。

本次本地证据：253 项相关定向测试通过；设置页 6 项真实构建产物组件测试通过（业务 API 使用 mock）；新增宿主测试使用真实 Run claim、PG、Redis、HTTP，Console 入口使用 typed fixture。Console API/PG投影另有真实 ASGI/PG 集成测试；这些证据不冒充整条真实浏览器到 Worker 的端到端验收。项目级 Linux 恢复/进程清理和规范 review verifier 按已确认计划延后到 CI，不标记为 pass。
