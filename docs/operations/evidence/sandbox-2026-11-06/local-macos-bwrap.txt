Environment:
  macOS 27.0.1 (arm64)
  OrbStack container kernel: 7.2.12-orbstack-00394-gbecdd6130068
  Docker image platform: linux/amd64 (emulated on arm64)
  Test image: fx-sandbox-test:local

Kernel smoke in the actual PlatOS base image
--------------------------------------------
Command:
  docker run --rm --platform linux/amd64 \
    --security-opt seccomp=unconfined \
    -v "$PWD/kernel_smoke.py:/smoke.py:ro" \
    docker.sangfor.com/mss-base/python-node:3.12.13-node24 \
    python /smoke.py

Observed:
  uid: 10001 gid: 10001
  kernel: 7.2.12-orbstack-00394-gbecdd6130068
  /proc/sys/user/max_user_namespaces=64278
  /proc/sys/kernel/unprivileged_userns_clone=<No such file or directory>
  OK user
  OK namespaces
  OK mount
  OK pid 1
  OK net 101
  RESULT: PASS

Same command without --security-opt seccomp=unconfined:
  FAIL unshare-user 1 Operation not permitted
  RESULT: FAIL

Note:
  Docker's default seccomp blocks unshare locally. The intranet Kubernetes
  default did not block it (see intranet-k8s-kernel-smoke.txt).

bwrap invocation notes that were required by the actual base image:
  - Bind /opt read-only: Python is at /opt/python3.12/bin/python.
  - Bind /lib64 (try): the PlatOS Python needs
    /lib64/ld-linux-x86-64.so.2.
  - Bind /usr, /lib, /etc, /opt and /dev.
  - Do not bind /mnt or /proc.
  - Use --clearenv and set only PATH / HOME / LANG / MUAD_SESSION_SOCKET.
  - Use --size <bytes> before --tmpfs /tmp (bwrap syntax).

Unix socket test:
  A Python Unix socket server was started outside bwrap. The session directory
  was bind-mounted into the sandbox. A Python client inside bwrap connected to
  the socket and received {"session":"ok"}.
  This validates the mechanism needed by session-manager; the real
  session-manager CLI still needs a P0 test in an intranet Pod.
